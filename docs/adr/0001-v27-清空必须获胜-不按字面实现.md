# ADR-0001：V27「清空必须获胜」不按字面实现

- 状态：已接受（2026-09-19）
- 相关提交：`6c69ba9`（接上纪元）、V32（退掉两列）
- 相关文件：`V27__memory_epoch_and_runtime_flag.sql`、`V32__retire_unwired_memory_columns.sql`、
  `AiWorkspaceServiceImpl.confirmArtifact`、`AiServiceImpl.clearMemory`

## 为什么写这条

V27 的迁移注释用**陈述句**描述了一道并不存在的栅栏：

> run 开始时的记忆纪元快照。清空记忆时，仍在跑的流式聊天会走「重建消息对」分支把内容写回来
> （AiServiceImpl 的迟到回答重建路径），仅靠 fact 侧的栅栏拦不住它。
> **最终事务比对本列，不匹配则整体丢弃，落实「清空必须获胜」。**

实际上四列在 Java 侧全是零引用。任何认真读迁移的人都会发现「列在、机制没写」，
然后动手去接——这正是本条 ADR 被写下来的原因：**这个决定必然被重新提出**，
而提交消息挡不住下一个人，他读的是迁移文件，不是 git log。

## 决定

**不实现 V27 字面描述的那道栅栏**（即：不让最终事务因纪元不符而丢弃整轮问答）。
纪元改为守在**记忆草稿确认**那一刻。

## 理由

### 一、V27 指的那条路径不复活任何旧数据

「迟到回答重建消息对」写入的是**用户当轮自己刚打的问题和它的回答**。
清空发生在这一轮进行中，用户正看着答案流式输出。把它丢掉，用户看到的是「我的消息被吃了」。
V27 担心的「已删数据复活」在这条路径上不成立——没有任何旧内容被写回来。

### 二、现有语义是刻意的，有三条判据加代码注释钉着

- `streamClearMemoryDuringModelRebuildsPairInRevivedConversation`
- `streamClearMemoryDuringModelRebindsRetrieverArtifactsToRebuiltMessage`
- `chatClearedDuringSecondModelCallKeepsPairIntact`

以及 `AiServiceImpl` 里那句「要么整对写入复活后的会话(清空)，要么整对被归属校验拒绝(删除)
——不会只留下一半」。按字面实现 V27 等于同时推翻这三条判据和这条注释，
那是**独立的产品语义决定**，需要自己的论证，不能顺手夹带在「补一道栅栏」里。

### 三、V27 担心的真复活路径，多数已被别的方式关掉

| 路径 | 今天的状态 |
|---|---|
| 记忆抽取自动写入 `user_ai_memory` | `9ff2aec` 改成草稿，不确认不写 |
| 摘要写入已清空会话 | `8507dd9` 的 `s.rebuilt` 守住 |
| 消息对重建 | 刻意行为，见上 |

### 四、今天真正还在的洞不在 V27 指的地方

`9ff2aec` 新开了一个：**草稿活得比 run 长**。用户清空记忆之后，那条 `MEMORY_DRAFT`
仍躺在面板上，点确认就把「已清空对话里提炼的事实」写回长期记忆。
`s.rebuilt` 拦不住它——那只覆盖 run 内。这才是纪元该守的位置。

## 后果

- `sys_user.memory_epoch` 在 `clearMemory` 递增；`beginRun` 快照到 `ai_agent_run.memory_epoch`；
  `confirmArtifact` 比对两者，不符则拒。
- run 内那一半由 `s.rebuilt` 关掉：清空之后不再弹「AI 想记住这些」。
- **覆盖边界**：不覆盖「读活值与写记忆之间恰好插进一次 `clearMemory`」那个事务内的毫秒级窗口。
  `clearMemory` 持用户锁，`confirmArtifact` 不持（它是 `@Transactional`，仓库既有次序是
  锁在事务外），与 `upsertMemory` 同形状。消掉的是「草稿整个生命周期都能复活记忆」，
  不是「清空必然获胜」。这条边界同时写在代码里判断的旁边。
- 行为判据：`AiConversationLifecycleIntegrationTest.清空记忆之后旧的记忆草稿不得再写入长期记忆()`。

## 什么情况下该重开这条

如果产品上决定「清空记忆」应当连同**正在进行的那一轮**一起作废（即用户预期清空后对话区完全空白，
哪怕刚问的问题也不留），那么理由二里那三条判据就是要改的对象，此时 V27 的字面实现才成立。
那是产品决定，不是技术补洞。
