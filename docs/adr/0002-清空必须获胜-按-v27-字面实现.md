# ADR-0002：「清空记忆」作废在途的那一轮

- 状态：已接受（2026-09-19）
- 取代：[ADR-0001](0001-v27-清空必须获胜-不按字面实现.md)
- 相关文件：`V27__memory_epoch_and_runtime_flag.sql`、`AiServiceImpl.streamChatInternal`、
  `AiServiceImpl.chat`、`AiServiceImpl.clearMemory`

## 决定

用户点「清空记忆」时，**正在进行的那一轮对话连同问题和答案一起作废**，不写回任何会话。
这是 V27 迁移注释描述的语义（「最终事务比对本列，不匹配则整体丢弃，落实『清空必须获胜』」），
V27 建了列却从未接线，本次真正实现。

## 为什么反转 ADR-0001

ADR-0001 主张不实现，理由是：那条路径写的是用户当轮自己刚打的问答、不复活旧数据，
而且用户正看着答案流式输出，丢掉像是消息被吃了。

产品侧的判断是：**「清空」就该清干净。** 用户按下那个按钮之后看到对话区里还有内容，
哪怕是刚问的那句，也是这个动作没有生效。一致性优先于「不浪费那一轮」。

ADR-0001 列的理由没有被推翻 —— 它们现在是这个决定的**代价清单**（见下）。

## 实现

- `clearMemory` 递增 `sys_user.memory_epoch`（与软删同事务、同用户锁）。
- `beginRun` 把当时的纪元快照进 `ai_agent_run.memory_epoch`。
- 流式：最终锁内事务开头比对快照与活值，不符则 `cancelRun` 并整轮丢弃，
  `done` 事件带 `status=CANCELED`。比对在用户锁内，`clearMemory` 也持同一把锁，
  两者串行，不存在「比完才清空」的穿透。
- 非流式 `chat()`：**V27 没覆盖这条路径**（它没有 run，没地方挂快照）。
  用方法内局部变量快照，最终事务里比对，不符则抛 `BusinessException("记忆已清空，本轮回答未保存")`，
  与「Notebook 已删除」同一个形状。

## 代价（即 ADR-0001 原来的反对理由）

1. **用户会看到自己刚问的问题消失。** 如果在答案流式输出到一半时点清空，
   那一轮的问题和已经显示出来的文字都不会留下。这是刻意的，不是 bug。
2. **做过活的那一轮也照样丢。** 检索跑完、工件落库，仍然整轮作废 ——
   否则就变成「按工作量决定要不要尊重删除意图」。
3. **四条判据被反转**，它们此前钉的是相反的行为：
   - `streamClearMemoryDuringModelDropsWholeTurn`（原 `…RebuildsPairInRevivedConversation`）
   - `streamClearMemoryDropsTurnEvenAfterArtifactsProduced`（原 `…RebindsRetrieverArtifactsToRebuiltMessage`）
   - `chatClearedDuringSecondModelCallRejectsWhole`（原 `…KeepsPairIntact`）
   - `clearMemoryDuringInFlightChatCompletesImmediatelyAndVoidsTheTurn`（原 `…DoesNotResurrectStaleHistory`）

   它们红起来不一定是回归。改之前先读本文。

4. **「消息对重建」那条路径基本不再被走到。** 代码保留着（占位消息被单独删除时仍会走），
   但清空这个主要入口已经被前置的纪元比对截掉。

## 什么情况下该重开

如果用户反馈「点清空把我正在问的问题也吞了」成为实际投诉，
那么可以考虑折中：清空只作废**已完成**的历史，在途那一轮照常落进新会话 —— 也就是 ADR-0001 的语义。
届时要一并改回上面四条判据，并在 `clearMemory` 的注释里写清两种语义的边界。
