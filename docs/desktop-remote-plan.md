# 方案：桌面版改成「登录网站、数据走网站」（2026-11-08）

用户 2026-11-08：「桌面版的mysql应该也要连服务器上的」；问过之后定了：**给所有下载桌面版的人用**（不是只给自己的电脑）。

> 标着「要你定」的地方，做到那一步之前先问，不替你拿主意。

## 一、为什么不能照原来的想法直接连服务器的库

桌面版里现在装着一个完整的后端（Java + 一个精简的 JRE），它连的是**用户自己装的 MySQL**（安装包不带数据库，没装 MySQL 的人打不开）。要连服务器上的库，桌面版的配置里就得有数据库密码和主密钥 —— 有了主密钥就能解开全站所有人的数据（AI 的 key、Wiki 正文、任务标题）。所以只能给自己的电脑，不能发给下载的人。

## 二、现状（2026-11-08 读代码）

- 外壳（`deploy/desktop/macos-shell/`，Swift + WKWebView）：起包里的 Java 后端（47615 端口），窗口里打开 `http://127.0.0.1:47615`。
- 本机才有的东西：选文件夹（系统的选择框）、代码模式读写用户磁盘上的项目、命令在系统沙箱里跑 —— 后端起包里的 node 跑命令行那一份循环（`zhiqu-cli/src/host/code-host.js`）。
- 命令行 `zhiqu`（已发布到 npm）：**循环和工具在本机，模型、登录、数据在服务器**（`https://zhiqustudy.com`）。桌面版要的正是这个形状。
- 安装包 152MB：JRE、后端 JAR、node（108MB）、外壳。

## 三、怎么改（三种，推荐 A）

| | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A（推荐）** | 窗口里直接打开 `https://zhiqustudy.com`；本机代码交给包里的 node 跑命令行那一份（「本机代码助手」）：桌面里的页面在代码模式下经外壳的桥把这一轮交给它，它在你的磁盘上读写、在系统沙箱里跑命令，模型走服务器的网关（和命令行一样） | 数据只在服务器上；不带 Java、JRE、MySQL，安装包小一半；本机代码和命令行同一份实现 | 外壳和页面之间要接一座桥（代码模式在桌面里换一条路走）；断网时什么都看不了（和网页一样） |
| B | 留着包里的 Java 后端，只做本机代码，别的请求转给服务器 | 页面不用改 | 包还是这么大；后端要拆成「本机那一半」和「转发那一半」，两份逻辑 |
| C | 窗口里只打开网站，桌面版不再做本机代码（本机代码只在命令行） | 最简单，一两轮就完 | 桌面版的代码模式只剩「生成到产物」（服务器上的临时空间），碰不到你电脑上的项目 |

## 四、按 A 的步骤（一步一轮）

| 步 | 内容 | 怎么验 | 进度 |
|---|---|---|---|
| 1 | 外壳打开网站（默认 `https://zhiqustudy.com`，能改）；记住登录（WKWebView 的数据按网站存）；迷你番茄钟、下载、外链这些外壳功能接上网站；不再起 Java 后端 | 重打的桌面应用里用鼠标走一遍：登录、关掉再开还在、番茄钟缩小到桌面 | 第一百二十五轮（和第 4 步合成一轮）；真窗口里用鼠标点一遍第一百二十六轮做完（用户点的，指向本机验证站 + `zhiqu_verify`） |
| 2 | 本机代码助手：外壳按需起包里的 node 跑命令行的宿主（stdio 协议，和后端起它的那一份同一个）；登录用页面的登录换一个只给本机代码用的令牌；模型走服务器网关 | 真起 node、真沙箱：写你的项目要确认、读不到家目录、断网 | |
| 3 | 页面在桌面里走这座桥：选文件夹（系统的框）、档位、代码模式的一轮、确认草稿写盘、`/review` `/init`；网页（浏览器里）照旧走服务器 | 同一个页面在浏览器和桌面里各走一遍 | |
| 4 | 去掉桌面包里的 Java 后端和 JRE、不再需要 MySQL；安装包重打、放上服务器 | 包变小；一台没装过 MySQL 的 Mac 上装好就能用 | 第一百二十五轮（合进第 1 步）；1.1.0（42 MB，原来 152 MB）第一百二十六轮重打、放上服务器 |
| 5 | Windows 版（要你定） | — | |

## 五、要你定

1. **A / B / C 选哪个**（推荐 A）。
2. **这台 Mac 本机库里原来的数据**（桌面版以前存在你本机 MySQL 里的任务、Wiki、对话）：迁到网站上你的账号（Wiki 有 ZIP 导出导入，任务、对话要另写一个迁移），还是不要了。
3. **断网时**：桌面版和网页一样打不开数据，可以接受吗？（要离线也能看，得做本地缓存和同步，是另一个大工程。）
4. **Windows**：现在的 Windows 版是在默认浏览器里打开，要不要也做原生窗口（WebView2 外壳，单独几轮）；还是 Windows 先维持「浏览器里打开网站 + 命令行」。

## 六、不能动的

- 主密钥、数据库密码只在服务器上，不进任何安装包、任何用户的电脑。
- 本机代码的边界不变：默认关、系统沙箱（只写工作区、断网、读不到家目录）、AI 写的先成草稿（auto 档的 shell 除外，用户定的）。
- 网页（浏览器里）的行为不变：服务器上不碰任何人的磁盘，代码模式只生成到产物。

## 七、用户定了（2026-11-08，问过）

1. **A**：本机代码助手（包里的 node 跑命令行那一份），窗口里打开网站。
2. **本机库里原来的数据不要了**：本机 MySQL 留着不动，新桌面版不再读它，不做迁移。
3. **断网时看不了数据，可以**。
4. **Windows 也做原生窗口**（WebView2 外壳）：要有一台 Windows 电脑打包和验证，排在 macOS 的 1–4 步之后，到那一步再问怎么弄。

## 八、做的时候改的

- **第 1 步和第 4 步合成一轮做**（第一百二十五轮）：外壳不起 Java 之后，包里的 JRE 和 JAR 就是死的 —— 几十 MB、每次打包多跑一遍 Maven 和 jlink，
  还让人以为桌面版有一个本机后端。分两轮只会多出一个「带着死 JRE」的中间包。node 留在包里给第 2 步。
- 在第 2、3 步做完之前，Mac 桌面版的代码模式和网页一样只生成到产物；本机项目用命令行 `zhiqu`。
