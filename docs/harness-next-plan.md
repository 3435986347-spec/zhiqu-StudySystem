# harness 下一阶段：写代码的证据，和画面的眼睛（2026-11-26）

这一轮先读了现行循环、历次评测和两段长会话，对照了 Codex、Pi、Claude Code 的公开做法，又单独看了做游戏、绘画、3D 和要画出来的前端。用户要求把方案写下来。

一步一轮做，做完更新「进度」。标「要你定」的，做到那一步开工前先问用户。两条线可以穿插，不要绑在同一次改动里量。

## 一句话

写代码的官方分卡在修法判断，不卡在缺工具：SWE-bench Verified 固定十题在工具补齐之后仍是 6/10、6/10、4/10。长活的钱卡在清不掉的上下文。用户碰到的网页入口比命令行少一截。游戏、绘画、3D 和要画的前端是另一条线：失忆补过了，眼睛仍是一张软件渲染的静态图，而「够不够立体」没有可测的信号。

两条线用同一个原则：**证据由 harness 产生，模型改不了口。** 测试看退出码，画面看亮度格、帧差、着色器日志。提示句再写一遍，尺子会继续全绿。

## 游戏、绘画、3D、要画出来的前端

### 两场会话

二十三小时做游戏（`docs/memory-plan.md`，私人会话不进仓库）：用户说了 7 句，第一句是不够立体、细节差、背景模糊、要做成白天。1223 次模型调用、1546 次工具、压缩 105 次（中位 5.7 分钟）、截图 206 张（105 张因超过 1.5MB 被拒）、最终回答 0 次。天空着色器写到 `_sky_v10`，「重写天空云层」从第 40 次压缩起一直是进行中，结束时清单 0/8。图的记账、空摘要、压完把正在看的代码还回去，后来补上了。

二十小时那场在补上一部分之后（`docs/agent-efficiency-plan.md`）：`preview_page` 149 次，142 次 `timeout_seconds=300`。任务里有黎曼和福建舰的 3D 讲解页。模型写了 `report_server.py` 和 `verify.html`，为的是给看不到图的核对员凑文字。

### 这只眼睛现在能说什么

`preview_page` 每次新起一个无头 Chrome，截完就杀（`preview.js` 的 `shoot`）。

| 要判断的事 | 现在回给模型的 | 结果 |
| --- | --- | --- |
| 脚本抛没抛 | 探针收 error、未处理的拒绝、`console.error`，各最多 10 条 | 做得到。`console.log` 不收。着色器要页面自己打出错误才进得了这张表 |
| 是不是一片空的 | PNG 抽样，颜色量化到 16 级；同一色占到 97%（`FLAT_SHARE`）就说可能是白屏、黑屏，或 3D 没画出来 | 大面积天空、夜景、白纸上的淡线、WebGL 没起来，挤在同一句里 |
| 立体、笔触、细节 | 超过约 400KB 就缩到长边 1280、转 JPEG，质量可以降到 50。没有和上一张的差 | 第一百七十二轮：DeepSeek 的回答看不出它用了图。截图后的提示仍写「要改就改完再截一张」 |
| 动画在不在动 | `--virtual-time-budget=5000` 写死。`timeout_seconds` 最大 300，只是墙钟到点杀进程 | 连续 `requestAnimationFrame` 让截图程序不结束。超时说明让模型先把动画停掉再截 |
| 点、拖、按键之后 | 没有这些动作 | 游戏停在标题。testagent 用一张停住的图查滚动跟随，后来去改了播放速度 |
| 正在跑的服务，或这个项目自己的网页 | 只收工作区里的 `.html`。服务器上的代码模式不下发这个工具 | Vite、本机 8080、要登录的页面看不到 |
| 和用户屏幕是不是同一张画 | 默认 `--use-angle=swiftshader`。真 GPU 要 `ZHIQU_PREVIEW_GL=metal`。结果里不标明 | 软件 WebGL 的光和阴影跟用户机器不同。模型按这张图改着色器 |

探针插进页面时必须仍是一行。第一百六十八轮真跑过：多行探针把报错行号推后，模型照着改会找错地方。

画布像素不要用页面里的 `readPixels`。WebGL 默认不保留绘图缓冲，读出来常常是空的；跨域图会把 canvas 弄脏。像素以已经截到的 PNG 为准，`analyzePng` 已经在解码。

### 和写代码撞上的同一道闸

同一处改到第 3 回要写根因，这条对「找错根因」是对的。调天空、调光、改一笔版面，本来就是同一段改很多回。闸门只挂在编辑工具上，所以模型改走 shell 替换，或另存 `_sky_v10`。

不给着色器、HTML、CSS 免闸。免了，testagent 那种「同一处试了 12 分钟」会从这道缝里回来。微调要记的是测量（帧差、亮度格），不是免掉记录。shell 改到的行算不算进这道闸，和写代码第 3 步是同一个要你定。

### 这一条线上明确不做

- 不把 Chrome 放进 Seatbelt / bubblewrap。渲染进程需要的系统服务一放，沙箱就拆了（第一百三十五轮的边界）。浏览器继续跑在宿主进程里，回合结束杀掉。
- 不添加 Playwright。`zhiqu-cli` 没有 dependencies，保持零依赖。
- 不一次往上下文里贴四张 JPEG。帧差在本地算，模型看数字。
- 不把 `timeout_seconds=300` 当成「让 3D 多画一会儿」。那是杀进程的墙钟。V3 之前在工具说明里写明：虚拟时间只有 5 秒，300 秒不会多画出 300 秒的动画。
- 不给 `preview_page` 任意 URL。本机端口也只认本会话拉起的那一个。
- 不重做图片 token 记账，不设截图张数硬上限。
- 关键字表判断一句目标是不是在说美。沿用模型判断含糊，收窄的只是「没有可观测标准就不能判达成」。

## 两条线共用的规矩

- 新判据先见红。扰动的备份放在 `src/` 外面，恢复用 `cp` + `touch`。
- 私人会话只在本机读、不提交。判据用照形状造的合成历史。
- 改在命令行和网页宿主共用的 `runTurn` / 工具里时，网页代码模式跟着变：后端带的是 JAR 里那份源码，要部署才生效；桌面宿主在安装包里，要重打。
- 动到 token 估算就两边一起改（`token-estimate.json`）。
- 历史只追加。并行、压缩、换工具表之前先看前缀缓存还在不在。
- 不调付费模型，除非那一步的「要你定」已经点头。HOME / ZHIQU_HOME 用临时目录。

## 建议的先后

写代码：1 → 3 → 5 → 6 → 4 → 7 → 10，第 2 步和第 9 步等预算，第 8 步等第 2 步的结果。

画面：V1 → V2，与上面穿插即可；V3、V4 等对应的「要你定」。

不先做的：hooks、会话分叉、worktree、用户贴图、命令规则、把子 agent 接到网页。hooks 以后用来接闸门，不拿它当下一轮的分数手段。Codex、Pi、Claude Code 的公开循环同样没有游戏和 3D 的眼睛；V1–V4 不是对齐表上漏抄的一格。

## 「要你定」

做到那一步再问，推荐写在每个问题后面。

1. 第 2 步花钱跑思考对照。推荐跑。不跑就不要改默认档位。
