## 进程级（真的宿主进程、真的命令行进程、假网关；脚本在 /tmp，不进仓库）

1. **两边狂点**：同一段会话，宿主 7 个、命令行 7 个进程乱序同时说，模型随机慢 0–400ms、一半先读一次文件。查：每个进程要么说完、要么照实说「正在跑」；说完的每一句只记一次；撞上的一句都没进记录；
   每一轮从人说的那句到下一句之间，最后的回答都是这一轮的（不交错）；锁放了；记录读得回；120 秒内都结束。
   - 起得密（一秒内全起来）5 遍、起得疏（间隔 0–700ms）4 遍：都对。
   - **对照组**：把锁关掉（环境变量让 `lockTurn` 直接放行），3 遍里每遍十几处交错（「H3 这一轮里出现了 答:C1」）。第一次做对照时环境变量没传给子进程、对照没生效，改了再做。
2. **跑一半强杀**：宿主在「读完文件、等模型」时被 SIGKILL、在第一次等模型时被 SIGKILL，命令行 220–230ms 接上；命令行在工具调用之后被 SIGKILL，宿主 124ms 接上。
   接上的那一边发给模型的消息里工具调用和结果成对、被杀那一轮人说的话和读到的东西都在、说完锁放了。
3. **600MB 的记录**（300 段 2MB 的读文件结果，每 50 段压缩一次）：宿主打开 + 说一轮 0.6 秒、最多 274MB；命令行 `exec resume` + 说一轮原来 1.1 秒、**609MB** —— 见下「修了的」，修完 1.0 秒、280MB。
4. **文件夹被挪走**：宿主在 X 里写过记录（本机索引记着 X），X 挪成 Y。在别的文件夹 `/resume`：X 没了，不指路、直接接文字版；在 Y 里命令行续接、宿主接着，都接得上，索引跟到 Y；再到别处 `/resume`，指到 Y。

## 本机后端（`zhiqu_verify` 库、假的 OpenAI 兼容模型，不碰线上和用户的账号）

补跑第一百四十五、一百四十七轮那两条没 Docker 跑不了的真库判据的场景，用真 HTTP、真 MySQL、真的桌面令牌和命令行令牌，18 项都对：
宿主拿桌面令牌经真网关跑；命令行接着说，存档落在原来那个对话、不多建对话；别人的对话号不绑、别人的对话一条不多；对话列表、文字版按时间顺序；别人的对话读不到；
**桌面令牌读对话列表 403**；默认对话：命令行接着说存进默认对话、不多建、排在列表最前；**对话在应用里被删之后命令行再说**：照常、存档不报错，另建一个对话存着，删掉的不再列。

撞到一处：对话被删、`app-<旧号>` 改挂到新建的对话上之后，「对话号 → 命令行会话 id」把所有 `app-` 开头的都排除了 —— 应用里打开那个新对话会另起一份 `app-<新号>`，接不上原来那份记录。
改成只排除「号对得上自己」的（`HarnessSessionBindTest` 补样本，扰动 2 处见红）。

`conversationHandoff` 里「摘要覆盖到的不再给」仍没有被照到：要攒到服务端生成滚动摘要，这里没有造。

## 真浏览器（Chrome + playwright-cli，发布的页面，外壳换成桩）

桩（`/tmp` 里的小服务 + 注入页面的一段脚本）照 `LocalAgent.swift` / `PageView.swift` 的样子回 `status` / `run` / `resume` / `ack`，`run` 起真的宿主进程（交给它的那一行照 `LocalAgent.payload`）。外壳本身由 Swift 检查程序（`DesktopLocalAgentTest`）管。

- 页面打开的正好是「对话被删、改挂过来」的那个对话：在页面上说，交给外壳的是 `app-1`（原来那个号）—— 接的是原来那份记录（这条就是上面那处修了之后才对的）。
- 命令行 `exec resume app-1` 卡在模型上时，在页面上说：宿主回 `busy`、这一句没存进对话、字放回输入框。提示条没截到（截图时已经消失），由判据 `slash-check.js` 管。
- 命令行说完之后连点四下发送（两次 ⌘ 回车、两次点发送按钮）：外壳只收到一次 `run`、对话里只存一条；宿主接着时命令行那一轮没有被再补一遍。
- 中途的一个怪现象：有一次撞锁没回 `busy`、也没进记录 —— 那时工作区被拉远端还原了（见下），`session.js` 里没有 `lockTurn`，宿主拿锁时抛错、被当成「记录打不开」不记，直接跑了。不是锁的毛病。

## 修了的

- **回放把工具输出全文攒在内存里**（`session.js` 的 `transcript`）：只画第一行，却把每段 2MB 的读文件结果都留着。截成开头 4000 字 —— 只截还不够：`slice` 切出来的是引用原串的一段（V8 的 SlicedString），
  原串照样留着，内存一点没降（679MB）；真拷一份之后 280MB。判据 `transcript-memory.test.js`：子进程带 `--expose-gc` 读 160MB 的记录，堆只能多 20MB 以内；扰动「只截不拷」「不截」「人说的也截」3 处见红。
- **对话被删后改挂的会话 id 不列**（见上）。
- **记忆第 7 步在应用里没有**（用户问的）：命令行开工时向服务器要一段长期记忆（`/api/harness/memory/brief`），和会话从哪来没关系，所以命令行 `/resume` 应用的会话照样带上；
  但桌面的本机代码助手从来不要这一段，桌面令牌的白名单里也没有这个接口。补了：白名单加上它（读的就是 `read_memory` 远程工具本来能读的，范围没变大），宿主开工时去要；
  拿不到一律当没有 —— **服务器还没部署新白名单时会回 403，不能当成令牌失效把这一轮停掉**。判据 `desktop-host.test.js` 1 条（带上、403 照跑、关着没有），`AccessTokenScopeTest` 加一个桌面令牌认的接口；扰动 3 处见红。
  第 8 步（尺子）是评测工具，从会话记录算指标；应用的会话现在也有记录，不用补。
