# 第一百三十八轮（2026-11-15）：记忆第 2 步 —— 工作状态卡

方案 [`docs/memory-plan.md`](../memory-plan.md) 的第 2 步。上一步（第一百三十七轮）让压缩少发生；这一步让它发生的时候不再等于失忆。

## 由来

那段 23 小时的会话里：任务清单整份重列 6 次、做完的项跟着消失 3 次；同一段着色器改到第 10 版；建了 42 个临时文件；
每次压缩之后先重新看 12 步才动手；进程崩掉那次连进度笔记都没有（`progress.md` 只在一句话正常返回时才写）。
压缩压不掉的原来只有两样：用户这次的原话、没做完的清单。

## 做了什么：`zhiqu-cli/src/state.js`

一份小记录，**每变一次就落盘**（原子写）。

| 记什么 | 谁记 |
|---|---|
| 用户说过的每一句（逐字） | 命令行 |
| 清单；**做完的记录**（只追加，带时间和验证方法） | 命令行（模型交清单时比出来） |
| 改过的文件（几回、加减行）；这段会话新建的文件（工具建的 + 开工 / 收尾两份文件清单比出来的，shell 建的也在） | 命令行 |
| 同一处改了几回（文件 + 200 行一段） | 命令行 |
| 最近 15 步；刚才在看 / 在改哪几段 | 命令行 |
| 定过的事、走不通的路、位置、临时文件 | 模型，用新工具 `note` |

- **清单记账**：`update_todos` 对模型还是整份替换，命令行会比。做完的项在新清单里没了 → 回「已经做完的 N 项……还记着，不用重做」；
  把做完的事换个说法又列成没做的 → 回「这一项之前标过完成（验证：……）」。标完成时可以带一句 `evidence`。
  「是不是同一件事」按去掉标点后相等、或者两字组合七成重合来认（模型重列时措辞常常小改）。
- **`note` 工具**：`decision / dead_end / anchor / temp`，一条不超过 300 字、每类最多 20 条；只写状态卡，三档都给，子 agent 不给。
- **同一处改到第 6、12、24 回各提醒一次**，附在那次改动的结果后面。计数在状态卡里，压缩清不掉。
- **压完还回去**：压缩之后追加一条命令行自己的消息 —— 状态卡，加上压缩前最后在看 / 在改的那几段代码**现在的**内容（最多 5 段、不超过窗口的 15%，放不下的整段不给）。
  清单已经在卡里，原来那条「清单再说一遍」不再另补。
- **挑时机**：占用过了六成、又正好有一项清单刚标完成，就在这里压；否则照旧等八成。
- **开工时接上**（取代 `progress.md`，那个模块删了）：
  - 桌面 / 网页（每一轮是新进程，状态在项目的 `.zhiqu/state.json`）：上一轮没做完 → 这一轮开头给状态卡，清单也带回来；做完了 → 文件删掉、空目录收掉；过 24 小时不接。
  - 命令行新开的会话：这个项目里最近那一段会话没做完（包括进程没正常退出）→ 开头说一声、给它的状态卡。只是告诉，不接管。
  - 状态停在「进行中」= 进程没正常结束，照样算没做完。
- `/state` 给人看；系统提示里加了一句什么时候用 `note`。

## 判据

`zhiqu-cli/test/work-state.test.js` 8 条，**扰动 25 处全部见红**（第一遍有 3 处没红：一处照出实现和说法不一样 —— 太大的代码段原来是截一半给，改成整段不给；两处是样本不够，补了）。
改了期望的旧判据：`agent.test.js`（plan 档多一个 `note`）、`cache-prefix.test.js`（三个样本各用各的目录：同一个项目里上一段没做完，新会话会被告知）、评测工具钉的工具清单（多一个 `note`）。`progress.test.js` 随模块删掉，它的四件事在新判据里都有。

## 没做的，和方案不一样的

- 压缩后的用户原话仍然同时置顶在系统提示里（`requestBlock`）：挪出去是为了缓存，放在第 4 步。
- 没有「标完成必须带验证方法」的硬要求，只是能带、带了就记。
- 新建文件的名单：工作区超过 4000 个文件就不比（只剩工具建的那些）；续接的会话没有开工时的那份清单。
- 「同一处」按 200 行一段数，改动把后面的代码往下挤了以后，同一段代码会落到另一格里。
- 没用真模型跑：模型会不会用 `note`、看了状态卡是不是真的 3 步之内动手，要等尺子（第 8 步）。
- 桌面应用里没点过。
