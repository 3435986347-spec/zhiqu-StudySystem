# 第一百五十轮（2026-11-17）：干活中途补充第 1 步 —— 循环里的收件箱

## 由来

用户 2026-11-17：「我现在想改造成能够在模型处理的时候发信息，作为一个引导或者补充，然后他运行完当前的命令或者是思考完能接收到，而不是现在只能等他一轮所有结束才能接收到我接着发的内容，后面的都在排队。」

先出了方案 [`docs/steer-plan.md`](../steer-plan.md)，四件「要你定」用户当天都按推荐定了：生成中回车 = 补充、Tab = 排队；网页默认补充；等这次模型调用说完再送；模型写出结论时箱子里有话就不收尾、接着做。这一轮做第 1 步：命令行、桌面、网页代码模式共用的那份循环（`agent.js` 的 `runTurnBody`）。入口（终端、宿主、页面）下一轮起接。

## 要做的

**一轮一个收件箱**（`src/steer.js` 的 `Inbox`）：`push` 放话（空话、关了的返回 false）、`take` 取走、`close` 收尾并交回没取走的。`runTurnBody` 开头新建一个挂在 `ctx.inbox`，入口往里放。

**两条缝。**

- 每一次去问模型之前（循环顶上）：箱子里有话就倒进上下文。所有 `continue` 的路（一批工具回完、截图那条记完、被推回去、续写）都走这里，所以一处就够；方案里列的「缝 C」不用单写。位置天然在**整批**工具结果之后 —— OpenAI 要求 `tool_calls` 后面紧跟每一条结果。
- 模型没调工具、要收尾时：箱子里有话 → 这句回答留在历史里（阶段性结论），`continue`。最后一轮 `continue` 就出了循环，话由收尾交回，所以不用另判最后一轮（写了又删：判据上照不出它和不判有什么不同）。

**倒进去的样子**：几句合成一条 user 消息，开头一句固定的「用户在你干活的过程中补充了下面的话。它比原来的要求新……」；记录里 `origin: 'steer'`，另记一行 `{ type: 'steer', text, via }`。

**配套。**

- 重复检测清零：用户说了新话，同一个调用再发一次是合理的。第 7 次重复本该停下的那一批里补了话，也不停。
- 状态卡记进「用户说过的话」，标「（干活中途补充）」：压缩会摘掉中间的 user 消息，卡不会。
- 压缩留的「用户原话」把补充算进去（去掉给模型看的那句开头）；`/resume` 回放显示成 `↳ 补充：…`，不当成新的一句；和应用对账的 `said` 不收它（Notebook 里没有这一条，配不上）。
- 收尾交回：`runTurn` 的结果多一个 `leftover`（被停下、最后一刻才到、最后一轮）。
- 子 agent 没有收件箱：它的 ctx 是父 ctx 浅拷贝的、看得见 `ctx.inbox`，所以循环用局部变量，不读 `ctx.inbox`。
- 直连 Anthropic（`direct.js` 的 `toAnthropicMessages`）：工具结果后面那条 user 文本并进结果那条消息、排在结果后面（和后端 `AnthropicFormat` 一样）。原来是连着两条 user，靠 API 自己合。
- 没有入口接 `ctx.onSteer` 时，终端打一行灰字「读到了你的补充：…」。

## 怎么验

`test/steer.test.js`，10 条，假模型；「模型正在想的时候用户说了一句」用 hook 在第 n 次模型调用进行中 push。

11 处扰动各自见红（每次先确认扰动落了；备份在 `/tmp`，`cp` + `touch` 恢复）：

| 扰动 | 红的判据 |
|---|---|
| 去掉循环顶上的倒入 | 5 条 |
| 去掉收尾前看箱子 | 收尾时补话、状态卡 / 记录 |
| 倒入时不清零重复 | 补了话重新数 |
| 子 agent 也读 `ctx.inbox` | 子 agent 不倒父亲的箱子 |
| 收尾不交回 | 最后一轮 / 被停下交回 |
| 第 7 次重复不看箱子 | 第 7 次那一批补话不停 |
| Anthropic 不并 | Anthropic 形状 |
| 状态卡不记 / 回放不认 / 压缩不去开头 / 记录不记 steer 行 | 状态卡 / 记录 / 回放 / 压缩那条 |

命令行全量 `npm test`：652 条，633 过、0 失败、19 跳过（全是 `sandbox-hosted.test.js` 的 bubblewrap 判据，macOS 上本来就跳）。

## 结果

内核做完，还没有入口能往箱子里放 —— 用户现在用起来没有变化。第 2 步接终端（回车 = 补充、Tab = 排队），然后发 npm。

- `toAnthropicMessages` 里 user 的 `content` 是数组（截图）时被 `String()` 成 `[object Object]`：直连 Anthropic 时截图没发出去。不是这一轮的事，记下来，单独修。
