# 第十一轮（2026-09-28）：暴力测试 —— 不同输入、不停刷新、没耐心的人

## 用户的要求（原话）
- 升级完这一轮后继续升级下一轮，然后做完后再继续升级下一轮，不过每次都要把计划保存；然后一直不停升级
- 同时暴力的测试这个东西比如不同输入，不停刷新，测试没有耐心的极端情况

## 计划（开工时）
这一轮先「找」再「修」：先造能自动反复跑的暴力测试，让它把问题照出来，再逐个修、每个修复配判据并扰动见红。

### T1 全接口输入模糊测试（网页后端，真库）
- 从 Spring 的映射表里**自动枚举**所有 `/api/**` 接口（不手写名单 —— 新加的接口自动纳入）。
- 对每个接口喂一组坏输入：空体、`null`、错类型（数字给字符串、对象给数组）、超长字符串（10 万字）、emoji / 零宽字符 / RTL、
  `<script>`、SQL 片段、负数、极大数、非法日期（2026-02-30）、路径参数给非数字、畸形 JSON。
- 判据：**不许出现未处理异常**（HTTP 500 或 `Result.code == 500` 的「系统错误」），也不许挂住（每个请求有时限）。
  坏输入该得到的是「说清哪里不对」的 4xx / 业务错误。
- 管理员接口、普通用户接口都跑；限流在测试里放开（测的是输入，不是限流）。

### T2 没耐心的人（网页，真浏览器 + 本机实例 18080 + 临时库 + 假模型）
- AI 流式回答时狂刷新（每 0.2 秒一次 × 20）、连按发送 5 次、回答中途关页面 / 断网：
  不许出现重复消息、停在「正在生成」的消息、停在 RUNNING 的 run、500。
- 各页面狂刷新到触发限流（429）：页面要显示错误，不许露出设计稿的示例数据、不许白屏。
- 同一个动作并发 20 次（完成任务、打卡、点赞、套用、确认草稿）：结果只生效一次或者给出友好的提示，不 500。

### T3 命令行（真 pty）
- 模型流式时、工具运行时、确认提问时连按 Ctrl+C；确认提问时狂打字 / 粘贴；输入 10 万字一行、控制字符、非法 UTF-8。
- 判据：进程不崩、不卡死、会话文件完整可 `/resume`、终端模式（raw / 括号粘贴）恢复。

### 修
T1–T3 照出来的每个问题：先写能复现的判据（红）→ 修 → 扰动见红。数量不设上限，这一轮以「照出来的都修完」收口。

## 过程中改的计划
做完 T1、修完它照出来的问题之后，用户贴来一段真实的命令行记录（小问题却一直在思考循环、1M 的模型按 64000 算、
要求思考过程不展示），并要求「也加入升级中」。所以 **T2（网页里没耐心的人）与 T3（命令行 Ctrl+C / 垃圾输入）挪到第十三轮**，
第十二轮先做用户点名的事。

## 结果
- **T1 全接口坏输入**：从映射表枚举到 156 个接口，每轮 5616 个请求（管理员、普通用户各一遍）。
  第一次跑：**499 处**坏输入变成了「服务器出错」—— 记成运行问题、把 Java / SQL 异常原文回给用户。修完：0 处。
  - 框架层的请求错误（不是合法 JSON 249、路径里的 id 给字母 213、缺参数 11、没按上传格式 5）原来全落进兜底分支 →
    现在 400 + 说清哪个字段、应当是什么，不记运行问题。
  - 真正的服务器端问题：日期参数写错直接抛（首页、例行计划 16）；用户名 / 个人资料 / 例行计划标题超长 → 数据库「Data too long」
    （个人资料 10 万字时 MySQL 直接拒收 1.2MB 的语句）→ 按列长校验。
  - 兜底分支不再把异常原文回给用户（原文里有 SQL、表名、类名），回一句话加运行问题的编号。
- **顺带查出**：这一版 BCrypt 对超过 72 字节的密码**静默截断**（实测 30 个汉字的密码，前 24 个字加别的也能登）→ 注册、改密码按字节拒绝。
- **顺带查出**：客户端上报运行问题的接口不登录也能调、不去重、不限量，而现在的页面根本不调它 → 要登录、10 分钟内同一条只记一次、每人每小时 30 条。
- 没做的（记下来）：后端没有密码最短长度（前端也没有）—— 这是产品规则，没擅自加。
