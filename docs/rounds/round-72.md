# 第七十二轮（2026-10-18）：换上新的应用图标（知字图标设计方案）

## 由来
用户：「开第二步之前，先把downloads里的知趣图标方案给应用了，然后继续」。`~/Downloads/知字图标设计方案.zip` 里是一套导出好的 PNG（近黑圆角方块上一道白色螺旋线）：
`favicon-16.png`、`favicon-32.png`、`icon-192.png`、`icon-512.png`（圆角、四角透明）、`apple-touch-icon.png`（180，铺满）、`icon-512-maskable.png`（铺满、图案在安全区里）。
名字和仓库里网页图标的四个文件一一对应。

## 查出来的
- 现在的图标还是第四十轮换中性配色之前的**蓝底白「知」**（`MakeIcon.swift` 现画的），和界面早就对不上。
- **网页的 `favicon.ico` 不是图标**：6 个字节的文本「zhiqu」（9 月 2 日放的占位）。每一页的第一个 `rel="icon"` 都指着它（`sizes="any"`），浏览器拿到的是一个解不开的图标。
- 桌面应用：macOS 的 `.icns` 每次打包由 `MakeIcon.swift` 画「知」；Windows 的 `zhiqu.ico` 是提交进仓库的 4 张图。

## 计划
1. 网页：方案里的四张 PNG 原样换进 `assets/icons/`；`favicon.ico` 换成真的 ICO（16、32 用方案里给小尺寸专门出的两张，48 从 512 缩）。判据先见红：favicon 是真 ICO、含 16 和 32；清单里每张图的实际像素和写的 `sizes` 一致。
2. 桌面：`MakeIcon.swift` 不再画「知」，改成拿方案的 `icon-512.png` 生成 macOS 的 iconset（按 macOS 图标的版式四周留白），顺带出两个 ICO；Windows 的 `zhiqu.ico` 换成 16–256 六档。
   方案最大只到 512：macOS 最大那一档（512@2x = 1024）只能放大，照实写，问用户要不要 1024 或矢量稿。
3. 界面里的「知」字标识（侧栏、落地页）不在这套导出里，不动；换不换问用户（换了首页轮播的截图也要重出）。
4. 收口：换缓存令牌、真浏览器里看图标都取得到、全量、桌面应用重新打包并核对 `.icns`、本轮记录、提交（不推）。

## 结果
- **网页**：`assets/icons/` 的四张（`icon-192.png`、`icon-512.png`、`icon-512-maskable.png`、`apple-touch-icon.png`）换成设计稿原样（逐字节就是 zip 里那几张）。
  `favicon.ico` 换成真的 ICO：16、32 是设计稿给小尺寸专门出的两张，48 从 512 缩（2.9 KB）。页面、清单都不用改（文件名一样），缓存令牌换成 `20261018-new-app-icon`。
- **桌面**：`MakeIcon.swift` 不再画「知」，改成读设计稿：macOS 的 iconset 按 macOS 图标的版式四周留白（1024 的画布里图标占 824，原来留 0.085），打包脚本每次照它出 `.icns`；
  同一个工具顺带出两个 ICO —— 网页的 `favicon.ico`、Windows 安装包的 `zhiqu.ico`（16 / 32 / 48 / 64 / 128 / 256，原来是 16 / 32 / 48 / 256 四张蓝底「知」）。
  设计稿里给 16、32 专门出的两张放在 `deploy/desktop/icon/`（ICO 的来源）。设计稿最大只有 512，iconset 最大那一档（1024 像素）是放大出来的。
- **判据**（`WebAppManifestTest` 加两条）：favicon.ico 和 zhiqu.ico 是真的 ICO（文件头、每一张是解得开的 PNG、目录写的尺寸就是图的尺寸、要的尺寸都在）；清单和页面写的图标尺寸就是文件的实际像素。
  第一条对着原来的 6 字节文本见红；扰动：换回旧的四张 zhiqu.ico、192 的位置放 180 的图、ICO 目录写错尺寸，都红。原有的两条（页面都引用、清单里的文件都在）对 6 字节的文本是绿的 —— 文件在、引用也在，只是不是图标。
- **真浏览器**：`/favicon.ico`（`image/x-icon`）、`apple-touch-icon`、清单里的三张都 200、都解得开、尺寸和写的一样；排在一页上截图看过（圆角版、铺满版、maskable 的留白都对）。
- **没动的**：界面里的「知」字标识（侧栏左上角、落地页）不在这套导出里，照旧；要不要也换成螺旋线问用户（换了首页轮播的截图也要重出）。

## 收口
- 后端全量 `mvn -o clean package`（开着 Docker）：**1170 项、0 失败、0 跳过**（多的两项是上面那两条判据）。
- 桌面应用重新打包：`codesign --verify --deep --strict`、`hdiutil verify` 都过；把应用里的 `知趣象限.icns` 拆回 iconset 看过，十档都是新图标、四周留白；
  JAR 里的 `favicon.ico`、四张图标、service worker、页面逐字节等于源码，四张图标逐字节等于设计稿。没有启动或替换用户在用的应用（Dock 里的图标要装上新包才换）。
- **要用户定的**：界面里的「知」字标识（侧栏、落地页）换不换成螺旋线；设计稿有没有 1024 或矢量版（macOS 最大那一档现在是放大的）。
