# 第五十五轮（2026-10-09）：界面打磨第 7 步 —— 知识 Wiki 的阅读排版与工具栏

## 由来
用户 2026-10-09「继续ui」。`docs/ui-plan.md` 第 7 步：「阅读排版（行宽、字号、段距、标题层级）、工具栏」。

## 现在是什么样（验证账号 207 页，另加了四页像样的：目标 / 薄弱点 / 项目 / 复盘）
- **正文没有行宽**：卡片多宽一行就多长（1440 宽时一行 70 多个字）；正文 13.5px、行距 1.75，和 AI 助手的聊天气泡一个样 —— 读长文偏挤。
- **标题层级**：一级 20、二级 17、三级 15.5 还带一道下划线（三级比二级还显眼）；段距一律 8px，标题前后也差不多，分不出节。
- **样式全写在渲染出来的 HTML 里**（`renderMarkdown` 每个标签带一串内联样式）：编辑器里用「段落」下拉插进去的标题、列表没有这些内联样式，和打开时渲染出来的长得不一样。
- **页面头部**：「文档视图」一行小字（界面规矩：标题上面不加小字）+ 页名；正文第一行通常又是同名的一级标题 —— 名字连着出现两遍。
- **工具栏**：「点击正文或标题即可编辑」「段落」两段说明文字 + 下拉 + 「B I U `」四个字母当按钮 + 「链接 公式 参考 源码」四个字按钮，挤成一行、两行。
- **顺手照出的我自己的回退**：第五十二轮给任务页的行起名 `zq-task-row`，Markdown 的勾选项（`- [ ]`）用的也是这个类 —— Wiki 里的勾选项被套上了任务表的内边距、分隔线和悬停底色（截图里一条条粗边框）。

## 计划
1. `renderMarkdown` 不再写内联样式：外层 `<div class="zq-md">`，标题、段落、列表、引用、代码块、表格、分隔线、勾选项都靠样式表的 `.zq-md …` —— 基本样子和原来一模一样（AI 助手的消息不变，量前后计算样式）；
   编辑器「段落」下拉插进去的东西自然和渲染出来的一样。
2. Wiki 的正文 `.zq-prose`：一行最多 40 个汉字上下（`max-width: 46em` 量出来再定），正文 15px、行距 1.85，段距加大，标题一级 24 / 二级 19 / 三级 16（去掉三级的下划线），节前留白比节后多；列表、引用、代码块、表格跟着放松。
3. 页面头部：去掉「文档视图」小字和两段说明，页名照旧点了改名、字大一号；正文第一行和页名一样的一级标题不再显示第二遍（内容里照样留着、保存不动它）。
4. 工具栏：一行 —— 段落下拉 + 图标按钮（加粗、斜体、下划线、行内代码、链接、公式、参考、源码），每个有悬停说明；放不下就换行。
5. 任务页的行改名 `zq-task-line`（回退修掉），并加判据：页面模块的类名不和 Markdown 渲染出来的类名重名。
6. 判据（真跑 `renderMarkdown`：没有内联样式、类名齐；Wiki 的行宽 / 字号 / 标题层级在样式表里；重复的页名藏起来但不删）；扰动见红；真浏览器量行宽、截图（浅 / 深、窄）；全量；桌面应用重新打包。

## 结果

**做了的**
1. `renderMarkdown`（`zhiqu-api.js`）不再写内联样式：外层 `<div class="zq-md">`，里面是光秃秃的标签加五个类（`zq-md-table`、`zq-task-row`、`zq-math`、`zq-math-i`、`zq-mono`）；只有代码块着色的 span 还带颜色。
   样子在 `zhiqu-ui.css` 的 `.zq-md …`，数值和原来内联的一模一样 —— AI 助手的消息前后量了计算样式（一段假模型回的 Markdown，标题 / 列表 / 引用 / 表格 / 代码 / 勾选项），只有勾选项变了，那是要修的那一处（见 4）。
   勾选项「勾上了就划掉」改成样式表按 `input:checked` 画：原来写死在文字上，点一下勾选框样子不跟着变。
2. Wiki 正文 `#zq-doc` 加 `.zq-prose`：一行最多 42em（15px 时 42 个字；1440 宽实测 630px、42 字，原来 70 多个），正文 15px、行距 1.85，段距 12px；标题 24 / 19 / 16 / 15，节前留白比节后多，三级标题不再带下划线。
   计划里写的是「46em 量出来再定」：46 字一行在 1440 宽时读着还是长，定在 42。
3. 页头：去掉「文档视图」小字、「点击正文或标题即可编辑」「段落」两段说明；页名 `.zq-wiki-title` 大一号（20px，两行截断）。工具栏一行：段落下拉 + 八个图标按钮（加粗、斜体、下划线、行内代码、链接、公式、参考、源码），各有 `title` 和 `aria-label`；「源码」按下时 `aria-pressed="true"`（换成图标以后看不出现在是源码还是排版）。新图标七个进了 `ICONS`。
   正文第一行和页名一样的一级标题挂 `.zq-dup-title`：读的时候藏起来，编辑时露出来；内容里留着，保存原样写回去（`markDuplicateTitle`，打开一页、从源码回到排版两处都标）。
4. **我自己第五十二轮的回退**：任务页的行起名 `zq-task-row`，和 Markdown 勾选项的类重名 —— Wiki 里的待办被套上任务表的内边距、分隔线和网格（三轮没人发现）。任务页的行改叫 `zq-task-line`（`tasks.js`、样式表、`tasks-check.js`、`TasksLookTest`）。
5. 编辑器插入的东西和渲染出来的同一个样子：「插入待办」「行内代码」「参考链接」不再自带内联样式；历史版本的预览容器原来也叫 `zq-md`，和里面 `renderMarkdown` 的外层重名、两层规则叠在一起，改叫 `zq-rev-body`。
6. 缓存令牌 `20261009-wiki`。页面和模块里的内联 `style=` 705 → 664 处（第 9 步要降到 100 以内）。

**判据**
- `markdown-check.js`（由新的 `WikiLookTest` 调用，真跑发布的 `renderMarkdown`）：每个标签只带白名单里的属性（没有 `style`，`<pre>` 里的着色归 `highlight-check.js`）；每种块长成约定的样子；渲染出来的每个类、每个要紧的标签（h1–h4、p、列表、引用、pre、code、表格、hr、a）在样式表里有 `.zq-md …` 规则；
  别的页面 / 模块不往页面里放 Markdown 的类（只认 Wiki 编辑器「插入待办」那一种结构一模一样的，而且必须恰好认出 1 处 —— 认不出来说明扫描没在看）。
- `WikiLookTest` 另外三条：读长文的排版（行宽按 em、34–46 字；正文比聊天大；行距 ≥ 1.8；标题一级比一级小、最小的不小于正文、节前比节后空；三级不带下划线）；页面（没有「文档视图」和提示、正文是 `.zq-prose`、工具栏八个按钮都只有一个图标且有 `title` / `aria-label`、「源码」有 `aria-pressed`）；重复的页名（只挂类不动内容、两处画正文后都标、编辑时不藏）。
- `DesignTokensTest` 的内联字重下限 80 → 70：内联样式挪进样式表，扫到的用令牌的内联字重从 80 多处降到 75（这条下限只证明没扫空）。
- 扰动 17 个全红：段落带回内联样式、勾选框去掉 `contenteditable="false"`、样式表少了 `.zq-md blockquote`、行内公式的类没规则、任务页的行改回 `zq-task-row`、行宽 none / 60em、三级比二级大、三级带回下划线、二级节前不比节后多、正文不是 `.zq-prose`、「文档视图」回来、加粗换回字母「B」、「源码」没有按下态、重复的页名改成删掉、从源码回来不标、编辑时也藏。
