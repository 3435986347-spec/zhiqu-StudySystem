# 第一百七十三轮（2026-11-25）：网页版 agent / 带工具的服务，验收底线自动补上

[`docs/testagent-review-plan.md`](../testagent-review-plan.md) 3.5 的第 1 条。产物在另一台电脑上，这里只有这份计划。止血（删调试接口、收 CORS、工作目录、抓取内网、密钥）不做。这一轮只改 zhiqu。

## 要做什么

那次做「对话和工具 agent，网页版」，写进 `criteria` 的六条都是展示层（流式、时间线、mock）。核对员只照写下来的标准放行，所以会话落在哪、谁能调用、密钥放哪、有没有可重跑的测试，一路被放过。

认出**正在做**网页版 agent，或带工具的服务时，四条底线同时出现在两处：

- 目标提示（执行者每一轮都看得到，标准还没写也在；写了展示层之后仍在）
- 核对材料的【验收标准】（模型没写、写了反话、把 `criteria` 写满 1000 字，都补在后面）

四条是：会话记在服务端（刷新、重启、换浏览器还在，不能只放浏览器本地）；谁能调用、工作目录和模型地址由服务端定，不能由网页请求覆盖；密钥在服务端，不进浏览器，也不在每次请求里明文传来传去；留下可重跑的测试（真实请求和断言，语法检查不算）。

不塞进 `goal.criteria`。那里最多 1000 字，写满会把底线截掉。`goal_update` 记下标准时也说一句：底线会一并核对。

不认的：贪吃蛇、贪吃蛇网页、工具栏、命令行 agent、只看不改、写一篇介绍、后端管理页。认的：那次的目标原文、带工具的本地服务、网页版智能体、带工具调用的后端、`Build a web agent`、`Create a browser agent`。
