# 第一百一十轮（2026-11-07）：Codex 同级第 3 步 —— search 认正则

## 由来
方案第 3 步（[`docs/codex-parity-plan.md`](../codex-parity-plan.md)）。真实评测里 `search` 调了 210 次，28 次是空的；它只认字面文本，不能按文件类型过滤，`.gitignore` 里的生成文件也一起搜。`shell` 里虽然能 `grep`，但 `search` 认草稿（网页改了还没确认的文件）、认 GBK、说得出跳过了什么，这些 `grep` 都没有。

## 计划
1. `regex: true` 按正则找，默认还是字面（老的调用不变）。写错了照实说，不悄悄退回字面。
2. 正则是模型给的，灾难性回溯不能卡死进程：跑在带时限的 `vm` 里，超时就停，说清楚。
3. `glob` 按文件过滤：`*.py`、`src/**/*.js`、`*.{js,ts}`。
4. 默认跳过 `.gitignore` 忽略的（根、子目录、工作区在子目录时上层的、`.git/info/exclude`），跳过了多少要说出来；`include_ignored: true` 才搜。明确指定 `path` 进被忽略的目录时照搜。
5. 字面没搜到、query 里有正则符号：提醒一句。
6. 判据：匹配规则拿真 `git check-ignore` 当对照，不是照自己的理解写。命令行和网页同一份。

## 结果
**真跑过的**
- 真仓库上：`class\s+\w+Test\b` + `*.java` 137 毫秒，`glob` 限定到 `zhiqu-cli/src/**/*.js` 25 毫秒，字面的老用法 229 毫秒。
- 真浏览器（网页 auto 档，假模型把参数交给 search）：正则 + glob 只搜到 `.py`；`(a+)+b` 碰上 60 个 a，1.5 秒停下、说清楚、这一轮照常收尾；写错的正则照实说；`include_ignored` 才搜到被忽略的文件。

**查出来的**
- 第一版用 `\s` 去行尾空白，把 tab 也去了：git 只去空格。拿真 `git ls-files` 当对照才看到（补样本之前这条也是绿的）。
- 扰动第一批 47 处红 36。绿的 11 处：3 处是多余代码（括号配对、CRLF 分行、规则范围，别的逻辑兜着，删了）；8 处是判据没照到（文件最后一行没换行、字面行号、带斜杠的 glob 从根算、`a/**`、`?` 不跨目录、`.gitignore` 里 `{}` 是字面、`#` 开头的文件、目录规则挡不挡同名文件），都补了，复验 11 处全红。

判据：后端全量 1339（1 跳过写明原因）、命令行 344/344、评测工具 102 过 1 跳。

**还没做的**
- `.gitignore` 只认工作区这一套和 `.git/info/exclude`，用户级的 `core.excludesFile` 不读；`core.ignorecase` 不看（按大小写敏感算）。
- `list_files` 还是只跳过 `node_modules` 这类目录，不看 `.gitignore`（方案第 3 步只说 search）。
