# 第四十轮（2026-10-06）：界面打磨第 1 步 —— 设计令牌、白天白晚上黑、金色强调

## 由来
`docs/ui-plan.md` 第 1 步。用户 2026-10-06 定了：中性风；主题收成白天白色、晚上黑色（跟着系统外观走）；喜欢金色，也说可以试试纯黑白；**第 1 步做完先给他看**。

## 计划

1. **主题收成一套**：去掉 v0…v4 五套配色；`:root` 是浅色、`html[data-zq-mode="dark"]` 是深色，两套定义同一批颜色令牌。
   外观三档：跟随系统（默认）/ 浅色 / 深色；换一个存储键 `zq.theme` —— 旧的 `zq.mode` / `zq.ver` 不再读，所以原来手动选过浅色的人也回到「跟随系统」（用户定的就是白天白、晚上黑）。
   跟随系统时，系统外观一变页面当场跟着变（`matchMedia('(prefers-color-scheme: dark)')` 的 change）。每页头上那一行内联脚本照这个规则先定好明暗，免得先闪一下另一种颜色。
2. **强调色**：金色（默认）、黑白两档，`html[data-zq-accent]`，键 `zq.accent`；菜单「界面风格」里两行：外观、强调色。
3. **令牌**：中性灰阶（浅色以白为底、深色以近黑为底）；字阶 12 / 13 / 14 / 16 / 20 / 24 / 30；间距 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40；圆角 6 / 10 / 14；阴影两级；字重 400 / 500 / 600。
   **对比度**：正文、次要、更次要的文字在页面底色、卡片、浅底上都 ≥ 4.5 : 1；强调色作文字（链接）≥ 4.5 : 1、按钮上的字 ≥ 4.5 : 1 —— 浅 / 深 × 金 / 黑白四种都算。
4. **组件类用上令牌**：标题、小标题、标签、按钮（主 / 次）、输入框、下拉、卡片、数字卡、徽标、表格、侧栏导航、头像按钮、弹出层、弹窗、面板收起按钮；
   新加以后几步要用的：危险按钮、小号按钮、分段控件、页签、空状态、骨架。
   **这一步不动页面里的内联样式**（817 处，第 3～9 步一页一页收），所以页面的大结构不变，变的是颜色、字、按钮、输入框、卡片、侧栏这些。
5. **判据**：只有一套配色（没有 `data-zq-ver` 选择器）、浅深两套定义的令牌一样多；对比度按 CSS 里的值**算**（不是写死期望）；
   头上那行内联脚本在 node 里真跑：跟随系统 × 系统明 / 暗、手动浅 / 深、旧的键被忽略；组件类里的字重只有 400 / 500 / 600。各自扰动见红。
6. **给用户看**：内置浏览器里 AI 助手、看板、任务、知识 Wiki、设置弹窗，浅 / 深 × 金 / 黑白，1440 宽；手机宽一张。截图发给用户，**停在这里等他挑强调色、看方向**。

### 怎么验
截图；全量通过、扰动见红。这一轮先不打桌面包（等用户看过、定了再一起）。

## 结果（2026-10-06）

照计划做完，停在「给用户看截图」。

- **主题**：`zhiqu-ui.css` 五套配色 × 明暗的十块（约 460 行）收成四块：`:root`（浅色 + 金）、深色、黑白强调色的浅 / 深两块。样式表 886 → 约 560 行。
  外观：跟随系统（默认）/ 浅色 / 深色，键 `zq.theme`；强调色：金 / 黑白，键 `zq.accent`；旧的 `zq.mode` / `zq.ver` 不再读。
  14 个页面头上那行内联脚本、`<html>` 上写死的 `data-zq-ver="v1"`、浏览器的 `theme-color`（原来是旧的蓝，现在按明暗各一个）、`manifest.json` 的两个颜色、落地页自己的明暗切换都跟着换了。
  菜单「界面风格」改成两行：外观（跟随系统 / 浅色 / 深色）、强调色（金色 / 黑白）。
- **令牌**：灰阶（浅色以 #FAFAFA / #FFFFFF 为底，深色以 #0B0B0C / #141416 为底）；金 #8C6D22（浅）/ #D4B062（深）；字阶 7 级（12 / 13 / 14 / 15 / 18 / 20 / 26，正文 13）、间距 8 级、字重 3 档、圆角 6 / 10 / 14、阴影两级、焦点光晕。
  次要文字 #8D99A8 → #6B6B74（对比度 2.7 → 5.3 : 1）。组件类（标题、标签、按钮、输入框、卡片、数字卡、徽标、表格、侧栏、菜单、弹出层、弹窗、设置弹窗的分栏、Wiki 工具栏、计划确认）用上令牌：
  卡片靠描边不靠阴影、按钮 34px 高、导航选中只用浅底（去掉左边那条强调色竖线）、字重只剩 500 / 600。新加：危险按钮、小号按钮、分段控件、页签、空状态、骨架（还没有页面用，第 3 步起用）。
- **实测**（内置浏览器，1440×900）：浅·金、深·金、浅·黑白、深·黑白的看板，浅 / 深的 AI 助手，深色的任务，浅色的 Wiki 和设置弹窗，「界面风格」弹层，手机宽的看板。
  跟随系统时把模拟的系统外观在明暗之间拨：页面当场跟着变（背景 #FAFAFA ↔ rgb(11,11,12)）。要注意：面板藏着的时候浏览器不跑渲染、媒体查询的变化事件也就不来 —— 第一次拨的时候面板正藏着，看着像没跟上；
  另起一个监听器对照，确认是同一件事，面板一露出来就跟上了。
- **没动的**（照计划，第 3～9 步）：页面里的内联样式 817 处 —— 看板周历的灰块、「逾期未完」的大红数字、任务页绿色的「新建任务」、AI 助手的输入区这些还是原样，只是换了颜色和字。

**判据**：`DesignTokensTest` 四条 —— 外观（`theme-check.js` 在 node 里真跑头上那行和 `zhiqu-ui.js`：15 条）、只有一套配色（各页同一行脚本、没有 `data-zq-ver`、浅深两块令牌同一批、黑白两块同一批）、
对比度（按样式表里的值算：浅 / 深 × 金 / 黑白，各级文字在三种底上、侧栏、按钮上的字、强调色作文字、状态色和象限色，共 88 对）、字重只有 400 / 500 / 600。
`InitErrorReplacesDemoContentTest` 认头上那行的键改成 `zq.theme`。扰动 8 个全红：头上那行不看系统、系统外观变了不跟、又读旧键、次要文字回到 2.7、深色少一个令牌、标题字重 700、又有五套配色的选择器、深色黑白按钮上的字看不见；
前两个扰动只改了看板一页时先被「各页同一行」那条照出来，另外拿改过的那一页单独跑 `theme-check.js`，行为判据自己也红（3 条、1 条）。

**做到一半用户说「或许字体设计的稍微更小一点会更好」**：字阶整体小一档 —— 正文 14 → 13px、页面标题 24 → 20、小标题 16 → 15、大数字 30 → 26、按钮 / 输入框 / 导航项 34 → 32px 高；
中文最小不低于 12px。截图在这之后全部重拍。

**第一遍全量红了 1 条**：`WebAppManifestTest.主题色不能和界面分叉` 要求 `manifest.json` 的 `theme_color` 等于 `--zq-primary` —— 那是旧设计（状态栏用主题蓝）。
中性配色里浏览器的边框跟着页面底色走（各页的 `theme-color` 也是这么改的），所以判据改成：`theme_color`、`background_color` 等于浅色的 `--zq-bg`，
每一页浅 / 深两个 `theme-color` 分别等于浅 / 深的 `--zq-bg`。扰动两个都红（一页的深色 theme-color 改成别的、manifest 改回近黑）。
