# 第一百六十八轮（2026-11-24）：长活省钱第 3 步——preview_page 带文字版的页面情况，核对员也看截图

[`docs/agent-efficiency-plan.md`](../agent-efficiency-plan.md) 的第 3 步（问题 C、E）。

## 计划与「要你定」

- 用户定的：① 核对员要看最后一张截图（模型不收图时退回文字）；② 每轮截图上限「不确定」。
- 第 ② 件先拿那段会话的数据看：两次改动之间连着截几张——137 段里 127 段是 1 张、9 段 2 张、1 段 4 张；一个目标轮 44 张是因为改了 40 多次。模型是「改一下、截一张看看」，**不是**不改东西反复截。按轮的硬上限只会挡住正常的迭代，旧截图本来也只留 2 张（`KEEP_IMAGES`）。所以**不设上限**，写进计划的结论里。
- 原来 `preview_page` 只给一张图：报错、白屏要靠模型看图猜；核对员只读文字，用户那段会话里模型为了给它凑「文字证据」专门写了回传报告的服务器和自检页（两个目标的第 2–4 轮）。

## 做了什么

- `tools/preview.js`：
  - `serveDir(root, { probe })`：给 html 注入探针（`PROBE_SCRIPT`，插在 `<head>` 最前面，没有 head 放在 doctype 之后），收探针 POST 回来的报告（只认 `PROBE_PATH`、64KB 以内）。探针收报错（含资源加载失败）、未处理的 Promise 拒绝、`console.error`，加上标题、可见文字开头、元素数、canvas 数；加载完 1.5 秒回传，3 秒时先回传一份加载中的。**探针是一行**：第一次真跑时页面第 2 行的报错报成了第 12 行（多行探针把行号推后了），模型照着改会找错地方。
  - `analyzePng`：解截图 PNG（8 位 RGB / RGBA，5 种滤波），抽样数颜色：一种颜色占 ≥ 97%（`FLAT_SHARE`）就说「几乎是单色——可能是白屏 / 黑屏，或者 3D 场景没画出来」。WebGL 的画布页面里读不到像素，从截图算最可靠。
  - `describePage`：拼成几行；没收到回传照实说（加载前就卡住、CSP 挡了内联脚本）。
- `tools/local.js`：`preview_page` 的工具结果里跟上这几行（命令行、网页 / 桌面宿主同一份）。截图后那条提示改成「文字情况在上面的工具结果里，先看那几行，再看图」。
- `goal.js` `lastScreenshot` + `agent.js` `verifyGoal`：核对员拿到最后一张截图（最近一条带图的消息里的最后一张），说明里告诉它截图可能早于最后几次改动、和工具结果冲突以工具结果为准；带图的请求出错（模型不收图之类）去掉图再问一次。

## 结果

- 新判据 `test/page-report.test.js` 9 条（含一段**真 Chrome**：页面里抛错、`console.error`、Promise 拒绝、黑底空画布都说得出来，行号和文件对得上；正常页面说没有报错、可见文字对；没有 Chrome 的机器显式跳过）。
- 10 处扰动，9 处见红：截图不开探针 → 2 红；插到最前面 → 1 红；Paeth 滤波解错 → 1 红；不认单色 → 3 红；核对员取第一张图 → 1 红；带图被拒不退回 → 1 红；工具结果不带文字版 → 1 红；回传不限大小 → 1 红；探针改回多行 → 2 红。**回传改成异步没有变红**：本机真 Chrome 上异步也送得到——推翻了注释里「异步的可能发不出去」的理由，注释改成「同步是保险，慢页面上没量过」。
- CLI 全量：739 项，717 过 / 22 跳 / 0 失败。
- 真程序：假网关（`start` / `delta` / `done`）+ `bin/zhiqu.js --goal … --mode auto`（非交互），模型对一个 `THREE` 没加载的黑底页面调 `preview_page`：工具结果里是「报错 1 条：Uncaught ReferenceError: THREE is not defined (/bad.html:2)」「100% 是同一种颜色 #000000，几乎是单色」；核对员请求里带着图、读到了报错，给的缺口是「页面有 ReferenceError，画面是黑的」。HOME / ZHIQU_HOME 用临时目录，没调付费模型。（只动命令行，真浏览器暴力测试换成这段真 Chrome + 真程序测试。）
