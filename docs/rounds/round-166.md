# 第一百六十六轮（2026-11-24）：coding agent 的上下文清理与目标核对——照一段真实长会话修

## 起因

用户给了一段真实的 zhiqu 命令行会话（`~/Desktop/test/.zhiqu/sessions/20261123-185647-15e6.jsonl`，28.8MB、1573 条事件，11-23 18:56 → 11-24 14:31），让我读完提优化方案。用脚本统计、再对源码，数字如下：

- 一个会话里做了 6 件不相干的事（鹈鹕骑车、加油站、黎曼猜想、福建舰视频、整理文件夹、写 ZHIQU.md）。
- 模型调用 452 次，输入共 1.89 亿 token，单次中位 37.6 万、最高 79.9 万；98.5% 命中缓存，但每次请求都贵、都慢。
- 工具：`shell` 201 次（其中 158 次在写文件，127 次是 Python `s.replace(...)`），`preview_page` 149 次（142 次 `timeout_seconds=300`），`write_file` 26、`apply_patch` 19、`edit_file` 4。

找到的问题，按收益排：

| 编号 | 问题 | 证据 | 原因（源码） |
| --- | --- | --- | --- |

| G | 每次 `compact` 事件把整份消息存一遍 | 19 份快照约 2000 万字，会话文件 28MB | `session` 的 compact 记录是全量 |
| H | 进程两次中途退出没有记录（12:21、12:38） | 下一次启动只说「进程中途没了」 | 没有退出时的记录；原因**没法确认** |
| I | 模糊目标（「继续打磨黎曼」）核对三轮才宣告卡住 | — | 设目标时不要求验收标准 |

## 计划（这一轮只做 A、B，是 [`docs/agent-efficiency-plan.md`](../agent-efficiency-plan.md) 的第 1 步；C–I 是那份的第 2–7 步）

1. **核对员不思考（B）**：`verifyGoal` 明确传不思考的档位（和摘要一样用 `SUMMARY_EFFORT`），输出上限够写一行 JSON。
2. **核对员出错不算执行者的（B）**：`parseVerdict` 解析不出 / 不是合法 JSON 时重试核对员一次；仍然不行就照实告诉用户「核对员没给出结论」，**不**计入 `verifyFailures`、不推执行者重做。
3. **先清也清工具调用的参数（A①）**：在 `clearStale` 里，旧的（最近 `CLEAR_KEEP_RECENT` 条以外）`write_file` / `apply_patch` / `edit_file` / `shell` 调用，参数超过阈值（暂定 2000 字）的换成占位——保持合法 JSON、保留 `path` / 命令开头，写明「已写入磁盘，原文 N 字，要看就 read_file」；调用与结果仍成对；纳入「能清出多少」的计算。已经是占位的不重复处理。
4. **清不出就摘要（A②）**：过了 `softLimit` 而先清清不出够大的一块时，直接走 `compactMessages` 摘要，不等到窗口 80%。注意：一次请求只做一次（不能每轮都摘），摘要失败的保险照旧。
5. **token 估算两边各一份**：如果动到估算（预计不动），按 CLAUDE.md 同步改另一边并跑 `token-estimate.json` 对拍。

## 验证计划

- 基线：`cd zhiqu-cli && npm test` 全绿再动手。
- 新判据先见红：
  - `verifyGoal` 的请求带不思考档位；核对员回空 / 回乱码时 `verifyFailures` 不变、会重试一次。
  - `clearStale` 对「参数占大头、输出很少」的历史能清出东西，清后每条 `tool_calls[].function.arguments` 都是合法 JSON，调用与结果仍成对，最近 N 条不动。
  - 过了软上限、先清清不出时会触发摘要，且同一轮只摘一次。
- 扰动：逐条删掉新加的那几句（`grep -c` 确认扰动落了），看对应判据变红；备份放 `src/` 外，`cp` + `touch` 恢复。
- 回放：拿用户这段会话在本机回放先清 / 摘要的决策，量「每次请求的估算占用」的中位数、最大值和摘要次数，前后对比。**这份会话是用户的私人数据（28MB），不提交进仓库**；判据用照它形状造的合成历史（参数大、输出小、截图多）。
- 真程序：本机脚本化假模型 + `pty` 跑 `bin/zhiqu.js` 的 goal 模式，核对员第一次回空、第二次回合法 JSON，确认不推执行者重做；不调用付费模型，HOME / ZHIQU_HOME 用临时目录。（本轮只动命令行，没有网页改动，「真浏览器暴力测试」换成这段真终端测试。）
- 收尾：CLI 全量 `npm test`；`ClaudeMdTest`；`git diff --check`。

## 做了什么

- `goal.js` `parseVerdict`：没有 JSON / JSON 坏了带 `unreadable: true`（核对员自己没答好），答了 false 不带。
- `agent.js` `verifyGoal`：明说不思考（`effort: SUMMARY_EFFORT`，和摘要同一档）；没答好再问一次。`runGoal`：两次都没答好照实说「没核对成，按执行者的证据收尾」，**不**记 `verifyFailures`、不推执行者重做。
- `compact.js` `clearStale`：旧的 `write_file` / `edit_file` / `apply_patch` / `shell` 调用，参数 ≥ `ARGS_CLEAR_MIN`（2000 字）的换成合法 JSON 占位——写文件留 `path`、补丁留 `files`（`writtenPaths` 认它，「读过之后又改过」照样认得出）、shell 留 `command_head` 且**不留半截 `command`**（照着占位再调一次就会跑出半截命令），shell 的脚本另存到 `sessions/<id>/out/`。结果在最近 8 条里的调用不动；参数和输出一起排、从最早的清起，一起算「能清出多少」。
- `compact.js` `softCompactable` / `softKeep` + `agent.js` 循环：大窗口（软上限低于六成那条线，即 1M 一类）过了软上限、先清这一轮什么都没清出，直接 `compactNow({ soft: true })`，留原文的预算是软上限的三分之一（留三成的话摘完马上又过线）；软摘没压下来记 `ctx.softCompactStuckAt`，要再多背 `minClear` 才再试。64K 一类的小窗口行为不变。`compactMessages` 多一个 `keepTokens` 选项。
- 顺带发现（没改）：直连模式（`direct.js`）根本不把思考档位发给供应商，`effort` 只在走服务器网关时生效；用户那段会话走的是网关。
