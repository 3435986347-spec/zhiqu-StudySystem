# 第一百零四轮（2026-11-05）：模型原地重复同一个调用；缓存命中率

## 由来
用户 2026-11-05 贴了一段公司电脑上的命令行记录：「ds 总是会一直重复，换了 opus5.5 就好很多，但是 opus5.5 命中率只有 9%；ds 命中率有 55%」。
- **重复**：deepseek-flash 把同一条 `node -e …`（每次都打印 `ok`、退出码 0）连跑 94 次，再跑一版 64 次，用满两次 60 轮，用户问「你在干什么」时认错，说完「好的」又接着跑。
  循环防的是同样的失败（`SPIN_LIMIT`）和连续只读（`READ_STREAK`），同样的成功谁都不管；第一百轮修的是不调工具的文字重复，这是调工具的重复。
  翻了评测全部 47 遍：同一调用连着重复从没超过 2 次（包括温度 0 的第九十八轮），所以不是温度一项能解释的，不动温度。
- **Claude 的命中率**：Claude 只缓存请求里用 `cache_control` 标过的部分，DeepSeek 是自动的。网关两条路都没标过（`grep cache_control` 零处），9% 只可能来自中转自己加的。
- **DeepSeek 的命中率**：拿评测真实会话模拟「和上一次请求的公共前缀」，第九十八轮模拟 93.3%（实际 95.5%，对得上）。评测里几乎不改任务清单（346 次调用 1 次），用户的会话改得多：
  清单写在系统提示里，排在所有历史前面，改一次下一次请求整段没命中。`slimThinking` 改写两轮之前的回复，每次也把那之后的内容弄丢，评测上损失约 1.6 个点（按价算约一成花费）。

## 计划
1. **同一个调用、同样的结果连着来**（`agent.js`，命令行和代码模式同一份）：比的是工具名 + 参数（键的顺序不算）+ 结果（命令用时不算）；第 3 次在结果后面附提醒，第 5 次起不执行、回「没有执行」，
   再拒 3 次（第 7 次）停下这一轮、照实说。换一个调用、结果变了、用户新说一句都重新数。
2. **任务清单不进系统提示**：系统提示和历史只追加、不改写。清单在 `update_todos` 的调用里本来就在历史中；隔 8 轮工具把清单附在工具结果后面（记进历史），压缩之后补一条。
3. **省略旧思考只在上下文吃紧时做**（超过窗口一半）：1M 窗口的模型基本不再改写历史；小窗口照旧。
4. **网关给 Claude 标缓存**：Anthropic 接口和「OpenAI 兼容 + 模型名带 claude」（中转）都在系统提示和最后一条消息上标 `cache_control`（滚动），DeepSeek 等不动；
   供应商 400 就去掉重试并记住这个模型，温度被拒也一样记住（Opus 5.5 不收 temperature，现在每一轮都要先挨一个 400）。中转把命中数放在 `cache_read_input_tokens` 里也认。
5. 判据先红：历史只追加（连续两次请求，前一次的消息必须是后一次的前缀）是这一轮的主判据。三组全绿。Claude / 中转这边没有 key，只能用假模型验请求长什么样，真实命中率要用户跑一段看 `/usage`。

## 结果
- **同一个调用、同样的结果连着来**：第 3 次提醒、第 5 次起不执行、第 7 次停下这一轮并照实说（`repeat-call.test.js` 5 条）。比的是工具名 + 参数（键的顺序不算）+ 结果（命令用时、附的提醒不算：记录里 0.1s / 0.2s 来回变）。
  同样的失败原来只提醒不拦（提醒里的次数每次不同，比结果时要去掉），现在第 5 次起也不执行。用户新说一句重新数。
- **历史只追加**（`cache-prefix.test.js`）：一段有清单、长思考、两句用户的话的会话，每次请求都必须以上一次请求的全部消息开头、工具定义不变。
  任务清单搬出系统提示：隔 8 轮工具附在工具结果后面（记进历史），清单不在历史里（压缩过）补一条；省略旧思考只在上下文过半时做。
- **给 Claude 标缓存**（`PromptCacheMarks`）：Anthropic 接口和「OpenAI 兼容 + 模型名带 claude」都标系统提示和最后一条消息；DeepSeek 等一个字不变。带标记被 400 就去掉重试，成功才记住这个模型不再标（再 400 是别的错，照常报、不记）。
  温度被拒也记住（Opus 5.5 不收 temperature，原来每轮先挨一个 400）。中转照搬的 `cache_read_input_tokens` 也认。
- 顺手修第一百轮的漏洞：那句「别复述」没进 `LEGACY_SYSTEM`，压缩时会被当成用户的原话。
- 模拟（评测真实会话，和上一次请求的公共前缀，第九十八轮模拟 93.3%、实际 95.5%）：不省略旧思考 +1.6 个点；评测几乎不改清单，清单这一项在评测上量不出来（346 次调用才 1 次）。
- **没验证的**：Claude 和用户的中转这边没有 key，只用假模型验了请求的样子和回退；真实命中率、中转认不认要用户跑一段看 `/usage`。温度没动（评测 47 遍里同一调用连着最多 2 次，包括温度 0 的第九十八轮，没有证据）。
  这一轮没有界面改动，真浏览器那段暴力测试没做；用户记录里的循环在 `repeat-call.test.js` 里照原样连发 30 次验的。
- 判据扰动 31 处全红（命令行 18、网关 13）。头一遍有 3 处没红：改过清单不重新数、清单做完了留一个空提醒、成功之后不再标 —— 各补了样本才红。
- **全量里红了两条，都不是这一轮的逻辑，查清才修**：
  - `CodeAgentLoopIntegrationTest`：测试读的是用户真实的 `~/.zhiqu/workspace-state.json`，它一存在就盖过测试配的 EXEC 和临时目录。用户 11-03 用第一百零三轮的按钮切到了 manual（WRITE），判题命令就不让跑了；
    之前绿是碰巧 EXEC —— 那时判题命令其实跑在用户真实的 `game` 目录里（跑的文件不存在，没造成损害），写设置的测试也会写到那份文件。`src/test/resources/application.properties` 把状态文件全局指到临时目录，加一条判据钉住（删掉那行红过）。第九十二轮记过这个坑（本机验证后端要带），测试这边一直漏着。
  - `WebPageFetchSsrfGuardTest` 的 `.invalid`：这个网络的 DNS 连 `.invalid` 都答（代理 fake-IP，`198.19.x.x`），解析失败根本不发生。量不了就写明原因显式跳过，不算通过。
    顺带记一笔：这种网络下 SSRF 校验看到的是代理的假地址，内部域名也一样，它防不住；没改（拦 198.18/15 会让开着代理的人网页抓取全挂）。
- 三组判据：后端全量 1299（0 失败，1 跳过 = 上面写明原因的那条 DNS）、命令行 297/297、评测工具 101 过 1 跳。
