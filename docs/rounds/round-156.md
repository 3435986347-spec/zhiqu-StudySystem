# 第一百五十六轮（2026-11-18）：代码模式撤回这一轮的草稿

真 DeepSeek 那一遍：写完 `test_calc.py` 的草稿，用户说「不要了」。模型没办法撤 —— 一遍让用户自己去页面上拒绝，一遍把它改成空内容的草稿，还说确认后磁盘上不会有这个文件。确认一份空的新建草稿，是写出一个空文件。

## 做了什么

草稿模式（网页选了文件夹、桌面本机代码助手）多一个 `discard_draft`。下发的和能执行的是同一份清单：给了写才有；只读、plan 档、命令行（直接写盘）、生成到产物（写的是真文件）都没有。没下发的名字照样执行不了。

- 新建的：草稿和草稿层都去掉，就当没建过，用户确认时不会有它，磁盘上也没有。
- 改过的：回到磁盘上的样子。读过的记录清掉，再改要先 `read_file`（不清的话，哈希对不上，模型会以为是用户在编辑器里改的）。
- 之前几轮已经交给页面的草稿碰不到，工具说明白让用户在页面上拒绝。
- 系统提示里写明：不要把内容改成空文件来代替撤回。
- 状态卡拿掉这个文件的「改过」「新建」「同一处改得多」和压缩后要塞回去的那一段。回答里一步「撤回草稿」。

顺带：直连 Claude 时，预览截图那条 user 的内容是数组，原来 `String()` 成了 `[object Object]`，图没发出去。照后端 `AnthropicFormat` 拆成 image 块。截图并进工具结果之后再来一条补充，原来并不上、成了连着两条 user；现在相邻的 user 并成一条，`tool_result` 排在前面。

命令行版本号不动（还是 0.2.6）。这个工具只在草稿模式，npm 上的命令行直接写盘，用不上。网页代码模式跑的是打进 JAR 的那份，部署就到。桌面应用跑的是安装包里的那份，要重打才到用户手里。

## 判据

`zhiqu-cli/test/discard-draft.test.js`。命令行全量 `node --test test/*.test.js`：676 项，657 过，0 失败，19 跳过（没有 bubblewrap 的那些）。

新判据都见过红（去掉对应的那一句再跑，失败的是它）：

| 去掉 | 红在 |
|---|---|
| `known.delete` | 再改报的是「被改过了」，不是「必须先 read_file」 |
| `overlay.delete` | 撤回之后还搜得到草稿里的字 |
| 清掉 churn | 卡上还写着同一处改了 6 回 |
| 清掉 focus | 压缩后还会把这个文件塞回去 |
| 系统提示那句 | 草稿模式的环境里没有 `discard_draft` |
| 相邻 user 一律合并 | 截图后面的补充成了连着的第二条 user |

暴力（没有页面改动，不在浏览器里点）：四十份草稿撤一半（名字里有空格、空内容、同一份撤两次），剩下的还搜得到，撤掉的搜不到，磁盘上的文件一个字节没动。生成到产物时模型硬调 `discard_draft`，文件还在，回的是「没有这个工具」。

## 结果

命令行全量见上。网页代码模式用的是打进 JAR 的这份，随这一轮部署到 `zhiqustudy.com`。桌面应用跑安装包里的那份，发布留给用户。
