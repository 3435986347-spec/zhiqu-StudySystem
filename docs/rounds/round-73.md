# 第七十三轮（2026-10-18）：换编辑器第 2 步 —— 新编辑器补齐

## 由来
第七十轮的分轮迁移计划第 2 步（`docs/rounds/round-70.md` 末尾）：新编辑器（CodeMirror 6 实时预览，还在开关后面）补齐现在的编辑器有、它还没有的：
粘贴 / 拖进图片、下划线、表格的样子、点哪儿光标落哪儿、代码块高亮。第七十二轮先换了应用图标（用户要求插在第 2 步之前）。

## 计划
1. **图片**：编辑时粘贴、拖进图片，工具栏「插入图片」，都走现有的上传（`insertWikiImage`），插入 `![[/api/knowledge/images/N|名字]]` 到光标 / 放下的位置；
   上传期间接着打字，插入点跟着移动；换页、取消、退出登录后回来的上传照旧不插。拖进别的文件不能被 CodeMirror 当文本读进来（它默认这么做）。
   光标不在时图片显示成图（私有图片照旧带登录去取）。
2. **下划线**：工具栏「下划线」加 / 去 `<u>…</u>`；光标不在时藏标签、显示下划线。
3. **表格**：光标不在表格里时画成和阅读模式一样的表格，点一下进原文；在里面时原文用等宽字，列对得齐。
4. **代码块高亮**：用阅读模式同一个着色（`tokenizeCode`），编辑时代码块里也有颜色。
5. **点哪儿光标落哪儿**：阅读模式里点的那个字，进编辑后光标就在原文里对应的位置、那一行停在原来的高度（现在是按屏幕坐标在新排版里找，越往下偏得越多）。
   做法：点的那一行可见文字 + 前面同样文字出现过几次 + 点在第几个字，映射到原文那一行、那一列（跳过列表符号、加粗、链接地址、公式源码这些看不见的字）。
6. 判据：node 里真跑 `wiki-cm.js` 的纯函数和 `knowledge-wiki.js` 的接入（`wiki-cm-check.js`），先见红；真浏览器里每一样都点一遍；第七十一轮的 14 页语料「不改保存」照旧 14/14。
7. 收口：全量（开 Docker）、换缓存令牌、本轮记录、README 和 CLAUDE.md 各一行、桌面应用重新打包、提交（不推）。

## 结果

新编辑器（开关后面）补齐了这些，旧编辑器一点没动（14 页语料「不改保存」照旧 6/14）：

**点哪儿光标落哪儿**：阅读模式里点一个字，进编辑后光标就在原文里那个字上，那一行停在点的高度。
- 做法：阅读视图那头记下点的那一段可见文字、前面同样的一段出现过几次、点在第几个字（`anchorFromCaret`，段按 `<br>`、子块、代码行切）；
  原文那头把每一行（表格是每一格）换成看得见的字并记住每个字在原文的列（`visibleText`，照 `mdInline` 的显示：成对的 `*` 才藏、双链只留显示的字、公式和图片各算一个占位字），
  找到同一段的第几次出现，按第几个字换回列（`sourcePosition`）。对不上（点在公式块上之类）才退回按坐标找。
- 量（2 万字的长页面，可视区里六个深度各点一个字）：

| | 落在点的那个字上 | 那一行离点的位置 |
|---|---|---|
| 原来（按屏幕坐标在新排版里找） | 0/6，偏 3 到几百行 | — |
| 现在，Chromium（内置浏览器） | **6/6** | 5–6 px |
| 现在，WebKit（不开窗口的 WKWebView） | **6/6** | 5–7 px |
| 现在，手机宽度（375） | 1/1 | 3 px |

  另外七页语料各点一处（加粗后面、嵌套项、续行、中文标点、公式后面、双链前面）7/7。

**图片**：粘贴、拖进图片，工具栏「插入图片」都走现有的上传，插 `![[/api/knowledge/images/N|名字]]`。真浏览器里把上传放慢 1.2 秒、期间在开头插了 10 个字：图片还是插在粘贴时的光标那里。
光标不在时显示成图（私有图片照旧带登录取，blob 地址）。拖进别的文件：CodeMirror 默认会把文件当文本读进来，现在拦下、提示「请选择 PNG、JPG、GIF 或 WebP 图片」、正文不变。

**表格**：光标不在表格里时用阅读模式同一个渲染画成表格，点一下进原文；在里面时原文用等宽字。阅读模式里点表格的一格，进编辑光标就在那一行原文里。

**代码块着色**：壳里加 `codeTokens`（和 `highlightCode` 同一个 `tokenizeCode`、同一套颜色），编辑时代码块里的关键字、注释、字符串有颜色。

**下划线**：工具栏和 ⌘U 加 / 去 `<u>…</u>`；光标不在时藏标签、显示下划线。

**review 时查出来、这轮一起修的**
- **勾选框**：新编辑器开着时，在阅读模式里点勾选框只是进了编辑，勾选丢了（原文没改）。现在阅读视图里第几个勾选框就改原文里第几个任务（`taskMarkerPositions`，代码块里的不算），只改那个方括号里的字；编辑器还没加载好时把框复原。
- **段落格式下拉**（标题、引用、代码块、列表、任务、分隔线）在新编辑器里还走 `document.execCommand` —— 那是给 contentEditable 的，会直接改 CodeMirror 的 DOM。改成改 Markdown（`setBlock`：换掉行首原来的符号、留着列表缩进，标题和引用顶格，代码块上下加围栏）。
- **⌘B / ⌘I / ⌘U**：旧编辑器是浏览器自己做的，新编辑器里按了没反应；接上，和工具栏同一个函数。桌面应用菜单里的 ⌘Z / ⇧⌘Z 走 `undo:` / `redo:`，CodeMirror 的撤销历史接 `beforeinput` 的 `historyUndo`，查过不用改。
- 新加的「上传期间编辑器换了」那道检查和原来的「编辑会话号没变」重复（新编辑器每次挂上都换会话号），删了，一个行为一道守卫。

**判据**：`wiki-cm-check.js` 从 8 条到 20 条（纯函数：下划线、表格、看得见的字、勾选框位置、段落格式、快捷键；用真的 `renderMarkdown` 画出来的标记量点击映射；接入：点正文落光标、勾选框、工具栏、图片插入跟着编辑走、换页不插、下拉）。
`WikiEditorSpikeTest` 多传一个 `zhiqu-api.js` 给它。`wiki-image-flow-check.js` 按 `insertWikiImage(file)` 这串字面量截源码，签名改了跟着改。
扰动 15 处全部见红（下划线收尾标记、下划线扫描不跳行内代码、表格扫描不跳代码块、加粗符号不藏、同样的一段不数第几次、列号不换回原文、任务位置不跳代码块、点正文只按坐标、勾选框不改原文、工具栏下划线没接、编辑器拿不到图片回调、图片插到上传完时的光标、有序编号不递增、下拉照旧 execCommand、标题不顶格）；
其中「标题不顶格」第一遍没红（样例里没有缩进的列表项换成标题），补了样例。
