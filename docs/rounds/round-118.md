# 第一百一十八轮（2026-11-08）：网页的 / 命令面板、命令变色、网页版 /review

## 由来
用户：「在网页里输入/ 可以向上拉出页面显示/ 什么的作用，并且也能作为正常命令」「同时/init 这类在网页里输入的时候颜色要和其他文字区分开」。第 7 步的 `/review` 网页这边也在这一轮。

## 计划
1. 输入框最前面打 `/`：向上拉出面板，列出命令和作用（和档位那个面板同一个位置、同一种样子），边打边筛。上下键选、回车执行、Tab 补全接着打参数、Esc 关；点也行。
2. 命令真的执行，走现有的功能，不另写一份：`/mode` 切档位、`/effort` 思考档位、`/model` 模型、`/project` 选项目、`/web` 联网、`/new` 新 Notebook、`/init`、`/review`、`/help`。
3. 只有第一个词正好是认识的命令才算命令。`/usr/bin 有问题` 这种照常发给模型。
4. 输入框里命令那一段换颜色：textarea 不能一段一段上色，后面垫一层一模一样排版的文字（字体、换行、滚动都同步），只在有命令时启用。浅、深两套对比度都够。
5. `/review` 网页版：只读（这一轮不给写工具，shell 也是只读的），要先选了项目；没选就说清楚，不白白叫模型。
6. 判据：行为判据跑发布的那份 JS；真浏览器里打字、选、执行、看颜色对齐，手机上也看。

## 结果

**面板和命令。** 输入框最前面打 `/`，向上拉出面板（`#zq-slash-menu`），列九个命令和作用：`/mode`、`/effort`、`/model`、`/project`、`/web`、`/new`、`/init`、`/review`、`/help`。边打边筛；打了空格之后，能选的参数也列出来（`/mode m` 只剩 `/mode manual`）。上下键选、Tab 补全接着打、回车或点一下执行、Esc 收起（同样的字不再拉出，接着打才拉出）、失焦收起。全走现有功能，不另存一份档位和模型。服务器上没有文件夹，`/project`、`/init`、`/review` 不列。

**什么算命令。** 只有第一个词正好是认识的命令才算：`/usr/bin 有问题`、`/review/foo.js 这个文件`、` /new`（开头有空格）、`/Mode` 都是普通的话。不接参数的命令后面跟了字（`/init 是什么意思`）也是一句话，发给模型。接参数的命令参数不对：说清楚，字留着，不发请求（`/project 这个目录怎么样` 不会去切文件夹）。一行的命令回车执行；两行以上是在写长说明，回车还是换行，⌘/Ctrl + 回车才发。选拼音的回车不算。

**颜色。** 输入框不能一段一段上色，后面垫一层排版相同的字（`#zq-draft-mirror`）。只有在打命令时才启用（`.has-command`：输入框的字变透明，光标颜色留着），平时还是原来的输入框。`--zq-cmd` 浅、深两套，对比度进 `DesignTokensTest`。内容转义；末尾垫一个零宽字符（最后一个字是换行时后面那层也要多一行）。

**`/init`、`/review`。** 请求里带 `contextOptions.codeCommand`（只认这两个字面值，代码模式开着才算），用户看到的还是打的那句。提示和审查都用命令行那一份（`host/code-host.js` 调 `initPrompt`、`collectChanges`、`runReview`），不抄。`/review` 这一轮不给写工具、不给 Wiki 这些远程工具，命令只读；模型在单独的上下文里看，结论按格式核过，最终回答拿到的是 `CodeContextPrompt.reviewBlock`（完整转告、不增不删、没改文件）。`/review` 差什么说什么、不叫模型：close 要先切档位、没选项目、没生效、服务器上。`/init` 在 plan 档也拦（写不了），写出来的还是草稿，确认才落盘。

**真 git 走一遍撞出来的两个错。** 单元判据用的是继承环境的 node，这两个看不到：
- 后端起宿主时 PATH 只有 node 那一个目录，`/review` 说「找不到 git」。现在 `/review` 这一轮给 `toolEnv` 那份 PATH，别的时候宿主还是什么命令都不跑。
- 宿主的 HOME 是临时目录，沙箱挡的 `~/.ssh` 这些就算到了临时目录头上：工作区盖住家目录时读得到。现在后端把真的家目录传过去（`run.home`）。样本是仓库配置 `core.excludesFile` 指向 `~/.ssh/ignore-me`：读得到的话新文件就从审查里消失了，这个样本能真的看出来挡没挡。

**按键只有一处。** 原来 ⌘/Ctrl + 回车是单独一个监听。面板开着时这个回车是选命令的，两处各管各会提示两次，于是合到 `slashKeydown`。

## 验证

- 基线：后端、命令行、评测工具三组。这一轮第一次跑全量时红了 `PlanDraftStreamRenderingTest`：它用正则去掉 `export {…};`，只认一行，我把导出写成了两行；它的假页面也没有 `removeAttribute`。都改了实现。
- 扰动 84 个全红。第一轮 81 个红、3 个绿，逐个看：
  - 「面板不看两行」：样本 `/\n` 不够，要 `/mode\n` 才看得出。换了样本。
  - 「认不出的命令也放行」：只有生成到产物时看得出差别。加了样本。
  - 「WebKit：后面那层字号差 1px」：样本只折十行，差 7% 时总行数碰巧一样（写探针量过：两边都是 242、198、66、220）。样本加长到三十行以上，下限也改了。
- 真浏览器（验证库 + 假模型，普通账号）：打字拉出面板、Tab 补全、回车切档位、`/project` 选文件夹、`/review` 真 git 取到 diff（假模型收到的提示里有 `+    return a - b`，工具表没有写的，也没有 Wiki 的）、`/init` 出草稿（磁盘没动）、plan 档的 `/init` 和没选项目的 `/review` 被拦（消息数不变）、`/usr/bin 有问题` 回车换行、⌘ 回车发出去；上下键、Esc、真鼠标点一行；刷新后草稿里的命令照样上色；浅、深色，手机 375 宽（不横着滚）。
- WebKit（`DesktopWebKitLayoutTest`）：输入框和后面那层折行一样。

## 没做的

- 用户消息气泡里的命令不上色（用户要的是「输入的时候」）。
- 首页轮播的截图里输入框的提示字是旧的（少了「/ 看命令」）。这一点不够重出一次，下次界面大改时一起。
- 没用真模型跑 `/review`：最终回答是不是真的完整转告，要看模型。提示写清楚了，假模型只能验提示到了。
