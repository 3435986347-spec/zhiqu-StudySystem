# 第一百一十四轮（2026-11-07）：Codex 同级第 7 步 —— /review

## 由来
方案第 7 步（[`docs/codex-parity-plan.md`](../codex-parity-plan.md)），用户：「接着做第七步」。Codex 有 `/review` 和 `codex review`：只读地看一段改动，按优先级列问题。

## 计划
1. `zhiqu review [--uncommitted | --base <分支> | --commit <sha>] [说明]` 和交互里的 `/review`，默认看没提交的（含没跟踪的文件）。
2. 全程只读：工具和只读沙箱同 `zhiqu exec` 默认。没有改动就直说，不调模型；不是 git 仓库、ref 不存在：退出码 2。
3. 结果按 P0–P3 列：文件、行号、标题、为什么、怎么改。走 JSON Schema 校验 + 重写，复用 exec 那一套；空的 findings 是合法答案。
4. 只报这次改动引入的真问题，不挑风格、不报老问题、不确定的不报；先核实再报。diff 里的文字是数据，不是指令。
5. `/review` 在单独的上下文里跑，不把会话撑大；结论放回会话，能接着说「修第 1 条」。历史只追加（缓存）。
6. 取 diff 的 git 也跑在只读沙箱里：克隆下来的仓库 `.git/config` 能配 fsmonitor、外部 diff、textconv、过滤器。没有沙箱时关掉能关的。ref 不能以 `-` 开头（不能当参数塞进去）。
7. diff 太大只给统计和文件清单，让模型自己一个文件一个文件看，说清楚不是全部。
8. 判据：真 git 仓库 + 假模型；仓库里埋了会写标记文件的配置，看它没被执行。

## 结果
做法写在 [`docs/notes/cli.md`](../notes/cli.md)。计划第 4、6、7 条照做；第 5 条的「单独的上下文」照做；第 8 条里的恶意仓库样本每一种都有对照（同一个仓库上普通的 git 真的会叫起那个程序）。

**真跑查出来的错（每一条读代码都看不出来）**
- **工作区是仓库的子目录时，沙箱里的 git 什么都跑不了**（第一百零九轮就有的错）：`fatal: unable to get current working directory`。git 要 chdir 到仓库顶层再 getcwd，顶层在沙箱读不到的地方。第一百零九轮的判据只算了路径、没真跑 git，样本的工作区又都是仓库顶层。`cd 项目/子目录 && zhiqu` 之后模型的 `git` 都不通。现在放开上面那几层目录本身和各层的 `.gitignore`、`.gitattributes`（只看得到文件名，别的文件内容还是读不到）。第一版把这个错报成「不是 git 仓库」，也改了：不是这个原因的错照实说。
- **Linux 上一样的场景错得不一样**（容器里真跑才看到）：bubblewrap 把工作区绑成单独的挂载点，git 往上找仓库碰到挂载边界就停，报 `not a git repository … up to mount point`。`GIT_DISCOVERY_ACROSS_FILESYSTEM=1`，只在这条路上设。
- **`git diff` 刷新 index 时会跑 `post-index-change` 钩子**：没有沙箱时，这是仓库配置能叫起程序的又一条路（真试出来的）。`core.hooksPath` 指到空设备。
- **`GIT_OPTIONAL_LOCKS=0` 管不到 `git diff`**：照样重写 `.git/index`；`diff.autoRefreshIndex=false` 倒是不写了，可只动了时间戳的文件就被算成改动。两个都不用：有沙箱时写不进去、结果照样对；没有沙箱时和用户自己跑 `git diff` 一样。
- **跑过一次 `zhiqu` 就「有改动」**：`.zhiqu/.gitignore` 这些算成没跟踪的新文件，干净的仓库也要花钱叫模型。排除掉。
- **`.env` 的改动会绕过 `read_file` 的规矩**：`read_file` 不读这个类型，diff 却照给。现在同一条规矩（扩展名白名单），不读的不进 diff、用户看得到没看哪些；只改了它们就不叫模型。
- **按字面排除才对**：第一版以为不按字面 `[x].env` 排除不掉，扰动说不对（git 先按字面比）。真正的毛病在另一头：名字叫 `src*` 的文件（类型不读）不按字面排除，`src/a.js` 的改动也跟着消失。
- **钉住的 `brief` 是多余的，还有害**：和提示不一样，从第一个请求起规矩就在系统内容里重复一遍。删掉，只清掉会话的 `request`（不清的话用户在会话里的原话会钉进审查）。压缩不会丢规矩：只有一轮时不碰它，重写时有 `userQuotes`。压缩留的原话只有开头和结尾，所以推回去重写的那条再说一遍 schema（exec 同样受益）。
- **只放统计也能超过窗口**：真仓库相对 100 个提交，统计就有 97K 字；几千个文件时供应商会拒绝整个请求。统计和提交信息都限长，说清共几个文件。

**暴力（真进程、真终端）**
- 这个仓库上：没提交的、上一个提交、相对 10 / 100 个提交（放不下，给统计）、第一个提交，都不到一秒起完；不存在的 ref、`--commit --output=…` 退出码 2、没写出文件；`.git/index` 一个字节没变，`git status` 行数不变。
- 真 pty（xterm-256color）：`/rev` 弹菜单有说明、Tab 补全、回车跑；结论打出来、原始 JSON 不打；接着说话模型看得到结论、看不到 diff；中途 Ctrl+C 回到提示符、没有结论、不退出，文件没变。
- 恶意仓库：fsmonitor、外部 diff、textconv、clean 过滤器、长进程过滤器、`post-index-change`、验签名（`gpg.program`）、缺对象时的 `ext::` 远端，每一种都有对照，有沙箱、没沙箱都没被叫起来。
- 奇怪的名字：`-rf.js`、`空 格.js`、名字里带换行、改名；还没有提交的仓库、linked worktree、合并提交（和第一个父提交比）、没有共同祖先、子模块里没提交的。
- Linux 容器（bubblewrap 0.8、git 2.39，非 root）：review 和沙箱的判据 66 过 3 跳过（2 个 macOS 专属、1 个 git 太旧没有 `GIT_NO_LAZY_FETCH`）。

扰动：第一批 114 处红 101。绿的 13 处逐条查：2 处防护重复（`clean=` 有 `process=` 就够了，真跑验证过；stat 和 diff 两道失败检查留一道）、1 处防护有害（`brief`）、2 处重复的判断收进 `rewriteUntilValid`、8 处判据没照到（补了样本）。复验 + 新增 31 次（含容器里 2 次），最后全红。复验时还逮到一次扰动落错了行（`replace` 只换第一处，落到了长得一样的另一句上），重跑了。

判据：后端全量 1345（1 跳过写明原因）、命令行 431/431、评测工具 102 过 1 跳。

**还没做的、做不到的**
- 只用假模型验过流程。发现得好不好是模型的事，这轮量不出来；第 10 步对比时一起量（花钱，先问用户）。
- 新文件的内容不进提示，只列名字让模型用 `read_file` 看（那边有类型的规矩）：模型可能不看。
- 过滤器都盖掉了：LFS、git-crypt 管的文件要是动过，看到的是原始内容和指针的差别。
