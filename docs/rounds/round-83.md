# 第八十三轮（2026-10-30）：知识 Wiki 像 Obsidian 那样 —— 编辑器一直在、打字就存、连按回车就换行、不卡不跳

## 由来
用户 2026-10-30：「我在测试知识wiki页面发现了很多问题：1.不能连续换行。2.鼠标点击和保存会很卡，并且也不能点击哪里就光标在哪里。
3.不能像obsidian那样只要输入了就自动保存。最大的问题就是很卡顿，不像obsidian那样子流畅，也不能连续点换行键，光标点击的时候也会卡，甚至还会出现页面上下跳动的问题。」

## 摸底（开工时，读代码）
- **两套东西来回换**：打开一页画的是阅读视图（`renderMarkdown` 的 HTML）；点正文 → `enterWikiCmEdit` 把阅读视图拆掉、挂上 CodeMirror，
  再按「点的那个字」量位置、`alignPos` 最多挪六次滚动去对位；点「保存」→ `saveWikiEdit` 存完 `paintWikiDoc` 把编辑器拆掉、重画阅读视图、再对位一次。
  每点一下、每存一次都是一次拆 + 建 + 量 + 挪：卡在这儿，跳也在这儿（对不准就是一跳）。
- **连按回车看不见换行**：第八十轮为了「编辑时的排版和阅读一样」（进出编辑不跳），`layoutLines` 让一串空行里只有第一行占高度，
  其余的、以及开头和结尾的空行都是 `.cm-zq-gap-0`（行高 0）。连按回车加的就是这种空行 —— 文字确实换了行，屏幕上光标不动。
- **没有自动保存**：只有底上的「保存 / 取消」；打的字先存进浏览器的草稿（第十五轮），要点保存才上服务器。
- 后端每存一次：`writeLog("page.update")` 记一条操作日志（log 页列最近 80 条）、重算双链、给 RAG 入一条作业（有去重键）。
  改成自动保存的话，log 页会被「更新知识页」刷满。

## 计划（照 Obsidian：编辑 = 实时预览一直开着，「只读」= 阅读视图）
1. **编辑器一直在**：打开一页就是实时预览的编辑器（没开只读时），不再「先阅读、点了才编辑」；点哪儿光标在哪儿交给 CodeMirror 自己。
   「只读」开着时是阅读视图（嵌入预览、附件、勾选框都在那儿），关掉回到编辑器。只有开关只读时才换一次。
2. **空行占一整行**：编辑器里每个空行都是一整行高，连按回车光标就往下走；块和块之间的间距放在块自己身上，不再靠压扁空行。
3. **自动保存**：打字停下约 1 秒存一次，一直在打时最多 5 秒存一次；切页、切标签、离开页面、窗口失焦时马上存。
   存的时候不重画、不动光标和滚动；头上一小行说「已保存 / 正在保存… / 没存上（原因）」。版本号照旧走乐观锁：
   别处改过（版本对不上）就停下自动保存、照实说，不覆盖。草稿照旧先存在浏览器里，断网时字不丢、连上了接着存。
   「保存 / 取消」那一条去掉；「删除本页」挪到工具栏。
4. **后端**：同一页连续的保存在操作日志里合成一条（同一个人、同一页、上一条也是 page.update、10 分钟内 → 改那一条），log 页不被刷满。
5. **量**：改前改后在内置浏览器（Chromium）和桌面应用（WebKit，真鼠标真键盘）里量：点一下到光标出现、按一次键到字出现、
   连按回车 20 次、保存时有没有跳、长页（几百段）里打字的延迟。热点照量出来的改。
6. 判据先红、扰动见红；真浏览器暴力（连按回车、狂点、打字中切页 / 断网 / 别处改过）；桌面应用里用 computer use 点一遍；全量；换缓存令牌。

## 中途用户又说的
- 「就是光标点的时候有时候还没反应，点不准，还卡顿」「还有光标停留的时候可以自动闪烁」「就像obsidian那样」「我把obsidian打开了，你自己对比差距有多大」。

## 结果

**改前量的（内置浏览器 Chromium，230 行的长页）**
- 点正文进编辑：48ms（拆阅读视图、挂编辑器、对位），偏 5px。
- 连按回车：第 1、2 次光标往下走（436 → 442），第 3、4 次行号在加、光标不动（442、442）—— 空行被压成 0 高。
- 点「保存」：118ms 拆编辑器、重画阅读视图，正在改的那段往上跳 33px（scrollTop 2294 → 2000）。
- 打一个字的同步部分 1.8ms —— 打字本身不慢，卡在「点一下换一次、存一次换一次」。
- 实时预览里点进去会变高的块：代码块（``` 两行从 13px 变整行）下面整块挪 +29px；表格（换回原文）−16px，光标还落在表格开头。

**真正的「点了没反应」**：编辑器自己画光标（drawSelection），默认是 1.2px 的**黑线**；我们只给系统光标设了颜色，系统光标被它藏着 ——
深色模式下光标画在深色底上，根本看不见（computer use 截图：点完 0.6 秒那一行上没有光标）。光标其实到了，看不见就像没反应、也不知道点在哪。

**改了什么**
- 编辑器一直开着（像 Obsidian）：打开一页就是实时预览的编辑器，不再「先阅读、点了才换」；「只读」= 排好版的阅读视图（嵌入、附件在那儿），关掉回到编辑器、字还在。
- 自动保存：打字停 1 秒存一次、一直打最多 5 秒一次；换页、关标签、开只读、焦点离开、页面藏到后台马上存。存的时候不重画、不动光标。
  一页同时只有一个保存在路上，回来以后接着存最新的；版本对不上（新的 412）停下、右下角说「别处改过」，给「用我的覆盖」（先问）/「载入别处的版本」；
  断网、服务器忙、回应丢了自己再试（回应丢了先原样重发那一份），业务上拒了的不自己重发；删空了不发。改名和自动保存排一队（原来各发各的会撞版本号）。
  「保存 / 取消」那一条去掉，「删除本页」挪到工具栏；状态浮在正文卡片右下角、不占排版（放在页名那一行的话，它一出一没，窄窗口里工具栏换行、正文整块挪）。
- 空行是一整行（不再压）；``` 两行一直整行高（碰到只露字）；表格按点的那一格放光标；表格 / 图片 / 公式换回原文以后，点的那一行留在鼠标底下；公式点得进去了。
- 光标：颜色跟正文走、1.5px、按 macOS 的节奏闪（1060ms）；选中的底色和全站一个；编辑器没焦点时不露 ## ** 这些符号（原来一打开页面第一行标题就露着 ##）；
  工具栏按下去不抢正文的焦点（不然点「加粗」的一瞬间符号藏一下又露出来）。
- ⌘W 在正文里也能关标签（原来「在编辑就什么快捷键都不管」，编辑器一直开着以后等于永远不管）。
- 后端：版本冲突单独回 code 412（`VersionConflictException`）；同一个人接着改同一页、10 分钟内的「更新知识页」日志合成一条（log 页不被自动保存刷满）。请求层把业务错误的 code 带出来。

**改后量的**
- 内置浏览器：真鼠标点「按」字 → 光标落在它旁边，滚动不动，按下到光标出现约 24ms；连按回车每次往下一行（434 → 461 → 489 → 517 → 545）；
  点代码块下面不挪（0px，光标离点的地方 1px）；点表格光标进那一行、离点的地方 2px，下面只挪 4px（原来 16）。
- 桌面应用（WKWebView，用这一轮的代码重打，真鼠标真键盘）：新页面直接写；连按 4 次回车字落在往下第 4 行；右下角「已保存」，
  后端这一页版本 0 → 1、操作日志里「更新知识页」只有一条；点「决」字插记号落在它前面；光标看得见、一闪一闪（隔半秒截三张：亮、灭、亮）；打开页面标题不露 ##。

**和 Obsidian 并排比（用户打开的 Obsidian，新建「知趣对比测试」，同样的标题 + 三段）**
- 一样了：连按回车一行一行往下走；点哪儿光标在哪儿；光标看得见、会闪；打开时不露符号、光标那一行才露；不用点保存。
- 还差的：
  1. 字和间距：Obsidian 正文约 16px、行高约 1.5、标题加粗；我们 15px、行高 1.85、标题 500（「字要细」是第四十一轮定的）—— 段距我们略大（约 50 对 45pt）。
  2. 表格：Obsidian 在表格里直接改格子；我们点进去换回原文（现在点哪一格进哪一格、点的那一行不挪，但整张表还是变成竖线和横线）。
  3. 自动配对括号 / Markdown 符号：Obsidian 默认打「(」出「()」、选中字打 * 包起来；我们打包的 CodeMirror 里没带这个模块（要重新打编辑器的包）。
  4. 保存：Obsidian 存在本机文件，没有网络；我们存在服务器上（1 秒），所以有「已保存 / 没存上 / 别处改过」的状态。
  5. Obsidian 页名就在正文顶上（inline title），我们页名在工具栏那一行。
