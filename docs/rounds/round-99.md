## 代码 review 出来的（三处，都改了、判据先红）
1. **宿主收到中断以后的迟到回音会停下**：模型调用中断了（超时），后端在半路的事件还会到 —— 原来当成「认不出的消息」发 fatal，fatal 抢在 result 前面，后端就丢了结论。
   现在收尾过的请求 ID 记下来，迟到的回音认得、丢掉；从没发过的 ID 照旧停。
2. **子进程不交结果就退，什么都没留下**：stderr 写在临时目录里、跟着一起删了（第九十六轮软链那回就是这样一声不响，查了半天）。现在没交回结果时把 stderr 末尾记进日志、轨迹里说清楚。
3. **「预期输出：ok」被当成「说跑过了」**：交活核对（第九十五轮）的说法判定把教用户怎么验的话也算进去了 —— 去掉「预期 / 应该 / 应当 / 会」开头的。
- 看过、没改的：草稿层只在读 / 改 / 搜里看草稿，列目录看不到新建的草稿（模型列一下目录会以为没建 —— 记一笔，没出过事，先不动）；
  执行器的子进程 HOME 现在是一个进程共用的空目录（跑过的仓库代码能往里写东西、影响之后的命令 —— 但能跑仓库代码就已经什么都能做了，EXEC 本来就不是沙箱）。
