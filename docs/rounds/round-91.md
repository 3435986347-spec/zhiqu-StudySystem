## 由来
用户 2026-10-31（第九十轮收口后）：「去掉核对，接着做下一版尺子，然后接着write_file 拆成两个工具、按缓存命中价记账、命令行和网页版两份 agent 合成一份。」
这一轮做前两件；后三件各一轮（第九十二到九十四轮），合成一份 agent 架构大，先出方案给用户定。

## 计划
1. 去掉第八十九轮的交活核对（`VERIFY_NUDGE`、`turnWrites`）：第九十轮用尺子量，正确率没有差别、每题多花一半到一倍 token。
   留着：温度 0（不花钱、DeepSeek 的建议）、提示词里那句收尾检查（不花钱）、「要推一句的那条先不当结论打出来」（清单没做完那一句照样用）。
2. 下一版尺子：第一版是单文件小题，这个模型 9/10 遍遍过，量不出东西；SWE-bench 上挂掉的是「在一堆文件里找到对的地方、照没写明的约定改」。
   新加 4 道多文件的题，题面只说现象，约定散在别的文件里：
   - inventory：一单多件、第二件不够时第一件不能已经扣掉（仓库里有 `store.transaction()`，进货就是这么写的）；报错要用项目自己的 `InsufficientStock`（接口层只认 `ShopError` 的子类）；
   - plugins：插件按 priority 执行 —— 「越小越先」只写在 README 里；`PluginError` 收进 `context['errors']`、别的异常往外抛；
   - user-cache：改了用户的邮箱以后，按旧邮箱查的缓存也要清（键要用 `Cache.key` 拼，大小写不敏感），别的用户的缓存不能清；
   - admin-routes（JS）：/admin 下要「登录 + 是管理员」，项目里有现成的 `requireRole`（没登录 401、角色不对 403、说法照项目里的），别的路由不受影响。
3. 对照组先验；用用户给的 key 拿现在这一版校准难度（每题 3 遍）：要有过有不过才量得出东西。

## 结果
- **交活核对去掉了**：`VERIFY_NUDGE`、`turnWrites` 拆掉；`pendingNudge` 只剩「清单没做完」那一句（要推的那条照样不先当结论打出来）。
  判据：原来测「推核对」的那条改成钉住「改过文件交活不再多推一次」（拿第九十轮的 agent.js 换回来跑：红）；测「结论只打一遍」的那条改用清单那一句（去掉不打结论的那个条件：红）；
  截断那条、评测工具里数请求次数的 4 条改回原来的数。命令行 269/269、评测工具 91 过 1 显式跳过。
- **尺子第二版**：新加 4 道多文件的题（inventory、plugins、user-cache、admin-routes），一共 14 道。对照组 15 条全过；
  对照组当场抓到两处出题的错：user-cache 的隐藏测试把参考答案自己在 `update` 里读库的两次也算进了「别的用户的缓存被清掉」（改成改完以后再数）；
  plugins 的隐藏测试原来要求没出错时 `context` 里没有 `errors` 这个键（README 没定，改成两种都认）。
