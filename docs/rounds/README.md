# 升级轮次的计划

用户 2026-09-28 的要求：一轮接一轮不停升级，**每一轮的计划都要保存**。每轮一个文件 `round-NN.md`，
开工时写下计划（要做什么、为什么、怎么验证），收口时补上结果（提交号、实测数字、扰动数），随那一轮一起提交。

从第十一轮起，每一轮都包含一段「暴力测试」：不同输入、不停刷新、没耐心的极端情况（连点、狂刷新、中途打断、超长 / 奇怪输入）
—— 用户 2026-09-28 的要求。

更早的轮次（第一到第八轮）没有单独的计划文件，它们的结论记在 `CLAUDE.md` 的「稳定性 / 可靠性 / 速度」各节里。
