# 第五十三轮（2026-10-09）：用户在桌面应用里看到的三处样子 —— 日历的日期出格、番茄钟下拉框撑出卡片、下拉框是原生的灰渐变

## 由来
用户 2026-10-09「继续」+ 三张截图（另一台 Mac 上的桌面应用）+ 一段命令行记录。截图里的问题分两轮：这一轮是样子（①②），下一轮是 AI 助手（③ 输出额度全用在思考上、④ 桌面应用里一问要等几分钟、命令行很快）。
用户拒了上一轮末尾那个问题（轮播截图要不要现在出、要不要推送）：不再问，轮播留到界面打磨第 9 步一起重出，不推送。

## 现在是什么样
1. **看板「本周」**：每一格是「周一」和日期并排（`.zq-day-head` 一行、`justify-content:space-between`），一格至少要 74px（左右留白 20 + 星期 24 + 间隔 4 + 日期 26）。
   桌面应用常用的窗口宽度（960–1200）里日历那张卡片只有 360 上下，一格 40px —— 日期被挤到格子外面，压在旁边一格上；今天那个黑圈压着下一天。我自己 1024 宽的截图里也出格了一点（数字压在格子边上），没看出来。
2. **番茄钟卡片**：「专注时长」「关联任务」两个下拉是一行内联的 `grid-template-columns:1fr 1fr` —— `1fr` 的最小宽度是内容的宽度，任务名长时下拉框按最长的选项撑开，撑出卡片。
3. **下拉框的样子**：样式表用的是 `appearance: base-select`（可定制的下拉框，只有 Chromium 认）—— Safari / WKWebView 不认，退回原生的灰渐变和上下箭头（桌面应用就是 WKWebView）。

## 计划
1. 日历：`.zq-week` 成为容器（`container-type: inline-size`），`@container (max-width: 560px)`：每一格星期在上、日期在下、居中，「N 项」藏起来（读屏照念），左右留白收窄 ——
   原来手机宽那段 `@media` 里的同样几条挪过来（手机上日历一样窄，一处写）。
2. 番茄钟：两个下拉放进 `.zq-pomo-fields`（`repeat(2, minmax(0,1fr))`），下拉框 `width:100%`。
3. 下拉框：`@supports not (appearance: base-select)` 里给 `.zq-select` 和 AI 助手的模型下拉 `appearance:none` + 自己画的小箭头（颜色用令牌），不认 base-select 的浏览器（Safari / 桌面应用）也是同一个样子。
4. **判据**：在真的 WebKit（WKWebView，检查程序不开窗口）里量：窄的日历一格里日期不出格、番茄钟的下拉框不出卡片、下拉框不是原生样子（`appearance: none`）；样式表的几条接线；扰动见红。
5. 内置浏览器（Chromium）里在 960 / 1100 / 1440 / 375 宽量一遍日期在不在格子里；截图（浅 / 深）；全量；桌面应用重新打包。

## 结果（2026-10-09）

照计划做完。先在 WebKit 里把用户看到的三样都复现出来（旧的样式表：日历并排、日期出格 24px；「关联任务」撑出卡片 331px；两个下拉都是原生的 `auto`），再改。

- **日历**：`.zq-week` 是容器（`container-type: inline-size`）。日历窄于 560 换竖排（星期在上、日期在下、居中，「N 项」藏起来，读屏照念 `aria-label`）；
  再窄于 260（320 宽的手机上日历不到 200）左右不留白、星期 10px、日期的圆 20px。原来手机那段 `@media` 里的五条挪进容器查询（手机上日历一样窄，一处写）。
  内置浏览器里把日历从 220 一路拉到 900（每 5px 量一次）：日期、星期、那排点都不出格子，560 上下切换一次。
- **番茄钟两栏**：内联的 `1fr 1fr` 换成 `.zq-pomo-fields`（`repeat(2, minmax(0,1fr))`）。先写了三条（格子 `min-width:0`、下拉 `width:100%`、`minmax`），
  在 WebKit 里一条一条拿掉量过：**每一条单独都够**（`1fr` + 随便哪一条都不出卡片，只剩 `1fr` 多出 347px）—— 留 `minmax(0,1fr)` 一条，别的删掉（一道防护替另一道挡着、照不出来，判据纪律第 6 条）。
- **下拉框**：`@supports not (appearance: base-select)` 里 `.zq-select` 和 AI 助手的模型下拉 `appearance:none` + 两段渐变拼的小箭头（颜色用令牌）。
- **新判据**：`DesktopWebKitLayoutTest` —— 检查程序在真的 WKWebView 里（不开窗口）载入发布的 `zhiqu-ui.css`，日历由 `week-markup.js` 真跑 `dashboard.js` 的 `renderWeek` 画出来，
  番茄钟卡片从 `dashboard.html` 原样截出来，量：322 / 802 / 200 三种宽的日历（竖排 / 并排 / 出不出格子）、长任务名时下拉框出不出卡片、两个下拉的 `appearance`。
  对着上一轮的样式表跑是红的；扰动 9 个红：没有竖排的容器查询、日历不是容器、两栏又是 `1fr`、看板又写内联的 `1fr`、WebKit 里还是原生下拉、宽的日期往外推、模型下拉没算进去、最窄那一档没有。
  「竖排了留白还宽」是绿的 —— 竖排时日期居中，左右留白再宽也只是压在留白里、出不了格子的边框；那条留白不是防护，只是好看，记下来不算。
- `MobileLayoutTest` 内联网格的下限跟着降（任务页的表头、番茄钟的两栏挪进了类）；`DesktopPageViewTest.run` 改成包内可见，新判据借它跑程序。

**截图**（发给用户）：1000 宽浅色（和用户那张差不多的宽度）、1100 宽深色。WebKit 那边没法截图（检查程序不开窗口），是量出来的。

**验**：全量 1022 / 0 / 0 / 0（开着 Docker）；桌面应用重新打包。用户那台 Mac 上的应用要换成这次打的包，三处才看得到（环顶上那个点第五十轮就修了，用户截图里还有，说明那台的应用是第五十轮之前的）。
