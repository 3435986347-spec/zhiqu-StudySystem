# 第二十三轮（2026-10-03）：一个新用户走一遍主流程

## 由来
用户 2026-10-03 让我「锐评一下现在有的东西」，我说最大的问题是**优先级倒挂**：二十二轮都在加固极端情况（UTC+14、五万个文件、300 个 MCP 工具、Zalgo），
而「新建任务只能填标题」「参考计划写死 4 个」「桌面版选不了文件」直到用户 10 月 1 日自己去点才发现 —— 这些轮次测的是我想得到的极端，不是学生每天做的事。
建议的第一步是「停下加固，用新账号走一遍主流程」。用户：「按你的建议顺序做，先走一遍主流程」。

走到一半用户补充了定位：「不只是学生产品了，更多是一个办公软件，AI 助手的功能」，并让我把建议写成方案（`docs/product-plan.md`，这一轮是其中第 1 步）。
所以主流程分两条，**A 线（AI 助手）在前**。

这一轮**不是暴力测试**，是反过来：只做一个普通用户第一次用会做的事，一步一步照屏幕上写的走，不看代码、不调接口、不用开发者知识绕过去。
卡住的地方、看不懂的地方、做完了却不知道成没成的地方，都算问题。

## 计划（开工时）

两条线用同一个新账号，注册（B 线第 1 步）放在最前面做。

### A 线：AI 助手（真浏览器，新账号，只用界面）
1. 第一次进 AI 助手：有没有能用的模型；没有时页面说了什么、知不知道去哪配。
2. 配一个模型（本机的假模型，照「模型设置」里写的填），测试连接。
3. 新建 Notebook、上传一份资料（PDF / Markdown），就资料提问 —— 回答是不是用了这份资料、引用点不点得开。
4. 让它出一个工作计划 → 确认草稿（改一项再确认）→ 任务出现在任务页、看板上，日期对不对。
5. 让它把一段结论写进知识 Wiki → 确认 → Wiki 里看得到。

### B 线：任务与提醒（真浏览器，同一个账号，只用界面）
1. **注册、第一次登录**：首页说了什么、注册表单、登录之后落在哪、第一眼看到的看板（空账号的样子：有没有设计稿的残留、知不知道下一步做什么）。
2. **建一个带截止时间的任务**：从学生会找的地方找「新建」（看板上、任务页）；建好之后它出现在哪（任务列表、看板的今天 / 本周 / 四象限 / DDL）。
3. **手机上收到提醒**：学生怎么知道提醒发到哪、要先配什么；没配的时候设了提醒会怎样（到点时页面上、任务上能不能看出来没发出去）；
   配置渠道那一页照着说明能不能配起来、「测试发送」说了什么。
   真的推到手机上要用户自己的 PushPlus / 企业微信 / QQ 凭据，我没有 —— 到点前后服务端做了什么（库里的状态、失败原因）我看得到，最后「手机响没响」请用户自己验。
4. **番茄钟**：真的跑一个（25 分钟，不改时钟、不注入假时间），中途切到别的标签页；到点之后看板上的「今日」、统计页有没有算上。
5. **看统计**：完成任务、跑完番茄钟之后，统计页、成就页上的数对不对、空账号时什么样。

顺路看到的（例行计划打卡、个人中心）也记下来，但主线是上面五步。

### 修
照出来的按「一个用户会不会因此用不下去」排先后，能修的这一轮修；需要用户拿主意的（比如要不要做浏览器内的提醒）写清楚取舍再问。判据先红、扰动见红。
