# 第十九轮（2026-09-28）：暴力测试 —— 模型那一侧不配合

## 由来
前面几轮的极端都在「我们这一侧」：用户的输入、用户的耐心、用户的数据量、本地文件。还没测的是**另一头**：模型供应商。
它是这个产品里最不可控的依赖 —— key 填错、欠费、限流、502、接上了不说话、说到一半断、回一段不是 JSON 的东西、
一个字都不回、回一本书、工具调用参数是坏的。开发时连的都是好好的模型（或者脚本化的假模型只演好的那一面），
所以这些情况下用户看到什么、库里留下什么，从来没人看过。

## 计划（开工时）
用一个可脚本化的假供应商（本机 HTTP，按请求序号演不同的坏法），网页 AI 助手、命令行网关（`/api/harness/**`）、
命令行本身各走一遍。每一种坏法都看四件事：

1. **用户看到什么**：一句能看懂、知道下一步做什么的话（「API Key 不对，去模型设置里改」），不是供应商的原始 JSON、
   不是 `I/O error on POST request for …`、不是一直转圈。
2. **库里留下什么**：没有停在 STREAMING 的消息、没有停在 RUNNING 的执行记录；已经收到的半截回答怎么处理要说清楚。
3. **多久才告诉用户**：接上了不说话、说到一半不动了 —— 等多久才放弃，这个时间合不合理。
4. **有没有漏东西**：供应商的报错里可能带着请求头 / key 的片段；系统模型（管理员配的 key）的报错回给普通用户时尤其不能带。
   以及这些「供应商的问题」算不算我们的运行问题（每次都记一条会把后台刷屏）。

### 坏法清单
- HTTP：401（key 错）、403、404（模型名 / 地址错）、429（限流，带 / 不带 Retry-After）、500、502 回一页 HTML、连接被拒、DNS 解析不了。
- 流：接上了一个字都不回；说了几个字就不动了；说到一半断开（没有 `[DONE]`）；回的是 HTML 不是 SSE；
  某一块 JSON 坏了；`[DONE]` 之前什么都没有（空回答）；回一本书（几 MB）；`finish_reason=length`；每 10 秒挤一个字。
- 工具调用：参数不是合法 JSON；调一个不存在的工具；同一个调用反复来。

### 顺带
- 例行计划列表里周期显示的是原始的 `DAILY`（第十七轮看到的）。

### 暴力测试（每轮都做）
- 就是这一轮本身。另加：坏模型之下连发、刷新，库里状态照样收干净。

### 修
照出来的都修，数量不设上限；判据先红、扰动见红。

## 结果

一个按脚本演坏法的假供应商（本机 HTTP，真 SSE、真库），网页 AI 助手演了 18 种，命令行网关演了其中会出现在它那一侧的 6 种。

### 网页 AI 助手：用户看到的那句话

| 坏法 | 改之前 | 改之后 |
|---|---|---|
| key 错（401，报错里回显了 key） | 「AI 接口调用失败：AI 接口调用失败」—— 原因整个丢了 | 「API Key 不对或已经失效（HTTP 401）：去「模型设置」里检查这个模型的 Key」 |
| 欠费（402）/ 模型名错（404） | 供应商的英文原文 | 先说是什么问题、该去改哪儿，原文附在后面 |
| 限流（429 + Retry-After: 20） | 「Rate limit reached for requests」 | 「模型供应商限流了（HTTP 429），20 秒之后再试」 |
| 502 回一整页 nginx | 整页 HTML 原样给用户 | 「模型服务暂时出错了（HTTP 502），稍后再试」 |
| 地址填成官网（200 回网页） | 一条「完成」的空白回答 | 「接口返回的不是模型的流式回答（返回的是 text/html）：「接口地址」可能填错了」 |
| 空回答（直接 [DONE]） | 一条「完成」的空白回答 | 「模型这次什么都没说（返回了空回答）」 |
| 说到一半断开（没有 [DONE]） | 半截回答标成「完成」，一个字不说 | 半截留着，底下说「模型的回答没说完，连接就断了」 |
| 流里一块 JSON 坏了 | 接口地址 + Jackson 的解析位置给了用户；已出来的正文清空 | 「模型返回的数据格式不对…」，已出来的留着 |
| 途中来了 error 事件 | 已出来的正文清空 | 已出来的留着，「模型在回答途中报错了：overloaded」 |
| 写到输出上限（finish_reason=length） | 停在半句话，一个字不说 | 回答底下「写到了单次输出的上限…可以说「继续」」，刷新之后还在 |
| 回一本书（300 万字） | 300 万字全推给浏览器，库里悄悄只存 20 万 | 收到 20 万字就停，推给浏览器的和存下的一样多，说只保留了前面 |
| 说几个字就不动了 / 接上了不说话 | 60 秒后 `I/O error on POST request for "http://…": Read timed out`，已出来的清空 | 60 秒后「模型服务 60 秒没有任何输出，已经放弃」，已出来的留着；等的时候气泡里说出已等几秒 |
| 供应商进程在回答途中崩了（连接硬断） | 已出来的清空，`I/O error on POST request for "http://…": Premature EOF` | 已出来的留着，「和模型服务的连接中途断开了，回答没说完」 |
| 连不上 | `I/O error on POST request for "http://127.0.0.1:…": Connection refused` | 「连不上模型服务（连接被拒绝）：检查「接口地址」…」 |

每一种都是：没有停在「正在生成」的消息、没有停在 RUNNING 的执行记录、不记运行问题（供应商的毛病不是我们的 bug）—— 这三件原来就是对的。

### 查出来的
- **失败时把已经出来的正文清空**：`failAssistantMessage` 用 `updateById` 写回了创建时的空正文，覆盖了阶段性落库的那一截。
- **页面有半截就不说失败原因**；**刷新之后失败的回答是空白气泡** —— 列表接口一直带着 `errorMessage`，页面从来不读。
- **流读完就算说完了**：断在半路、被截断、被审核拦下、回的根本不是 SSE，全都标成「完成」。
- **401 的原因读不到**：流式 POST 遇到 401 时 JDK 拿不到响应体，只剩状态码 —— 而状态码原来不进那句话。
- 消息列表的行有两份一模一样的构造，新加的字段只进了一边（判据红出来的）。
- 命令行网关：流里一块坏 JSON 被说成「连不上模型服务：I/O error on POST request for http://…」还标成可重试；空回答发一个空的 done。
- 顺带：例行计划的周期显示 `DAILY` / `WEEKLY`（第十七轮看到的）。

- **真浏览器里撞出来的一种**：假供应商用 `com.sun.net.httpserver` 写的时候，关连接总会把分块收好尾 —— 真的进程崩了、代理掐了连接，
  JDK 报的是 `Premature EOF`，页面上是兜底的「和模型服务通信失败」。补了映射和一个用原始套接字硬断的判据。

### 浏览器里走了一遍
临时库 zhiqu_verify、18080，一个本机的坏模型（第 1 次说三句就断、第 2 次写到输出上限、第 3 次 401 回显 key）：
三条回答各自带着那句话（红色的失败原因 / 琥珀色的不完整说明），key 没出现在页面上；重启服务、刷新页面之后三句话都还在。
例行计划列表：「每天 · 30 分钟」「每周一、三 · 20 分钟」。控制台没有错误。

### 暴力测试
8 个回答同时进行、模型每个都说到一半断开、一半的人读到第一个字就刷新：8 条都收成「失败 + 半截还在」，没有停在「正在生成」的，没有运行问题。

### 扰动
27 处，全红。一处一开始是弱判据：遮 key 的判据用的是 `sk-` 形状的 key，「遮配置里那一把」和「遮长得像 key 的」两道互相替对方挡着，
删掉哪一道都不红 —— 加了一把没有前缀的 key 之后各自能红。另一处是扰动脚本自己抠错了原文（`'⚠ '` 在源码里是一个更长的字面量的一部分），
改过之后红。
