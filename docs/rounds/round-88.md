# 第八十八轮（2026-10-31）：coding agent —— 少花轮数：一轮发多个调用、读文件读成段、快到轮数上限时收尾、工作区里的绝对路径照收

## 由来
用户 2026-10-31：「继续，做下一轮的 coding agent」。第八十七轮重跑之后，工具那一层的错基本没了（十题里只剩 3 次拒绝），分数卡在模型自己的判断上；
但轮数和 token 还有明显的浪费，而轮数直接决定能不能做完（60 轮上限）、每一轮又要把整段对话重发一遍（输入 token 随轮数近似平方涨）。

## 摸底（第八十七轮重跑的十段记录）
- **一轮一个调用**：234 次带工具的回复里 209 次只发 1 个调用（2 个 23 次、3 个 2 次）—— 互相不依赖的读 / 搜也一轮一个。
- **读文件一小段一小段地挪**：83 次 read_file 里 55 次只读 ≤ 80 行；sympy-23950 把 piecewise.py 从 170 行起分 6 次往下读（170–210、209–249、248–308、308–353…），boolalg.py 也是。
  工具说明写的是「一次最多给 2000 行」，提示词里没说要读成段、也没说一轮可以发几个。sympy-23950 用满 60 轮，63 次调用里读 / 搜 / 列 39 次。
- **轮数用完时没有结论**：sympy-23950 到 60 轮停下时最后的回答是空的（命令行只说「已经连续调用了 60 轮工具」），用户不知道做到哪了；到上限之前也没有任何提醒。
- **工作区自己的绝对路径被拒**：3 次 `cwd: "/work/base_repo"`（就是工作区根）被当成「超出工作区」拒掉，每次白花一轮。（第六十九轮那几次是往 `/tmp` 写，真在外面，照旧拒。）
- 剩下没解决的两题是修法不对（pytest-10356 多个基类的 mark 排序反了，pytest-5840 的问题只在 Windows 上出现、没法复现），不是工具的事，这一轮不碰。

## 计划
1. 提示词：互相不依赖的读 / 搜 / 列一轮里一起发；读文件读成段（不知道要哪几行就整份读，最多 2000 行），不要几十行几十行地往下挪。
2. 命令行自己盯着：同一个文件接着上一次读到的地方往下读（offset 正好接上），在结果后面附一句「直接读大一点」（和已有的「连续看了 8 次还没动手」一样，只附一句、不拦）。
3. 快到轮数上限（剩 3 轮）时在工具结果后面附一句：收尾 —— 把改到一半的改完、验证一次、用几句话说做到哪了、还差什么。
4. 命令行的路径参数（文件、目录、`cwd`）收工作区里面的绝对路径：落在工作区根之内的换成相对路径再交给原来的检查；外面的照旧拒。服务器端和一致性用例不动。
5. 判据（假模型的进程内测试）先红；用户给的 key 在验证库里拿真模型对比改前改后：同一个要读好几个文件的问题，各跑两遍，比轮数、一轮几个调用、输入 token。
6. 要不要再花钱用同样十题重跑看分数，问用户。

## 结果
- 提示词（`prompt.js`「一次做对」）加两条：互相不依赖的读、搜、列目录放在同一次回复里一起发（每多一轮整段对话都要重发一遍）；读文件读成段（不知道要哪几行就整份读，知道大概位置也一次读上百行）。
- 命令行盯着（`agent.js`，和「连续看了 8 次」一样只在工具结果后面附一句、不拦）：
  同一个文件接着上一次读到的地方往下读（offset 和上一次的结尾差 5 行以内）→「你在接着上一次往下读 X（第 N 行起）。直接读大一点…」，一个文件一轮对话只提醒一次；
  再过 3 轮到上限 →「开始收尾：改到一半的先改完、跑一次验证，然后用几句话说做到哪了、还差什么」，只附在那一轮最后一个调用上，上限不到 10 轮的不附。
- 路径（`local.js` 的 `inWorkspace`）：读 / 写 / 删 / 列目录 / 搜的 `path` 和 `run_command` 的 `cwd`，落在工作区里面的绝对路径换成相对路径再交给原来的检查（给的写法和解析过软链的写法都认）；
  外面的、前缀相同的兄弟目录、软链跳出去的照旧拒，报错里写的是模型给的那条原路径。服务器端的工作区和一致性用例不动。
- 判据：quiet-thinking 3 条（读成段的提醒、收尾提醒、提示词）、local-tools 1 条；扰动 12 + 2 处全红
  （第一遍三处绿：「只认解析过的根」—— 样本的根本来就是解析过的，补了经软链给的根；「工作区根本身不认」—— 空串往下本来就当根，那一句是多余的，删了；
