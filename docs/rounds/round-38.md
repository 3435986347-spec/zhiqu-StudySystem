# 第三十八轮（2026-10-05）：CLAUDE.md 瘦身（方案第 5 步）

## 由来
`docs/product-plan.md` 第 5 步：`CLAUDE.md` 1529 行，每次会话整份读进上下文，成了日记。
方案定的做法：压到两百行以内，只留规矩（怎么跑、怎么测、不能碰的地方、几条踩过就会再踩的坑），每轮的经过只留一行链接到 `docs/rounds/`。
验收：行数 ≤ 200；删掉的内容在 `docs/` 里找得到。

## 计划（开工时）

1. **原文一字不改地挪走，不删**。按标题切，每一节整节挪到一个地方：
   - 第二到第八轮（「稳定性 / 可靠性 / 速度」各节，当时没有单独的计划文件）→ 新建 `docs/rounds/round-02.md` … `round-08.md`；
   - 第九到第二十二轮的那几节 → 接在各自的 `round-NN.md` 后面（「收口时记在 CLAUDE.md 里的要点」）；
   - 其余各节按主题进 `docs/notes/`：开发环境（概述、命令、iCloud 那段历史）、测试（判据的纪律和那些故事）、后端（包、启动期密钥守卫、权限、登录流程、RAG）、
     配置、前端、AI 助手（含拆 `AiServiceImpl` 的经过）、知识 Wiki 与参考计划、代码工作区（含限额边界）、命令行（npm 版、Java 版、服务端网关）、桌面应用。
2. **新写一份 `CLAUDE.md`**（≤ 200 行）：这是什么、怎么跑、怎么测（含判据的纪律，压成几条）、进行中的计划、不能碰 / 不能绕的地方、前端的规矩（缓存令牌、页面模块）、
   踩过就会再踩的坑、各部分的说明在哪、每一轮一行。

   `docs/rounds/` 下每一轮在 `CLAUDE.md` 和 `docs/rounds/README.md` 里都有一行。各自扰动见红。
5. 代码注释里指着 `CLAUDE.md` 某一节的（「见 CLAUDE.md 第十轮」「CLAUDE.md『宁可启动就炸』那一段」）改指新的位置。

这一轮不动产品代码，没有暴力测试那一段（不改页面、不改接口；全量照跑）。
