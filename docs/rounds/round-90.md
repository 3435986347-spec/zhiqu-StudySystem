# 第九十轮（2026-10-31）：尺子 —— 本机能跑的小题、每题跑几遍；用它量第八十九轮

## 由来
第八十九轮锐评的第一条建议：「先把尺子做好」。第八十八轮拿两遍、一个问题下了「轮数减半」的结论，评测十题完全没复现；十题 SWE-bench 一题一遍，6/10 和 4/10 的差在随机翻转的范围里，量不出改动有没有用。
用户 2026-10-31：「先做尺子，用那个key量第八十九轮」。

## 计划
1. `tools/benchmarks/ruler/`：6 道小题（5 道 Python、1 道 JS），每题一个带毛病的小仓库 + 一段照真实 issue 写的问题（带例子和边界）+ 模型看不到的隐藏测试 + 参考答案。
   专门设的坑：漏边界（空的、首尾相接、负数、不认识的单位、全是标点）、改坏调用方传进来的数据、要照仓库现成的约定抛自己定义的错误类型。
2. 对照组先验（`ruler.test.mjs`，不调模型）：原始代码过不了隐藏测试、参考答案过得了、公开测试两边都过、仓库里看不到隐藏测试。对照组不死，尺子不作数。
3. 跑法：每题跑几遍（一遍一遍轮着跑，各题摊开网关那一侧的波动），记过没过、轮数、输入 token、核对推了几次。
4. 量第八十九轮：用户给的 key（验证库模型 ID 23），两版各跑 3 遍 × 6 题 —— 第八十八轮那版（d3cce0f 的命令行 + 网关不设温度）和第八十九轮那版（现在的命令行 + 网关温度 0）。
   两个网关各起一个实例（18080 温度 0、18081 留空），同一个库、同一个账号、同一个模型。
5. 用户 2026-10-31（尺子在跑时）：「跑完写对比、提交推送，还有其余的也一并修复」—— 锐评里其余能在这一轮做掉的：终端里命令输出只给尾巴、子进程 HOME 的口子、桌面后端不写日志、网页 code agent 跟上温度。

## 结果

### 尺子（`tools/benchmarks/ruler/`）
- 10 道题（第一版 6 道 + 第二版加的 4 道难题：memo-alias 缓存的结果被调用方改了、mro-order 多继承时照现有约定定顺序、tag-order 去重不能打乱另一个调用方依赖的顺序、week-range 周日 / 跨年 / 闰年）。
- 对照组（`tools/benchmarks/ruler.test.mjs`，不调模型）：11 条全过；扰动 3 处（参考答案错一个字、隐藏测试什么都不查、隐藏测试漏进仓库）全红。
- 公平性：mro-order 原来要求多个父类之间的某一种顺序，那个顺序现有代码和题面都没定 —— 改成只查有依据的（父类在前、自己在后、去重、单继承不变）；
  deep-merge 的隐藏测试查「结果不能和传进来的 dict 共用嵌套对象」，题面原来没写 —— 两版 6 遍全挂在这一条上，补进题面以后再量（下面第三轮）。

### 量第八十九轮（用户给的 key，验证库模型 ID 23；r88 = d3cce0f 的命令行 + 网关不设温度（18081）；r89 = 现在的命令行 + 网关温度 0（18080）；先用记录请求的假模型核过：18080 发 `temperature: 0.0`、18081 不发）

| 轮次 | 题 | r88 过 / 遍 | r89 过 / 遍 | r88 平均轮数 / 输入 token | r89 平均轮数 / 输入 token |
|---|---|---|---|---|---|
| 第一轮 | 原来 6 道 × 3 遍 | 16/18 | 16/18 | 4.4 / 19,659 | 5.9 / 30,506 |
| 第二轮 | deep-merge + 新 4 道 × 3 遍 | 12/15 | 12/15 | 3.9 / 16,219 | 5.7 / 29,130 |
| 第三轮 | deep-merge（题面补清楚）× 3 遍 | 2/3 | 1/3 | 3.0 / 13,301 | 6.3 / 40,319 |

- **两版的正确率没有差别**：10 道题里 9 道两版都是遍遍过，唯一拉得开的 deep-merge 两版都时对时错。核对一共推了 35 次，没有救回一题；
  第三轮 r89 那份代码的说明里写着「返回的结果也不与它们共用嵌套对象」，代码却直接把 override 的值放进结果 —— 核对问「都验证过了吗」，模型说是，没写测试去试。
- **温度 0 没让结果稳下来**：r89（温度 0）在 deep-merge 上照样 ✓✗✗。DeepSeek 在 0 温度下也不是每次一样。
- **代价是实的**：r89 每题多 1.5–3 轮、输入 token 多 55–200%（多的主要是核对那一轮）。
- 尺子本身的问题：单文件的小题对这个模型太容易（9/10 遍遍过），量不出改动；SWE-bench 上真正挂掉的是「在大仓库里找到对的地方、理解没写明的约定」，小题复现不了。
  下一版尺子要有多文件、要读现有代码才知道约定的题。

### 其余的修复
- **终端只给尾巴**（`agent.js` 的 `shownOutput`）：命令输出多于 9 行时给开头 3 行 + 结尾 5 行，中间写「…（中间省掉 N 行）」；原来只给最后 8 行、也不说前面还有。
- **子进程的 HOME**（`exec.js` 的 `childHome`）：从工作区换成这个进程自己的空目录（mkdtemp，0700）。这台机器上试出来：HOME 是工作区时，仓库里带一个
  `Library/Python/3.9/lib/python/site-packages/sitecustomize.py`（Linux 上是 `.local/lib/pythonX.Y/site-packages`），任何一句 `python3`（哪怕 `python3 -c "print(1)"`）都会先执行它；换成独立的 HOME 就没有。
  git 那一层（`GIT_CONFIG_GLOBAL` 指到空设备）留着。
- **桌面后端写日志**（`application-desktop.yml`）：`~/.zhiqu/logs/backend.log`，10MB 滚动、留 5 份。用桌面 profile 真起了一次（`user.home` 指到临时目录、库指到验证库）：日志写出来了。
- **网页 code agent 跟上温度**：`ToolTurnLimits` 多一个可空的温度（`withTemperature`），code agent 干活的轮带 `app.ai.harness-temperature`（默认 0，setter 注入，留空跟全局）；
  工具轮（OpenAI 兼容和 Anthropic）不认就去掉重试一次；「不认 temperature」的判断收到 `ModelProviderClient.rejectsTemperature` 一处，命令行网关也用它。
- 判据：命令行 2 条（头尾、HOME + sitecustomize）+ 原来一条改断言；后端 4 条（工具轮带温度、两种供应商不认就去掉、code agent 带温度 / 留空不带、桌面日志）；
  扰动 命令行 4 处、后端 6 处全红。
- **一个失误**：第八十九轮提交时只跑了后端全量和命令行，没跑评测工具那一组 —— 交活核对多一次请求，评测工具里 4 条数请求次数的判据红着推上去了。这一轮改了（照实加一次、写明是核对那一次）。
  以后评测工具的判据和另两组一样，提交前必跑。

## 要用户定
- **交活核对留不留**：尺子上没量出好处，每题多花一半到一倍的 token。我的建议是去掉（按锐评里自己说的：量不出作用就删），温度 0 留着（不花钱，DeepSeek 的建议）。
