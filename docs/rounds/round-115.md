# 第一百一十五轮（2026-11-07）：代码功能开放给所有用户，工作区和档位分账号

## 由来
用户：「把代码功能开放给所有用户，不只有管理员可以用」「工作区和档位要分账号」。改掉 `CLAUDE.md` 里「工作区的接口和 code agent 读工作区都要管理员」这条（用户明确要的）。服务器上的网页版下一轮做（生成文件到 artifact，命令走 WSL2 + bubblewrap），这一轮只动本机的后端（桌面应用、本机跑的网页）。

## 计划
1. 先在真后端上证实：只去掉管理员校验的话，一个陌生的网页（DNS 重绑定，`Host` 是它自己的域名）能不能注册账号、开档位、读文件。照证实的结果定防线。
2. 工作区接口和 code agent 去掉管理员校验：登录的用户都能用。档位默认关、回环地址、生产 profile 拒绝都不动。
3. 工作区接口只认本机来的请求：连接来自回环地址、`Host` 是 `localhost` / `127.x` / `[::1]`、没有代理转发头。陌生网页和经过反向代理的请求调不了档位、读不了文件。
4. 档位和文件夹分账号：每个账号在这台电脑上存一份（还放在 `~/.zhiqu`，路径只在这台电脑上有意义，不进数据库）。账号之间读不到对方选的文件夹，切档位互不影响，改动的落盘用自己的文件夹。原来那份不分账号的谁也不继承（默认关）。
5. 判据：普通账号真能用；两个账号互不影响；`Host` 不对、带转发头一律拒绝，管理员也一样。真浏览器：普通账号点档位、选文件夹、假模型跑一遍 shell。

## 结果
防线和取舍写在 [`docs/notes/code-workspace.md`](../notes/code-workspace.md)。计划照做。

**先证实的**：真后端（`zhiqu_verify`）上发 `Host: evil.example:18082`，注册、登录都成功，只有管理员校验挡着。只删校验的话，一个陌生网页能开档位、列目录、读文件。

**分账号比原计划多带来一道防线**：新账号默认关、开档位只认本机的请求，所以陌生网页注册的账号走不到 code agent。例外是配置给了默认档位（本机开发才这么配）：加了 `WorkspaceDefaultLocalFilter`，那时整个 `/api/**` 只接本机的请求。

**顺手关掉的**：生产 profile 原来只拒绝执行，配了档位还能读服务器的磁盘（靠管理员校验挡着）。现在一律关（`WorkspaceAccess.production`），服务器上连本机的请求也不给。

**真跑过的**（默认配置的后端，档位靠账号自己开）
| 谁 | 做什么 | 结果 |
|---|---|---|
| 普通账号 A（`USER`） | 真浏览器：选文件夹显示 rootA、auto 档，发消息，假模型叫 shell 写文件 | `proof.txt` 落在 rootA，B 的文件夹没动 |
| 普通账号 B（`USER`），同一个浏览器换账号 | 显示 rootB、plan 档，同一条命令 | 工具只有 `read_file`、`shell`；`Operation not permitted`，文件夹没变 |
