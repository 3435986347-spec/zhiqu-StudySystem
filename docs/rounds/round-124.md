# 第一百二十四轮（2026-11-08）：RAG 第一次建好就自动启用

## 由来
第一百二十二轮装好旁路之后，线上用户之前点过两次的「重建」都做完了（#1、#2 都是 READY），但一个都没启用 —— 检索照旧退回关键词，要管理员在后台点「启用」。用户要的是「默认启动」：新装的服务器、第一次建好的索引，不该还要人去点一下才用上。

## 计划
1. 后台处理完一批索引作业之后：一个启用的都没有、又有建好的（READY）→ 自动启用最新建好的那一个。走和管理员点「启用」同一条路（锁住所有代次、核对覆盖面、发布）。
2. 已经有在用的就不自动换：换不换由管理员决定（蓝绿切换本来就是要人看过的）。
3. 几个后端连同一个库：在锁里再看一次「是不是一个启用的都没有」，两边同时撞上也只启用一个。
4. 判据：真库 + 真 worker：没有在用的 → 自动启用最新的 READY；已经有在用的 → 新建好的照旧 READY；多个 READY 时启用最新的。

## 做的时候改了计划
线上查了一下：投影表（`rag_indexable_unit`）是空的，可用户已经有 6 个 Wiki 页 —— 写的时候 RAG 关着，没进投影表。那两个代次是空索引（0 / 0），手动点「启用」也会被拒（`validateCurrentReadyCoverage`：投影表空、库里有原料 → 要先全量对账）。所以光「建好了就启用」不够，得把整条路接起来。

## 结果

- `RagAdminService.bootstrapStep(sidecarReady)`：一个启用的都没有时往前推一步 —— 对账在途就等；投影表空、库里有原料就入队全量对账；有在建的就等；有建好的就启用最新的（和管理员点「启用」同一条路，覆盖不上就落到下一步）；旁路准备好了才建新的。整步在锁住所有代次之后做（几个后端连同一个库也只有一个往前推）。已经有在用的就不动：换不换由管理员决定。
- `RagBootstrapScheduler`：开机 20 秒后、之后每 30 秒一次；RAG 关着、切换期间（worker 关了、生产冻结）不推；旁路准备好没有在拿锁之前问；这一步出错吞掉、下一次再来。
- 判据：真库 + 真 worker + 照真旁路回包写的桩，照线上的样子（Wiki 页在、投影表空、两个空的 READY）：对账 → 在途时等 → 对账完两页进投影表 → 旁路没准备好不建 → 那两个空的覆盖不上、建新的 → 在建时等 → 建好、旁路收到两页 → 启用、只有一个 ACTIVE → 之后再建好的照旧 READY。RAG 关着什么都不推。定时任务三条（替身）。扰动 11 个全红。第一次跑撞到一处：对账在途时投影表还是空的，一遍遍回「对账」—— 先看在途、再看空不空。

## 线上
