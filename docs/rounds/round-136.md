# 第一百三十六轮（2026-11-12）：把限时和限轮次去掉，没做完的活下一轮能接上

## 由来

用户连着三条：

> 现在就是每次做到一半，没有完全修复就暂停，下一次又得从头开始，所以把限时和限轮次去掉吧
>
> 还有为什么应用版没有 /compact
>
> 然后每次选然后要建一个临时脚本，没改完就暂停了，下一次又建临时脚本，又从头开始看

三句话说的是同一个毛病：**一轮被掐断 → 下一轮从零开始**。掐断的来源有两层，一层是预算
（时间 / 轮数），一层是上下文（下一轮看不到上一轮做到哪）。这一轮两层都动。

## 一、预算：0 = 不限

口径统一成「**0 / 没填 = 不限**」，四处都认这一条：

| 在哪 | 原来 | 现在 |
| --- | --- | --- |
| 桌面壳 `LocalAgent.Config.timeoutMs` | 600_000（10 分钟） | 0 |
| 桌面壳 `LocalAgent.roundsSetting()` | 默认 80，clamp 1–120 | 默认 0 |
| JS 宿主 `code-host.js` | `Math.min(120, run.maxRounds \|\| 30)` | `Math.max(0, run.maxRounds \|\| 0)` |
| 后端 `CodeLoopBudget.EXPLICIT` | 80 轮 / 600 秒 | 0 轮 / 0 秒 |
| CLI `config.js` 默认 | 80 | 0 |
| goal 模式 `DEFAULT_MAX_GOAL_TURNS` | 25 | 0 |

几处必须跟着改、不改就出事的地方：

- `JsCodeAgent` 的看门狗原来 `child.waitFor(budget.millis() + 5_000)` —— millis 变 0 就变成
  **5 秒后杀掉宿主**。改成 millis <= 0 时 `waitFor()` 一直等。
- `CodeLoopBudget.turnLimits()` 原来用「剩余预算」夹单次调用的读超时，millis 0 会算出
  `max(5000, min(150000, -elapsed))` = **5 秒**。改成不限时直接给单次上限（150 秒）。
- 桌面壳的进程看门狗 `timeoutMs / 1000 + 15`，0 时是 15 秒 —— 加了 `if config.timeoutMs > 0`。
- 前端 `waitLocal` 原来 `budget <= 0` 会兜底成 10 分钟，并且 `budget + 30000` 到点就
  `localCall({action:'stop'})` 并报「这一轮太久了」。改成 0 就不设定时器。
- `unfinishedReport` 的 `timedOut` 分支在 budgetMs 0 时会说「到了时间上限（0 秒）」，加了判断。

**没有动的是兜底「卡死」的那几条**（这是防死循环，不是防做不完）：

- 单次模型调用的读超时（后端 150 秒 / 网关 180 秒）；
- `REPEAT_STOP`：连着几次发同一个调用、结果一直没变 → 停下并照实说；
- 用户自己的「停」按钮 / Ctrl+C。

`CodeLoopBudget.KEYWORD`（关键词误触发档，4 轮 / 30 秒）**没动**：那一档是刻意过触发的，
「今天写了三小时代码」也会拉起它，放开就是烧钱。

连接层跟着放宽（不再是任务上限，只是别让没人看的 SSE 挂一整天）：

- `AiWorkspaceService.STREAM_TIMEOUT_MS`：15 分钟 → 4 小时；
- `ai-assistant.js` 的 `STREAM_POLL_MAX_ATTEMPTS`：450（15 分钟）→ 7200（4 小时）。

## 二、没做完的活：留在项目里，下一轮接上

新文件 `zhiqu-cli/src/progress.js`，笔记写在 `<项目>/.zhiqu/progress.md`（已加进 `.gitignore`）：

- 一轮**没做完**（被打断 / 出错 / 连着重复被停下 / 轮数用完）→ 写下：改过哪些文件、
  做过的最后几步、最后一步是什么；
- 一轮正常收尾 → 删掉笔记（不留噪音）；
- 下一轮开工 → 读进来，作为一条 system 消息排在用户这句话前面，并明说
  「不要从头再通读整个项目，也不要重建已经有的临时脚本」；
- 超过 24 小时的不认（那是上一次的活，不是接着做）；
- 这一轮什么都没做（用户只问了一句）→ **不动**已有笔记，上一轮的进度还等着接上。

只记真发生了的（`ctx.changedFiles` / `ctx.steps`），不让模型自己编。写不进去（只读目录、没权限）
就静默跳过 —— 记账不能把这一轮弄挂。

## 三、应用版 /compact

后端在对话太长时会说「请先压缩（/compact）」，而应用版的命令表里根本没有这个命令 ——
用户在桌面上打不出来，只能去命令行。这一轮补上：

- `SLASH_COMMANDS` 加 `/compact`（`bare: true`，不当成一句话发给模型）；
- 桌面路径的 history 是页面自己组装的（`slice(-40)`），所以压缩也在页面做：
  把较早的对话按**原话**摘成一段（用户的话留 400 字、回答只留第一段 240 字），
  按 notebook 存进 localStorage；
- 之后发送时用「摘要 + 压缩点之后的消息」代替「最近 40 条」；聊天记录一个字都不动；
- 不调模型：压缩本身不该再花一次调用，也不该因为模型挂了而失败。

网页版没有这个命令（`paintSlash` 在非桌面直接返回，网页里 `/` 开头就是一句话）；
网页那条链路的 history 由后端组装，压缩在 `ToolLoopContext` 里做（省略较早的大段工具输出）。
