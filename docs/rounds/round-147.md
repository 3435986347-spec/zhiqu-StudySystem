# 第一百四十七轮（2026-11-17）：应用的会话在命令行里接着做 —— 第 3 步：没有文件夹的对话

方案 [`docs/app-resume-plan.md`](../app-resume-plan.md) 的第 3 步。用户定的：没有文件夹的会话也要能 `/resume`，列表里写明「只有文字」。

## 由来

前两步只管桌面应用里选了文件夹的对话（本机代码助手在项目里写会话记录）。普通聊天、生成到产物、服务器上的代码模式在用户电脑上没有记录，
命令行的 `/resume` 还是看不见。它们在服务器上只有一问一答（工具调用本来就没存），所以只能接文字版。

## 做了什么

- **后端两个只读接口**（`HarnessController`）：
  - `GET /api/harness/conversations`：最近的对话（最多 50 个），每个带命令行那边用的会话 id —— 命令行来的是它自己的 id，别的是 `app-<号>`，默认对话（有消息才列、排最前）是 `app-default`；标出哪些是命令行来的。
  - `GET /api/harness/conversations/{id}/messages`：一个对话的文字版 —— 还能用的滚动摘要，加上它没覆盖到的最近 40 条问答（id、谁说的、正文）。`id` 是对话号或 `default`。
  - 两个接口只认命令行的令牌（和登录）；桌面那种 12 小时的令牌按白名单不认（它读得到聊天原文）。别人的对话号照旧拒绝（`requireOwnedNotebookIfPresent`）。
- **命令行 `/resume` 分两段**：这个文件夹里的会话记录在前（带工具调用）；下面一段「应用里的对话（这个文件夹里没有记录：接过来只有文字，没有工具记录）」，编号接着往下数。
  这里已经有记录的对话不再列第二遍；服务器给的 id 不合规的不列（要拼进文件名）；取不到（断网、直连没有服务器、旧服务器）就只有本地那一段。`/resume <编号>`、`/resume <会话 id>` 也认。
- **接过来**（`importConversation`）：在这个文件夹里开一份同 id 的会话记录，前情摘要和问答拍扁成「供参考」放进去，记下对账点 ——
  和桌面应用的本机代码助手走同一条路（把那几个函数从 `host/code-host.js` 挪进了 `src/handoff.js`）。之后在这里说的每一轮存档回原来那个对话（第 1、2 步已经接好）；
  之后在桌面应用里选这个文件夹接着说，接的也是这一份，接过来的那几轮不会再补一遍。导入时拿这段会话的锁（同一台电脑上的应用可能正在这个文件夹里跑它）。
- **指路**：桌面的本机代码助手每打开一段对话的记录，就在本机的 `~/.zhiqu/app-sessions.json` 记一条「这段对话的记录在哪个文件夹」（用外壳给的家目录；只在本机，不上传绝对路径；最多 500 条）。
  命令行在别的文件夹里挑这段对话时，那边的记录还在就先说「这段对话在 ~/proj 里有完整的记录（带工具调用）：cd 过去再 /resume」，问一句要不要仍在这里接文字版，默认不接。
- `/resume` 的说明改成「列出这个工作区的会话和应用里的对话，挑一段接着做」。

## 判据

- `zhiqu-cli/test/app-import.test.js`（新）6 条：两段的顺序、写明只有文字、编号接着数、这里有的不列第二遍；挑一段之后模型看得到摘要和问答、存档回原对话、桌面应用接着时不重复补；
  按编号 / id 直接接、默认对话、本地有会话时编号不错位；指路（不要就不接、要就接、那边的记录没了就不指路）；取不到时本地照常；不合规的 id 不列。
- `desktop-host.test.js` 加 1 条：宿主记本机索引（用外壳给的家目录、记的是绝对路径；不给 id 不记）。
- `HarnessSessionBindTest` 加 2 条（对话列表、文字版），`AccessTokenScopeTest` 加两个桌面令牌不认的接口（对照：命令行的令牌认）。
- `HarnessUsageIntegrationTest` 加 1 条真库的（列得出、读得回、按时间顺序、别人的读不到）。**这台机器没有 Docker，没跑过。**
  `conversationHandoff` 里「摘要覆盖到的不再给」那一段只有这条判据照得到 —— 也就是说现在没有被验证过。
- 扰动 23 处全部见红。第一遍有 2 处没红：「按编号挑应用的对话错位」—— 判据里本地一段会话都没有，错位和不错位一样，补了本地有会话的样本；
  「本机索引记相对路径」—— 扰动时跑错了判据文件（应该跑宿主那份），换了以后见红。
- 真进程端到端（`/tmp` 里的脚本，假服务器同时给对话列表、文字版和模型）：真的 `Api`（HTTP）走 `/resume` 挑应用里的对话 →
  真的命令行进程 `exec resume app-12` 接着说（看得见摘要和聊天里的问答，存档发往 `app-12`）→ 真的宿主进程在同一个文件夹里接着（聊天那一轮、命令行那一句各只出现一次）。

## 没做的，和方案不一样的

- `zhiqu --resume <id>`、`zhiqu exec resume <id>` 不会从服务器接：只认这个文件夹里已有的记录。要接应用里的对话先进交互模式用 `/resume`。
- 文字版最多最近 40 条问答 + 滚动摘要；摘要和这 40 条之间要是有空档，空档里的话就没了。摘要「对不上」（服务端的判脏）时不给摘要，只给 40 条。
- 列表里不显示每个对话有几条消息（要多查一次）；没有消息的对话也会列出来，接过来是空的。
- 本机索引只有桌面应用写；命令行自己从服务器接过来的那一份不记（它就在当前文件夹，下次 `/resume` 在本地那一段里）。
- 还是没重打桌面应用（宿主改了：记本机索引）。没用真模型跑。

- 后端 `mvn -o clean test -Dzhiqu.skipDockerTests=true`：1524 条，0 失败，268 跳过（要 Docker 的集成测试，这台机器没有），BUILD SUCCESS。
