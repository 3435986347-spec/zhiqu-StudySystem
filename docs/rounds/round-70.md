# 第七十轮（2026-10-18）：知识 Wiki 换编辑器内核的验证（CodeMirror 6 实时预览）

## 由来
第六十九轮锐评第 4 条：Wiki 的编辑器是自己用 contentEditable + `execCommand` 写的，保存时再把 HTML 转回 Markdown，第六十四到六十八轮五轮都在修这一层（滚动跳、点击编辑、只读）。
用户问「编辑器内核所以可以更换成什么」，答推荐 CodeMirror 6 做「实时预览」（Markdown 原文是唯一的真相，Obsidian 同款），候选 Milkdown / TipTap / Vditor；先花一轮验证、数字说话，过了再分轮迁。用户：「好的」。
用户同意从 registry.npmjs.org 下载 CodeMirror 6 的包和 esbuild（放仓库外的临时目录，只打一次包），打好的单个文件提交进 `assets/vendor/codemirror/`。

## 计划
1. **引进来**：选发布超过两周的版本，esbuild 打成一个 ESM 文件（不压缩以外不做别的），和 KaTeX 一样放 `assets/vendor/`，附版本清单、SHA256、许可证。前端照旧没有构建步骤；判据核对清单和文件对得上。
2. **最小实时预览**（开关后面，默认关，不改现在的编辑器）：标题、加粗 / 斜体 / 行内代码在光标不在时藏语法、`[[双链]]`（显示成链接、`[[` 补全页名）、行内 / 块公式（复用 KaTeX）、任务勾选。阅读模式照旧用 `renderMarkdown`。
3. **量**（同一页：第六十九轮那页 2 万字、166 个公式；同一台机器、同一个浏览器，和现在的编辑器并排）：
   - 点进编辑到能打字的时间；
   - 打字延迟（输入到下一帧）；
   - 不改内容保存回来是否逐字节一样（现在的编辑器拿 Markdown 判据的语料和真实页面跑一遍 `htmlToMarkdown(renderMarkdown(md)) === md`）；
   - 中文输入法：桌面应用是 WKWebView，不开窗口没法真打字 —— 能在 WebKit 里量的量，真输入法留给用户在装好的包里试，照实写。
4. **结论**：数字和差异写进本轮记录，给出「迁 / 不迁 / 换候选」的建议和分轮迁移计划（先编辑、阅读不动；工具栏、粘贴图片、草稿、只读逐个接上）。
5. 收口：全量（开 Docker）、真浏览器、本轮记录、README 和 CLAUDE.md 各一行、提交（不推）。

## 结果

**引进来**：CodeMirror 6（state 6.7.6 / view 6.43.13 / commands 6.11.1 / language 6.12.4 / lang-markdown 6.5.2 / autocomplete 6.20.3，@lezer/markdown 1.7.2 等共 12 个包，都是 MIT，都是 10 月 4 日以前发布的）用 esbuild 0.28.2 打成一个 ESM 文件：
`assets/vendor/codemirror/codemirror.js` 359 KB（gzip 117 KB），附 `VERSIONS.json`（包、版本、SHA256、打包命令）、`LICENSE`、`entry.mjs`。
`markdown()` 会把 HTML / CSS / JavaScript 语言包一起带进来（542 KB），Wiki 用不着，改成只导出 Markdown 语言自己包一层。比先前估的 200–300 KB 大一些（光 `@codemirror/view` 就 166 KB）。只有打开开关、进编辑时才按需加载。

**实时预览**（`assets/wiki-cm.js`，开关在 Wiki 右侧「页面检查」里，默认关）：标题、加粗 / 斜体 / 删除线 / 行内代码、链接在光标不在时藏语法；`[[双链]]` 显示成链接、点了跳页、`[[` 补全页名；行内 / 块公式用现有的 KaTeX；任务勾选框只改那一个字符。
阅读模式照旧用 `renderMarkdown`。工具栏的加粗 / 斜体 / 代码 / 链接 / 公式接上了，下划线、插图片、「源码」在验证版里还没接（点了会说）。

**量**（同一页：2 万字、166 个公式；同一台机器；现在的编辑器 vs 验证版）

| | Chromium（内置浏览器） | WebKit（不开窗口的 WKWebView，桌面应用的引擎） |
|---|---|---|
| 点进编辑（中位） | 56 ms → **38 ms** | 82 ms → **35–38 ms**（第一次 68–69 ms） |
| 打字每个字（中位 / p95 / 最慢） | 3.3 / 3.4 / 5 → **1.0 / 2.3 / 5 ms** | 4 / 5 / 15–16 → **2–3 / 4–5 / 15 ms** |
| 编辑时正文里的节点 | 11,588 → **633**（只画看得见的几屏） | 同左 |
| 不改内容保存，逐字节一样 | **0/14 → 14/14** | 同一份代码 |
| 打 30 个字进去几个 | 30 → 30 | 30 → 30 |

- WebKit 里打字要计到「真的进了文档」为止：不开窗口时 WKWebView 没有焦点，CodeMirror 靠 MutationObserver 晚一点才收，同步计时会少算（第一次量出「30 个只进 29 个」就是读早了，逐个查过 8/8 都进去了）。
- **不改内容保存时现在的编辑器改了什么**（14 页语料：标题强调、嵌套列表、任务、表格、代码、公式、链接、引用、换行转义、嵌入、混合笔记、空行）：
  只多一个结尾换行的 5 页（后端存的时候本来就去掉结尾换行）；真改坏的 9 页 —— **嵌套列表被压平**、**代码块的语言丢了**（```` ```js ```` → ```` ``` ````）、**表格对齐丢了**、**行尾两个空格的硬换行丢了**、列表项之间被插空行、连续空行被合并、
  转义的 `\[不是链接\]` 被当成显示公式、保存成 `$$` 公式块把段落拆开。用户点进编辑改一个字再保存，这些全都会发生。
- 验证版真改的时候只改该改的：嵌套列表里打字，缩进原样；点勾选框只改 `[x]` → `[ ]`。

**顺手看到的**
- **后端存的时候去掉结尾换行**（POST 进去 12 页，回来 11 页不一样，都是少了结尾的 `\n`）：Obsidian 的文件都以换行结尾，导入再导出本身就改字节。
- **阅读模式不认两个空格缩进的嵌套列表**：`  - 嵌套一` 显示成文字「- 嵌套一」。这是 `renderMarkdown` 的事，换不换编辑器都要修。
- `renderMarkdown` 把 `\[…\]` 当显示公式（模型常这么写公式），所以转义的方括号在阅读时也变成公式 —— 是取舍，不是单纯的错，记一笔。
- **用户看到的「左右两侧都压缩变形了」**：Wiki 两侧面板默认收起，刷新时先按展开画出来，脚本加上「收起」时宽度一下缩到 44 px，里面的内容却还要 0.12–0.24 秒才淡出 —— 每次打开都闪一下挤扁的目录和页面检查；
  我截图时内置浏览器在后台、动画被冻住，正好停在那一帧。内容和竖条的淡入淡出改成只在面板初始化完（`zq-panel-ready`）之后才有，刷新直接是收起后的样子（判据先见红）。
- 中文输入法：不开窗口没法真打字，要用户在装了新包的桌面应用里打开开关试 —— 照实写，没测。

**判据**：`wiki-cm-check.js` 8 条（扫描双链 / 公式、加粗来回、开着才挂、保存发原文不经过 htmlToMarkdown、换页拆掉、只读和工具栏、关着一点不碰），`WikiEditorSpikeTest` 另核对 vendor 清单（SHA256、大小、MIT、没带语言包），
`PanelMotionTest` 加一条（面板里的过渡只在 ready 之后）。扰动：保存走 htmlToMarkdown、换页不拆、只读不传、开关不认、bundle 改一个字节、面板过渡回到 ready 之前，全部见红；
`paintWikiDoc` 里原来写了两处拆编辑器，删一处判据不红 —— 第二处是多余的，删了（一个行为一道守卫）。

## 结论与建议：迁

数字支持换：保存不再改写内容（这是现在编辑器最要命的问题，不是速度）；点进编辑快一倍（WebKit 82 → 38 ms）；长页面编辑时只画看得见的部分；打字两边都快、差不多。
建议分轮迁，每一步默认关、在开关后面验收，最后再把默认换过来：
1. 先修阅读那头：`renderMarkdown` 认嵌套列表（不然编辑器保住的结构在阅读时还是被压平）；后端不再去掉结尾换行（或在导出时补回）。
2. 编辑器补齐：粘贴 / 拖进图片、下划线（`<u>`）、表格编辑的样子、点哪儿光标落哪儿（阅读视图的位置映射到原文位置）、代码块高亮。
3. 用户在桌面应用里试中文输入法、长时间用；没问题再把默认换成新编辑器，旧的 contentEditable 编辑路径和 `htmlToMarkdown` 的保存路径删掉。

## 收口
- 后端全量 `mvn -o clean package`（开着 Docker）：**1166 项、0 失败、0 跳过**。Wiki 的 node 判据 9 份照旧全绿（开关关着时什么都没变）。
- 真浏览器（内置浏览器、验证库的测试账号）：开关打开 → 点正文挂上编辑器 → 编辑时再点开关被拒绝、取消后能换回；两种编辑器各量两遍；14 页语料两种编辑器各走一遍「点进编辑 → 保存」（保存请求在页面里拦下、没写进库）。
- 桌面应用重新打包：`codesign --verify --deep --strict`、`hdiutil verify` 都过，应用里 JAR 的 `wiki-cm.js`、`codemirror.js`、Wiki 脚本、样式表、壳、service worker 逐字节等于源码。没有启动或替换用户在用的应用。
- **要用户试的**：装上新包，打开 Wiki →右侧「页面检查」→「试试新编辑器（验证版）」→ 点正文，用中文输入法打几段字（含选词、删除、换行、在列表和标题里打字），再保存。
- **留在验证库里的**：「语料01」到「语料12」十二页（`zhiqu_verify`，留给用户删）。
