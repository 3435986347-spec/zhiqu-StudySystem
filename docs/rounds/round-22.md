# 第二十二轮（2026-09-29）：暴力测试 —— 网络和服务器的极端

## 由来
第十九轮看的是「我们的服务器 → 模型供应商」这一段出问题。另一段 ——「用户的浏览器 / 命令行 → 我们的服务器」—— 只在请求层做过一次加固
（超时、只在安全时重试、看不懂的响应说人话、同一个写请求不重发），真的断网、回应丢在半路、服务器半路重启，没人演过。
第二十轮刚让手机能用，手机上的网络恰恰最不稳：电梯里、地铁里、Wi-Fi 切 4G。

几个一看就可疑的地方：
- **写操作的回应丢了**：服务器已经建好了任务 / 记好了番茄钟，回应在回来的路上断了。页面说「网络连接失败」，学生再点一次 —— 两份。
  写操作故意不重试（重来可能写两遍），而服务端的幂等（`Idempotency-Key`，第八轮）只接在新建任务、套用参考计划和几个 AI 接口上。
  第二十一轮给番茄钟加的「没记上要说出来」，在这种情况下会说「没记上」—— 其实记上了。
- **服务器半路重启**（部署、崩溃、桌面应用被关掉）：正在流的回答在库里停在 STREAMING、agent 的执行记录停在 RUNNING。启动时没有任何东西去收拾它们
  （RAG 的任务有租约，会被捡回去；这两样没有）。重启之后页面上是不是永远「正在生成…」？
- 网慢（3G）、时断时续、离线再上线：页面等多久、按钮在等的时候什么样、打了一半的字和正在跑的番茄钟怎么样。

## 计划（开工时）

### 1 网页：写操作的回应丢了
真浏览器里拦截（Playwright 的 `route`）：请求照常到服务器、服务器照常处理，回应在回来的路上掐掉（也演超时、502）。每一种写操作都演：
新建任务、例行计划、Notebook、Wiki 页、参考计划、反馈、模型配置、打卡、番茄钟记录、个人资料、改密码。看两件事：页面说了什么（说的是不是真的），
学生照着提示再点一次之后库里是一份还是两份。

### 2 服务器半路重启
真的 `kill -9` 再拉起来（也试正常停止）：流式回答进行到一半、agent / 代码工作区的执行进行到一半、一批写操作进行到一半。
看重启之后库里的状态（STREAMING / RUNNING 残留、半截的数据）、页面刷新后看到什么、命令行在等回答时说什么、能不能接着用。

### 3 网慢、时断时续、离线再上线
3G 限速（CDP 的网络模拟）下各页打开要多久、写操作等待时按钮什么样；`context.setOffline` 让网断一会儿再回来：正在打的字、正在跑的番茄钟到点时的记录、
正在流的回答、离线时点的按钮。

### 4 命令行
到服务器的连接断在半路、服务器重启、连接挂住一个字节都不回（不是断开，是不动）：会话能不能接着用、正在流的回答、工具循环的中间状态。

### 暴力测试（每轮都做）
- 一边连发写操作（新建、打卡、番茄钟）一边 `kill -9` 服务器再拉起来，反复几次：库里不许有重复、不许有停在 STREAMING / RUNNING 的。
- 网每几秒断一次，照常用一段时间。

### 修
照出来的都修，数量不设上限；判据先红、扰动见红。

## 结果

真浏览器（Playwright + Chromium）、临时库 zhiqu_verify。「掐回应」用 Playwright 的 `route`：请求照常到服务器、服务器照常做完，回应在回来的路上断掉；
「时断时续」用一个自己写的 TCP 代理（回程慢 300ms，每 0.4～2 秒切一次断 / 通，断的一刻掐掉所有连接）—— Chromium 的 `setOffline` 不会掐已经建立的连接，
流到一半的回答在它下面根本没断过，第一次演「流到一半断网」就是这么演错的。对照组是第二十一轮的服务端加上一轮的页面（另起一个实例）。
「没有 Redis」另起一个实例把 Redis 指到没人听的端口 —— 桌面应用就是这样。

### 1 写操作的回应丢了

每一种写操作都演：新建任务（快速添加）、套用参考计划、例行计划、Notebook、Wiki 页、反馈、模型配置、番茄钟记录、打卡、个人资料、删除任务。

| 回应断在路上 | 原来 | 现在 |
|---|---|---|
| 第一下页面说什么 | 「网络连接失败，请检查网络后重试」—— 其实已经做了 | 只断一次：页面自己用同一个键重来，说「成功」；一直断（三下都断）：「网络连接断了，不确定有没有保存上 —— 再点一次不会重复保存」（删除：「不确定有没有删掉 —— 再点一次就好」；502：「服务器暂时不可用（HTTP 502），不确定…」；超时：「服务器 30 秒没有回应」之后自己重来） |
| 照着提示再点一次 | 例行计划、Notebook、Wiki 页、反馈、番茄钟、任务都是**两份**；删除说「任务不存在或无权访问」（其实删掉了） | 11 种都是一份；删除说成功。四下请求带的是同一个键 |
| 打卡 | 一份（库里有唯一键） | 一份 |

- **服务端**：`IdempotentWriteAspect` 给所有登录后的写接口（`@Post/Put/Delete/PatchMapping`）接上 `Idempotency-Key` —— 原来只有新建任务、套用参考计划、
  AI 批量建任务接了。同一个用户 + 接口 + 地址 + 键只做一次，再来交回上次的结果（15 分钟，见下面 review 那一段）。不接的列在判据里：自己在参数里接了的、回应里带 Cookie 的
  （登录、退出、改密码）、流式回答。同一个键「上一次还在处理」单独回 409（`RequestInProgressException`），页面等一下用同一个键再来。
- 锁原来 30 秒 —— 正好是页面的超时：一次做了 31 秒的写，超时后重来的那一下碰上锁到期，和还没做完的那一次**同时**执行。改成 6 分钟（比代码工作区一整轮长）。
- **页面**（`request()`）：每个写请求带一个键；断网、超时、502 / 503 / 504、409 用同一个键重来两次；还不行就照实说「不确定」，并把键留 10 分钟 ——
  内容一模一样的下一次（照着提示再点）还用它。这期间同一块数据（地址第一段相同）有别的写成功了就作废：打卡没弄清 → 撤销 → 再打卡，拿旧键只会拿回旧结果、
  什么都没做。宁可偶尔多一份（看得见、删得掉），不能说做了其实没做。快速添加原来每次点击现生成一个键 —— 回应丢了再点就是新的一次，去掉了。
- **重启之后也认得**：结果原来只在 Redis 里、没有 Redis 时在进程里。没有 Redis 的实例上 `kill -9` 重启，同一个键再来：原来 1 条 → 2 条，现在 1 条
  （表 `idempotency_record`，V39）。

### 2 服务器半路重启

真的 `kill -9`（也试了正常停止）。

| | 原来 | 现在 |
|---|---|---|
| 流式回答进行到一半 | 库里停在 STREAMING、执行记录 / 步骤 / 任务停在 RUNNING；刷新之后「正在生成…（已等 18 秒）」接着「还在等模型开始回答（已等 88 秒）」一直数下去，已经收到的半截也不显示 | 启动时收成失败：「⚠ 服务在回答途中重启了，这条回答没说完（已经收到的部分留着）。可以再问一次。」（一个字都没落库时说「没能说出来」）；没轮到的任务标成跳过 |
| 暴力测试里 4 次重启之后 | 回答 4 条、执行记录 4 条、步骤 4 条、任务 20 条停在进行中 | 0；4 条回答收成了上面那句 |

`InterruptedWorkRecovery`（`ApplicationRunner`）：只动这个进程开始之前建的行，启动之后新来的回答碰不到；部署是单实例的，将来多实例要改成按心跳判断。
RAG 的索引任务有租约，提醒有「处理中太久就重新排队」，上传资料的解析在一个事务里 —— 这三样本来就不会卡住。

### 3 网慢、时断时续、离线再上线

**慢网（Slow 3G：往返 400ms、400kbps，手机宽度）**：文字类的回包原来原样发（Windows 部署前面的 Caddy 会压，手机直连服务器、Linux 部署都没压）。
开了压缩（流式回答 `text/event-stream` 不压 —— 压缩要攒够一块才发）：

| 页 | 原来：能用 / 全部加载完 / 传了多少 | 现在 |
|---|---|---|
| 看板，第一次 | 8.8s / 16.8s / 708KB | 4.0s / 5.7s / 138KB |
| 看板，第二次（页面脚本在 Service Worker 里） | 2.9s / 8.5s / 296KB | 2.1s / 2.6s / 10KB |
| 任务 | 2.7s / 3.2s / 75KB | 1.2s / 1.7s / 4KB |
| 例行计划 | 2.7s / 3.2s / 55KB | 1.6s / 2.1s / 4KB |

回答照样一段一段到（每 0.5 秒一段，和不压时一样）。生产模板（`deploy/windows/application-prod.example.yml`）同样打开 —— 第一遍全量里
`ProdConfigParityTest` 红了：只加在开发配置里的话，线上是替换配置，悄悄回到不压；前面挂着 Caddy 时它见到已经压过的就不再压。**写操作等回应的那几秒**：原来按钮、页面都不变（3 秒延迟实测：例行计划「创建」、个人资料「保存」、
任务状态切换），学生以为没点上。现在刚点的按钮标成忙（变淡、光标转圈），0.6 秒还没回来页面顶上说「正在保存…」。按钮不禁用 —— 禁用由各处自己管，再点也不会写两遍。

**时断时续**：网每 0.4～2 秒断一次，连着建例行计划、Wiki 页、记学习记录各 20 件，页面说失败 / 不确定就等一秒再点：

| | 原来 | 现在 |
|---|---|---|
| 网断了 | 124 次 | 94 次 |
| 点了 | 120 下 | 77 下 |
| 页面说的 | 60 × 「网络连接失败，请检查网络后重试」 | 17 × 「网络连接断了，不确定有没有保存上 —— 再点一次不会重复保存」 |
| 库里 | 60 件事 **90 条**（30 件两份或三份） | 60 条 |

**番茄钟到点的那一刻网断了**（地铁里）：原来「这个番茄钟没记上：网络连接失败，请检查网络后重试」，25 分钟就没了 —— 页面上也没有能「再点一次」的东西。
现在先存在这台设备上：「网络断了：这个番茄钟先存在这台设备上，连上网会自动补记」，看板上「另有 1 个还没传上去（连上网自动补记）」；网回来：
「补记了 1 个番茄钟（专注完的时候网断了）」。断网到点之后直接关了页面，网好了打开任务页也补上。每一条带自己的幂等键（补几次都一份）；过了零点才补上的带完成那天的日期；
服务器明确拒了才丢掉并说原因；登录过期、别的账号的留着。

**AI 助手**：

| | 原来 | 现在 |
|---|---|---|
| 回答流到一半真的断了 4 秒 | 提示「network error」；网回来之后接着出字（这一样原来就好） | 「连接断了，网回来之后会把回答接上」；接回那一下还连不上的话，等网回来再试（原来只试一次） |
| 断着网点发送 | 提示「Failed to fetch」；聊天里多出两条，一条写着「（连接中断，正在尝试接回…）」—— 什么都没发出去，网回来之后也一直挂着 | 「网络连接失败，这句没发出去 —— 字放回输入框了，连上网再发」；那两条撤掉；网回来之后拉一次消息（万一其实发到了） |
| 打了一半的字 | 在输入框里 | 在输入框里 |

### 4 命令行

| | 原来 | 现在 |
|---|---|---|
| 回答到一半 `kill -9` 服务器 | 「✗ 模型的回复中途断开了（ECONNRESET）」—— 怪到模型头上；安静模式下已经收到的 14 段一个字都不显示 | 先打出「（断开前已经收到的：）第1段…第14段」，再说「回复中途断开了：和服务器 … 的连接断了（ECONNRESET）—— 服务器可能在重启，或者网络断了；等一下再说一次就好」 |
| 工具循环到一半（刚写完文件）断了 | —— | 文件在；`-c` 接着问，记录里是完整的三条（问、工具调用、工具结果），没有悬空的工具调用 |
| 服务器接了连接、一个字节都不回 | 一声不吭 **91 秒**，然后「连不上服务器 …（ETIMEDOUT）」 | 15 秒时「· 连不上服务器 …（服务器 15 秒没有回应），再试一次…」，30 秒时说完 |
| 远程工具（会建草稿的）回应丢了 | 「远程工具调用失败：连不上服务器（ECONNRESET）」—— 草稿其实建了，模型看到「失败」再调一次就是两份 | 登录后的 POST 都带键、断了用同一个键重来；还不行就说「没拿到回应 …不确定这一下有没有做成；内容不变再来一次不会重复」，模型照原样再调沿用那个键 |
| 网页存档的回应丢了 | 下一轮补发 —— 网页上多一份 | 补发的内容不变，沿用没弄清的那个键 |

### 暴力测试

- **一边连发写操作一边 `kill -9`**：例行计划、学习记录、Wiki 页、打卡连着做（每件做成为止），5～10 秒杀一次、拉起来，共 4 次；另一个标签页同时在流回答。
  没有 Redis 的实例：78 件、点了 86 下（8 下「不确定」），**没有一件多一份**，打卡没有重复，没有停在进行中的，重启时正在流的 4 条回答都收成了那句话。
  有 Redis 的实例：81 件、89 下，同样。原来：86 件、120 下（34 下「网络连接失败」），也没有重复 —— `kill -9` 时请求大多还没进门（连接被拒），
  重复出在「做完了、回应断在路上」，那是上面时断时续那一张表；但回答 4 条、执行记录 4 条、步骤 4 条、任务 20 条一直停在进行中。
- **网每一两秒断一次**：见上面「时断时续」。

### 判据

- `IdempotentWriteIntegrationTest`（5 条，真 HTTP、真库）：七种写操作同一个键两次只做一次、交回同一个结果；换键 / 不带键照常各做各的；同一个键发给别的接口不串；
  同一个键同时来 20 下只做一次、其余回 200 或 409；重启之后同一个键还认得、过了 10 分钟不认；不接这个头的写接口一个一个列清楚（新加的默认都接）。
- `IdempotencyLockSpanTest`：锁比页面一整轮自动重来长、比最长的一次写长。
- `InterruptedWorkRecoveryIntegrationTest`：从启动时的入口（`ApplicationRunner`）进；半截留着、一个字没有时换一句；启动之后建的不碰；再跑一遍什么都不改。
- `NetworkCompressionIntegrationTest`：页面脚本、页面、接口的 JSON 按 gzip 发，解开和原文一样；流不压。
- `RequestResilienceTest` + `request-check.js`：写请求带键、断了 / 502 / 409 用同一个键重来、说「不确定」、照着提示再点沿用、同一块有别的写成功就作废、
  业务拒了 / 限流不说「不确定」、登录注册不带键；聊天流连不上 / 断在半路说中文；断线接回等网回来；「正在保存…」和按钮的忙状态；接线（快速添加不自己带键、断网发送）。
- `PomodoroOutboxTest` + `pomo-outbox-check.js`（11 条）。
- 命令行 `reliability.test.js`：新加 4 条（带键重来、不确定之后沿用、存档的键、卡住的服务器），改 2 条（没登录的 POST 照旧不重来；断开前收到的打出来、说清是和服务器的连接）。
- 前几轮的判据跟着改（意思不变）：`SharedPlanApplyOnceTest` 看的键生成函数改名 `writeKey`。

扰动：第一批（服务端幂等、页面请求层、启动时收拾）21 处全红。第二批（命令行、番茄钟待补记、压缩、聊天断网、「正在保存」、结果落库）27 处，
第一遍 24 处红在该红的那条，另外三处照出的是判据和代码自己的毛病：
- 命令行的存档另给了每条一个键 —— 和「内容不变、不确定之后沿用那个键」那条规矩重复，删掉哪一道都不红。删了存档那一道；
  之后拿掉「沿用」，存档那条判据跟着红。
- 番茄钟补记「用的是存下时那个键」：不带键时两边都是 undefined，`===` 成立 —— 红在别的判断上，这一条是真空绿。改成先要求有键。
- 「断线接回等网回来」：拿掉重试之后那个 Promise 永远不来，node 在事件循环空了之后照样退出码 0、一行 FAIL 都没有。给它加了时限。
  三处改完重跑都红。

### review（收口之后又过了一遍）

用户要求 review 并修。审出 15 条，其中两条是真问题、代价大：
- **存下来的回包是明文**：幂等那一层把每个写接口的回包原样存进 Redis 和 `idempotency_record` —— 新建的个人访问令牌（库里本来只存它的 SHA-256）、
  管理员重置出来的临时密码、解密后的任务标题和 Wiki 正文（库里本来是密文）都原样进了库和备份。现在存之前用 `SensitiveCryptoService` 加密，
  落库的那个构造器必须带它；加密之前存的明文照样读得回来。
- **过期的清不完**：每 10 分钟只删 1000 行，而每个带键的写都插一行 —— 写得比每分钟 100 次多，表只涨不落。现在一批一批删到删完（一次最多 50 批）。

其余的：
