# 第四十四轮（2026-10-06）：界面打磨第 4 步 —— AI 助手：输入框、两侧面板的开关、消息排版

## 由来
`docs/ui-plan.md` 第 4 步。用户看过第 3 步的截图：「没有问题」。做完照例给截图。

## 计划

1. **输入区**：原来是一条常驻的虚线拖拽框 + 一排六个小按钮（上传 / 输入框 / 联网 / 深度思考 / 模型 / 发送），像表单。
   改成一个大圆角输入框：上面是附件、中间是输入（两行起、最高 200px）、底下一条工具：左边「附件」图标、联网 / 深度思考 / 代码三个开关，右边模型和一个圆形的发送箭头。
   和消息同宽、居中。开关按下的样子用样式表管（`aria-pressed`），不再在 JS 里一项一项写内联样式（原来还写死了 `fontWeight = '600'`）。
   发送中：箭头换成转圈、读屏念「生成中」；输入框空着时箭头变淡。
2. **拖文件**：拖拽框平时不出现。文件拖到对话这一栏上方时整栏盖一层「松开即可上传」；上传中 / 出错时输入框上面一条状态。粘贴文件、点附件图标照旧。
   原来手机上就是这样（第二十轮），现在桌面也一样。
3. **去掉调试信息**：页面右上角「已同步 50 条历史消息」和那个跳动的绿点。
4. **两侧面板的开关**：收起后的竖条不再竖排文字，只有一个面板图标按钮（悬停说「展开 Notebook · 资料」）；展开时右上角的按钮也换成同一套面板图标（和侧栏的收起按钮一样）。
   手机上收起的面板是正文上方的两个页签，字照旧留着。Wiki 的两侧面板用的是同一个机制，一起变；Wiki 左边「目录 · N 页」的字挪到按钮的提示里。
5. **消息排版**：用户的话是右边一个浅灰的气泡（不再有「我」的头像）；AI 的回答不套气泡、不要头像，直接排在页面上（像 Claude）；正文 14px、行距 1.7；
   消息一栏最宽 760px、居中（宽屏上一行不再拉到一百多个字）。样式从 JS 字符串搬进样式表的类。
6. **判据**：输入区的结构（输入框单独一行、工具都在框里、没有常驻的拖拽框）；开关的样子只在样式表里；发送中的状态；拖到整栏上方才出现的那一层（在 node 里真跑：进进出出子元素不闪、松手就收）；
   没有「已同步」；两侧面板的开关只有图标、有名字；消息行的结构。各自扰动见红。
7. 截图（浅 / 深、手机宽、拖文件时、发送中）发给用户；暴力测试：连点发送、拖着文件在栏里来回进出、展开收起两侧面板连点；桌面应用重新打包。

### 怎么验
截图；全量通过、扰动见红；桌面应用重新打包。

## 结果（2026-10-06）

照计划做完，另外多做了一件（表格，见下）。

- **输入区**：一个大圆角框（`.zq-composer`）：附件在上、输入框单独一行（两行起、最高 200px，14px 字）、底下一条工具：「附件」图标、联网 / 深度思考 / 代码三个开关（`.zq-chip`，带图标）、
  右边模型（无边框的小下拉）和一个圆形的发送箭头。和消息一栏同宽（最宽 760px）、居中，不再有上面那条分隔线。
  开关按下的样子由样式表按 `aria-pressed` 画，`setAiToggleState` 只写 `aria-pressed`（原来一项一项写内联样式，还写死了 `fontWeight = '600'`）。
  发送中箭头换成转圈、`aria-label` 换成「生成中」，回来换回；输入框空着时箭头变淡（`:has(:placeholder-shown)`，纯样式）。
  手机上三个开关只留图标（名字在 `aria-label` 里），375px 宽时整条放得下（量过：发送键右边缘 352 = 工具条右边缘，页面没有横向滚动）。
- **拖文件**：拖拽框（`#zq-drop-zone`）平时不出现，上传中 / 出错时当输入框上面的一条状态；拖拽事件挂到整个对话栏（`#zq-chat-col`）上，拖着文件进来时整栏盖一层「松开即可上传」。
  数进出了几层（进出子元素时不闪），多来的 `dragleave` 不减成负的，拖的不是文件不管、不拦；`dragover` 隔 1 秒不来也收（拖出窗口时有的浏览器不给 `dragleave`）。
- **去掉调试信息**：右上角「已同步 N 条历史消息」和跳动的绿点、写它的那一行 JS。
- **两侧面板的开关**：收起后的竖条只有一个「展开面板」图标，展开时右上角是「收起面板」图标（左右各一套，和侧栏的收起按钮同一类图标），名字在提示和 `aria-label` 里（「展开「Notebook · 资料」」）。
  手机上收起的面板仍是带字的页签。Wiki 也用这个机制：目录的页数（原来竖排在竖条上）挪进展开按钮的提示。新加 6 个图标（左右面板、附件、地球、灯泡、代码）。
- **消息**：用户的话是右边一个浅灰气泡（最宽 80%），AI 的回答不套气泡、没有头像，直接排在页面上；正文 14px、行距 1.7；样子从 JS 字符串搬进样式表的 `.zq-msg`。
- **多做的：表格**：Markdown 表格原来每一格四面描边、表头灰底（像格子纸），改成只有横线、表头的线深一档、表头字用次要色；字号 12.5px → 13px（令牌）。
  `renderMarkdown` 是 AI 助手和 Wiki 共用的，Wiki 里的表格一起变了。

**判据**：新的 `AiComposerTest` 七条（输入区的结构；开关的样子在样式表里；发送中 + 输入框高度和样式表一致；拖文件 —— 在 node 里真跑抠出来的 `bindAiDropZone`（`ai-drop-check.js`，15 条）；
两侧面板的开关；没有调试信息；消息排版）；`ui-shell-check.js` 加 12 条（在 node 里真跑 `zhiqu-ui.js` 的 `makeCollapsible`：左右两个面板的收起 / 展开按钮是哪个图标、只有图标、有名字、页签的字还在）。
跟着改的：`ChatBubbleSpacingTest`（气泡的内边距从 JS 的内联样式搬到了样式表，到那里读；理由补了一段）、`MobileLayoutTest`（原来管「手机上输入框挪到单独一行」，现在输入框本来就单独一行，改管「手机上开关只留图标」）、
`PageHeadTest`（同步状态去掉了）。扰动 27 个全红；走 node 的 9 个另外直接跑过，各自红在想照的那一条上。

**暴力测试**（内置浏览器）：用本机假模型真发一句、发送键连点 8 下 → 只发出一次（多两行），转圈、「生成中」，回完换回箭头、输入框清空；
拖文件（合成的拖拽事件）在栏里进出子元素 → 不闪，拖出去 → 收；两侧面板展开收起、明暗、手机宽各看过；Wiki 的两个竖条提示是「展开「目录 · 203 页」」「展开「页面检查」」。

**截图**（发给用户）：AI 助手浅色（气泡与回答、表格）、深色、深色两侧展开、发送中、拖文件进来时、手机宽深色、Wiki 的图标开关。

**验**：全量 992 / 0 / 0 / 0（开着 Docker）；桌面应用重新打包。
