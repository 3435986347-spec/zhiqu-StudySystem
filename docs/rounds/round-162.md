# 第一百六十二轮（2026-11-22）：coding agent 用户决策第 3 步——macOS 本机桥

接续第一百六十轮 CLI、第一百六十一轮网页代码模式。本轮只接 macOS 桌面应用的本机代码助手；Windows 在下一轮。

## 现状

- 本机模式的宿主和网页模式共用 `ask_user`，但 `LocalAgent.swift` 还没给宿主开启回答者，收到 `question` 会按未知消息停下整轮。
- 页面已有完整的多问题面板，但事件只认服务器 SSE 的 `decision.ask` / `decision.resolved`，提交只走服务器答案接口。
- 桌面任务已有 `resume` 快照、停止、离页恢复和中途补充协议；本机决策要复用这些路径，不另建一套窗口。

## 计划

- **能力组合**：页面发起本机 `run` 时显式带 `userDecision: true`；外壳只把字面 true 交给宿主。旧页面 / 旧外壳不开启工具，退回文字提问，不把 `question` 当致命错误。
- **外壳协议**：`LocalAgent` 转发 `question`，新增 `zqLocal {action:'answer', runId, decisionId, answers}` → 宿主 `question_result`。只接受当前运行、已登记且待答的批次；逐题校验完整性、方案编号、其他输入与长度。
- **幂等与收尾**：第一次有效答案只写一次；相同答案重复提交可确认但不重复唤醒，冲突和迟到答案不覆盖。运行结束、停止或宿主退出后不再接受答案，不让页面等待失去着落。
- **页面复用**：本机 `question` / `question_resolved` 进入现有 `decisionRuns` 和输入框上方同一个面板；本机提交走外壳，不调用服务器答案接口。待答与解决事件进 `resume` 快照，处理直播 / 回放交错，避免旧问题重新出现。
- **边界**：推荐项不自动选中；不新增数据库表，不改变写文件、命令和普通聊天审批；没有跨应用重启恢复承诺。
- **验证**：新判据先在旧实现见红；真编译 Swift、真起 Node 和 WKWebView，假模型完成多问题、其他输入、连点、离页回放、冲突 / 迟到提交和待答时停止。再跑前端专项、CLI 与后端全量；定点扰动确认判据有效。
- **交付边界**：开工时不调用付费模型，不碰用户真实账号，不部署线上、不发布 npm、不提交 Git；收口前用户另行提供 DeepSeek key 并指定 `deepseek-flash` 做最小真实测试，key 只进本轮临时配置、量完删除，不进仓库和文档。外壳需要重新打包才能交付，本轮先验证源码和真实组件，不擅自上传安装包。

## 实现

- `LocalRunRequest` 只把字面布尔 `userDecision: true` 交给宿主；缺省、字符串和其他值都为 false。新版页面的本机 run 显式声明，新旧页面 / 外壳组合因此都保持文字提问退路。
- `LocalAgent` 登记 `question`，按运行和问题编号保存问题与已规范化答案。`answer` 校验全部问题、方案、其他输入和 2000 字上限；相同答案返回 duplicate，不再次写入宿主，冲突不覆盖。结果到达、停止中和进程退出后都拒收。
- `PageView` 新增 `zqLocal answer`，只认当前运行；`question` / `question_resolved` 都进入 `resume` 快照。已答回包先落解决事件再回复页面，迟到回调不能重建已删除快照。
- 页面复用第一百六十一轮的 `decisionRuns` 和面板：`waitLocal` 把本机问题标成 local，`submitDecision` 走外壳而不 POST 服务器；直播 / 快照交错先缓存，终态与已存档终态都清掉待答。
- 静态缓存令牌为 `20261122-r162`；没有新增视觉样式或数据库表，首页轮播图无需改变。

## 验证

- 新判据在旧实现见红：真实 Swift / Node 检查里问题不到页面、`answer` 不被识别；本机提交误走服务器、直播问题不进入面板，本机 run 也没声明能力。
- `DesktopLocalAgentTest` 2/2：真编译 Swift、真起 Node、真 WKWebView、假网关。两题选择非推荐项和其他输入；漏答、空其他输入、错运行、错批次、冲突和迟到提交都拒收，相同答案只唤醒一次；待答停止正常收尾。
- 同一检查还载入发布的 `ai-assistant.js`，在真实 WKWebView 里点击方案、切下一题、填其他输入、连点提交；模型收到实际选择，面板成功收起。夹具的全局名和 Swift / JS 转义问题已修正，没有当成产品通过。
- 语义相同但其他输入带首尾空白的重复提交先见红，改为先规范化再比较后通过。定点扰动均见红并恢复：强制关闭能力、快照漏存 `question_resolved`、本机提交强制走服务器、取消直播缓冲、终场不清待答。
- 终态扰动在「已经成功提交」场景仍绿，因为提交本身已收面板；没有拿这次空扫当证据，改用「回放待答后收到终态」样本见红。
- 恢复后 `decision-check.js` 与 `stream-reattach-check.js` 均 ALL-GREEN；专项 15 项通过、0 跳过。CLI 全量 700 项：678 通过、22 跳过、0 失败。
- 用户随后指定真实 `deepseek-flash` 补测：直连最小调用返回 OK（33 输入 / 8 输出 token）；真 CLI + PTY 调出两题，三次 Enter 提交 JSON 文件与命令行，模型正常收尾、退出码 0。首次 PTY 401 是同一 shell 命令过早展开临时变量、写入空 key，修正后通过；不是产品故障。
- 真实模型补测是 CLI 直连；macOS 真实面板链路使用本机假网关，两者不混称。临时 key 配置、会话和扰动备份均已删除，未读写项目文件。
- 后端 `mvn -o clean test` 全量 1561 项：1561 通过、0 失败、0 错误、0 跳过，BUILD SUCCESS。首次后台观察 300 秒超时终止不算结果，随后以不限观察时限完整重跑取得上述结果。
