# 第一百六十轮（2026-11-22）：coding agent 用户决策第 1 步——统一内核与 CLI

用户确认按五轮实现结构化决策：本轮只完成统一提问协议、`ask_user` 工具和 CLI 多问题选择器；网页、macOS、Windows 分别在后续轮次接入。

## 计划

- 新增结构化问题与答案协议：一次 1–4 题，每题单选，可标一个推荐项，可允许其他输入；非法参数不弹半截问题。
- `ask_user` 只在当前存在交互回答者、且是主 agent 时下发；必须单独调用，和其他工具混发时整批不执行，避免未决定先产生副作用。
- CLI 在活动区上方显示选择面板：↑↓ 选、Enter 记录、←→ 切题、其他输入、全部回答后提交；推荐项只预高亮，不自动采用。
- Esc 取消本批提问，Ctrl+C 沿用整轮中断；提交或取消后留下摘要，窄终端与 resize 不留残影。
- 权限确认仍走原安全链路；`zhiqu exec`、无人值守和非交互输入不下发新工具。
- 新判据先见红，再用假模型和终端模拟器跑通完整问答，最后跑 CLI 全量测试。

## 实现

- `zhiqu-cli/src/decisions.js`：统一 `ask_user` schema、问题与答案校验、给模型的答案文本。一次 1–4 题，每题 2–6 个选项，推荐项最多一个；其他输入最多 2000 字。
- `agent.js`：只有带 `ctx.decide` 的主 agent 且非 exec 才下发；子 agent、无人值守不下发。`ask_user` 与其他工具混发或一次混发多批时，在任何工具执行和远程只读预取之前整批拒绝。没有回答者时硬调会说明不能交互，不谎称工具不存在。
- `cli.js`：交互终端接入 `Ui.decide`；`exec` 和非交互输入不接。
- `ui.js`：多问题选择器与原有 `chooseChain` 共用串行队列。↑↓ 移动，Enter 记录并跳到下一道未答题，←→ 切题；其他输入单独编辑；全部回答后高亮「提交答案」，最后一次 Enter 才 resolve。推荐只预高亮；Esc、abort、Ctrl+C、输入结束都取消且不采用推荐项。提交 / 取消留下摘要，恢复未发送草稿，支持窄终端和 resize。
- `steps.js`：新增 `decision` 步骤种类和「等待你决定」标题。`prompt.js` 教模型只在真正需要用户决策时使用、单独调用、每题给推荐项。
- `zhiqu-cli/README.md` 与 `docs/notes/cli.md` 同步本轮用法和边界。网页 / 桌面宿主本轮没有 `ctx.decide`，仍不给他们下发新工具，留待后续轮次。
