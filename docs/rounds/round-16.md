# 第十六轮（2026-09-28）：暴力测试 —— 命令行遇上坏掉的本地状态和奇怪的文件

## 由来
用户 2026-09-28 要的暴力测试：「不同输入…没有耐心的极端情况」。第十三轮测了命令行的 Ctrl+C / Ctrl+D 和垃圾输入，
第十四、十五轮在网页。这一轮回到命令行，但换一个方向：**它自己的文件坏了**、**工作区里有奇怪的东西**。
没耐心的人会在写到一半时强杀进程（kill -9、合上笔记本、断电），留下半行的会话记录、半截的配置、没删的锁文件；
工作区里会有二进制文件、几百 MB 的日志、不是 UTF-8 的文件名、指向自己的软链。

## 计划（开工时）
先一个个造出来、真跑 `zhiqu`（真 pty 或 `-p` 单发），看它怎么反应；判据先红、扰动见红。

### 1 坏掉的本地状态（强杀之后留下的）
- 会话记录最后一行只写了一半、中间夹着坏行：`/resume` 能接着用，坏行跳过并说出来（不是静默丢、不是崩）。
- `~/.zhiqu/config.json`、`.zhiqu/settings.json`、`.zhiqu/mcp.json`、`setup.json` 是半截 / 空文件 / 不是 JSON：
  启动不崩，说清哪个文件坏了、按什么处理（用默认值 / 忽略），不把坏文件悄悄覆盖掉（那可能是用户正在手改的）。
- 锁文件（`setup.json` 的 `wx` 锁）留在那儿、进程早没了：不卡住。
- 两个 `zhiqu` 同时在一个工作区里写会话、改设置：不互相写坏。

### 2 工作区里奇怪的文件
- 二进制文件（图片、zip、sqlite）：read_file / search 不把乱码塞给模型，说清是二进制。
- 很大的文件（几百 MB 的日志）：read_file 分段、search 不把内存吃满、不卡住。
- 文件名不是 UTF-8、带换行 / 控制字符、很长：列目录、搜索、写入都不崩，显示时不搞乱终端。
- 软链成环、目录很深：列目录 / 搜索不死循环。
- 没有读权限的文件 / 目录：说清楚，不崩。

### 修
照出来的都修，数量不设上限。

## 结果

### 1 坏掉的本地状态（真跑 `zhiqu -p`，假服务器）
- `config.json` 半截 / 空文件 / 手改多了个逗号：原来只说「还没登录」。现在先说哪个文件、错在哪、这次按什么处理、文件没动。
- **更糟的一条是改之前实测出来的**：环境变量里有 `ZHIQU_TOKEN` 时照常启动，启动时记 system.md 指纹会调 `saveUserConfig` ——
  坏掉的 config.json（里面有令牌和服务器地址）被换成两个指纹字段，没有备份、没有一句话。现在坏了的时候启动不写它；
  真要写（登录、/verbose、/window）先另存 `config.json.broken-<时间>`（一字不差）再写，并说出来。
- `.zhiqu/settings.json` 坏了：原来一声不吭（允许的命令悄悄不生效）。`mcp.json` 坏了原来就会说 —— 照它的样子改的。
- 这些警告原来只在交互横幅的末尾说，`-p` 单发一句都不说；挪到最前面，每种命令都说。
- 会话索引坏了：原来当成空的，下一次写就整个换掉，`/resume` 找不到记录还在的会话 → 从 `sessions/*.jsonl` 找回（标题取第一句用户的话，
  goal 推的那种不算）。会话记录里的坏行、崩溃留下的锁：以前就处理了（有判据）。
- 实验本身先骗了我一次：用 `spawnSync` 跑 zhiqu，假服务器在同一个进程里、事件循环被 spawnSync 卡住，请求一个都到不了 ——
  看起来像 zhiqu 卡死了 20 秒。改成异步 spawn。

### 2 工作区里奇怪的文件（直接跑 LocalTools）
- 图片改名成 `.txt`、带 NUL 的 js：原来读进来是六千个乱码字符 → 说清是二进制、不读。
- GBK 的中文 C 文件：第一版把它判成了二进制 → 按 GB18030 解码给模型看、说清编码；不许 write_file 改；搜索能搜到里面的中文。
- 300MB 的日志（.txt）：原来「超过 262144 字节的上限」，连最后几行都看不了 → 流式读开头 / 中间一段 / 最后 N 行（offset 负数），
  内存只多几十 MB；搜索在 264ms 里搜到第 7000001 行；不能改。
- 没有读权限：读文件原来抛出带绝对路径的原始错误 → 「没有读权限：secret.txt」；锁住的目录原来列成「（空目录）」→ 「没有读权限」；
  搜索跳过它们时说出来。
- 文件名里带 ESC / 换行：列目录、搜索结果里原样带着，打到终端就会被执行 → `termSafe`。
- 软链成环、150 层深的目录：本来就没问题（软链不跟随、深度有上限）。文件名不是 UTF-8：macOS 的文件系统直接拒绝创建（EILSEQ），没法造。

### 扰动
本地状态 8 + 奇怪的文件 21 处，全红。两处一开始是弱判据：「有 NUL」和「控制字节太多」两道二进制判定，测试样本同时满足两道，
删掉哪一道都有另一道替它挡着 —— 补了各自单独才能照出来的样本（一大段文字里只夹一个 NUL；没有 NUL、满是 ESC 的录屏）。
