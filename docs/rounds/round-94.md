# 第九十四轮（2026-11-02）：两份 coding agent 合成一份 —— 第 1 步：后端用子进程跑命令行那一份循环（开关后面）

## 由来
用户 2026-10-31：「……命令行和网页版两份 agent 合成一份。」第八十九轮锐评第 6 节：命令行（JS）和网页 code agent（Java `CodeWorkspaceAgent`）是两套循环、两套工具，
第八十六轮的删代码错两边都有，第八十七到九十二轮命令行放开、改进的东西（读成段、收尾提醒、温度、工具拆分……）网页那边要么没有、要么要再写一遍 —— 两份正在分叉。
2026-11-02 给了四种合法，用户选「**一份 JS，后端用子进程跑**」：网页 / 桌面应用的代码模式也跑命令行那一份循环，工具换成「写成草稿、照服务端的规矩执行」；
代价是后端那台机器要有 Node（桌面应用打进安装包、网页服务器部署要装）。

## 三步（照 Wiki 换编辑器的做法，一步一轮）
1. **第九十四轮（这一轮）**：JS 那边的「草稿模式」和宿主（`zhiqu-cli/src/host/`）、和后端之间的协议；Java 这边起子进程、接协议（`JsCodeAgent`），
   放在 `app.ai.code-agent.engine=js` 后面（默认还是 `java`）。工作区的读、列、搜、写草稿、改草稿、跑命令走通；Wiki 工具和「把里程碑排成任务」先不接。
2. **第九十五轮**：Wiki 工具（`search_wiki` / `read_wiki_page` / 判过题之后的 `create_wiki_patch`）和里程碑计划经桥回到 Java 执行；
   把 `CodeWorkspaceAgentTest` 里的情形逐条对一遍（两种引擎同一组输入）；真浏览器里两种引擎各跑同一组请求比；默认换成 `js`。
3. **第九十六轮**：删掉 Java 的循环（`CodeWorkspaceAgent` 只留门和桥）；桌面应用把 Node 和命令行的源码打进安装包、后端 JAR 带上命令行源码；网页服务器部署说明加 Node。

## 第 1 步的设计
- **谁管什么**：门（是不是管理员、工作区档位、有没有写意图、能不能执行、生产 profile）还是 Java 一处判（`CodeWorkspaceAgent.run` 前半段不动）；
  模型调用回到 Java 的 `HarnessModelGateway`（同一个进程里调，温度、输出上限、不思考、上下文裁剪和命令行完全一样）；
  **跑命令也回到 Java 的 `WorkspaceExecutor`**（服务器上执行命令只有这一处，行内代码开关、超时、输出上限、不继承环境变量都在它里面）。
  循环、提示、提醒、工具的参数和拒绝的说法、读文件读成段 —— 全是命令行那一份。
- **草稿模式**（`DraftTools`）：读、列、搜照旧直接读磁盘（规矩同一份 `conformance/workspace-rules.json`）；`write_file` / `edit_file` 不落盘，改动记在内存里的草稿层，
  之后读、改、搜同一个文件看到的是草稿（同一个文件改几处叠在一份草稿上）；没有 `delete_file`；跑命令时有没落盘的草稿就说出来（跑的是磁盘上的旧版本）。
  收尾时把草稿（路径、全文、读到时的指纹、是不是新建）交给 Java，照旧成一份 `CODE_DRAFT`，用户看过 diff 确认才落盘。指纹和 Java 的 `baselineOf` 同一个算法（文件字节的 SHA-256，没有这个文件是 `ABSENT`）。
- **协议**（一行一个 JSON）：Java → 子进程：`run`（工作区根、这句话、最近的对话、能不能写 / 跑、轮数上限、模型）、`event` / `error`（模型调用的回音）、`exec_result`；
  子进程 → Java：`model`（请 Java 调一次模型）、`exec`（请 Java 跑一条命令）、`step`（轨迹里的一句）、`result`（结论、草稿、用量）、`fatal`。
  子进程不继承环境变量；超时整组杀掉；协议里认不出的东西就停（不猜）。
- 判据先红；真浏览器里开关切到 `js`，用用户给的 key 让它改文件、跑测试，看轨迹、草稿、确认落盘。

## 结果
- **JS**：`LocalTools` 多一层草稿（`overlay`，命令行里是 null、一切照旧）：读、改、搜先看草稿，新建的草稿磁盘上没有也读得到、搜得到。
  `DraftTools`（`tools/drafts.js`）：写 / 改只记草稿（指纹是第一次改时磁盘上的，和 `baselineOf` 同一个算法）、没有删除、跑命令交回后端、有没确认的草稿时跑命令会说「跑的是磁盘上的旧版本」；
  只下发后端给的那几个工具（`allowedTools`）。环境说明换成草稿模式的一段（`environmentBlock({ draft })`：改动只成草稿、不要建临时文件、不接受行内代码），和上面说命令行的几句冲突时以它为准。
  宿主 `host/code-host.js`：一行一个 JSON 的协议，收尾交回结论、给最终回答用的上下文（每个工具的结果一段 + 结论）、草稿、写调用次数、用量；最后一行写完才退出。
- **Java**：`JsCodeAgent` 起 node（不继承环境变量：只给 HOME 和 PATH；超时整组杀；认不出的消息就停）；模型调用走同一个进程里的 `HarnessModelGateway`（模型由后端定，子进程给的不认），
  跑命令走 `WorkspaceExecutor`（不能执行时直接回拒绝），草稿路径照写入规矩再判一遍。`CodeWorkspaceAgent.run` 门判完、开关是 js 才交出去；起不来（没有 node / 脚本）照旧走 Java 的循环。
  开关 `app.ai.code-agent.engine`（默认 java）、`node`、`cli-dir`，生产模板同步。日志记每次跑命令的退出码、每轮收尾的轮数 / 草稿数 / 结论开头。
- 判据：命令行 6 条（草稿层、工具下发、协议、真起进程、认不出就停）；后端 `JsCodeAgentTest` 4 条（真起 node 跑真的循环；专门干坏事的假子进程：自己挑模型、不许执行硬跑、跳出工作区的草稿路径、
  环境变量 —— 不手写名单，现场量 node 在空环境下自己有的那几个当地板）、`CodeWorkspaceAgentTest` 1 条（门判完才交出去、不是管理员连起都不起、起不来退回）。
  扰动：JS 8 处、Java 7 处，全红。
- **真浏览器**（用户的 key、验证库、EXEC 档的临时工作区、开关 js）：「加 div、b 为 0 抛 ValueError，给测试加两条断言，跑一下」——
  轨迹是命令行的说法（读取 calc.py / 读取 test_calc.py 一轮并发、修改 calc.py、修改 test_calc.py），两份草稿 diff 对；它没跑测试，说「草稿确认之前跑的是旧版本，写进去后跟我说」——
  照草稿模式的规矩是对的。确认落盘后让它跑：经桥由后端的执行器跑 `python3 test_calc.py`，退出码 0。
- **点出来一个老错（两种循环共用的最终回答那一步）**：「写进去了，跑一下 test_calc.py 看看过没过」—— 句子里有写的词，写工具就下发了；循环只跑了测试、过了，
  最终回答却说「这一轮没生成草稿，所以没写入磁盘，请再说一次写进去」（两遍都是）。根子在 `CodeContextPrompt.dataBlock`：能写、没草稿就让模型说「没写成」。
  改成 `Result.writeAttempted`（这一轮真的调过写工具；Java 循环、JS 宿主各自报）—— 没试过写就照结果回答，不说没写成；试过写却没成照旧说。判据 3 处 + 扰动 5 处全红；重打后同一句话回答对了。
- **没做的 / 第 2 步要做的**：Wiki 工具和里程碑计划（开关是 js 时这一轮没有）；JS 那份的模型调用记进了命令行的用量表（`harness_usage`），网页的代码模式原来不记 —— 要不要分开记，第 2 步定；
  「再跑一下」时循环拿对话里上一次的结果回答、没有真跑（0 轮，说的是「刚才跑的是」）—— 第 2 步两种循环对着同一组请求比的时候一起看。
- 三组判据：后端全量 1340（0 失败、0 跳过）、命令行 277/277、评测工具 99 过 1 跳。
