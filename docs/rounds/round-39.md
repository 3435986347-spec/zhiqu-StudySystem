# 第三十九轮（2026-10-05）：页面切换流畅，文字一律系统无衬线字体

## 由来
用户 2026-10-05：「连续点击不同页面的时候有时候会出现一到两秒的卡顿」「就是页面切换非常不流畅」。
查的过程里用户又定了一件：「switch ui text to system sans-serif to all」（锐评界面时提到 Google Fonts 在这台机器的网络上很慢，见下）。

## 先量（开工前，第三十八轮做到一半插进来的）

账号里灌了「用了一阵子」的量（300 条任务、30 个例行计划、200 页 Wiki、一段 60 轮的对话）。用户说预览只用内置浏览器、不要弹窗口 ——
前半段用真 WKWebView 量过几次（桌面应用的引擎），之后全在内置浏览器里量。

- **每切一次页面都是「空白 → 淡入」**：主内容区在接口全回来之前一直藏着（`zq-booting`），揭开时 0.18 秒淡入，每页的内容外壳还有 0.3 秒的淡入上滑（`zqFadeIn`）。
  WKWebView 里每 50 毫秒截一帧：旧页 → 一帧白 → 只有侧栏、主区空白 100～250 毫秒 → 淡入。数据再快也是这样。
- **AI 助手（登录后的首页）最慢**：原来的代码点下去到看得到内容 0.82～1.32 秒（内置浏览器），这段时间主区一直空着 ——
  50 条消息一次排版，记录和右侧执行轨迹排着队取。
- **Google Fonts**：每一页都引它的样式表，挡渲染、也挡脚本执行。这台机器的网络（走系统代理）上，没缓存时样式表一次 1.3～2.7 秒、字体子集文件每个 1.4～5.3 秒（curl 实测）；
  有缓存时也量到过专注统计页的首次绘制整整等它 0.18 秒。「有时候卡一两秒」最像它。
- 本机数据库、远程数据库（加了单程 20 毫秒延迟的代理模拟）两种都量过：本机库时接口不是瓶颈；远程库时看板 0.7 秒，几乎全是串行的请求在排队。

## 计划

1. **页面一打开就露出自己的骨架**（标题、按钮、表头），数据到了填进去。遮罩只留给「可能马上被送走」的页面：后台页（普通用户会被劝返）和两个旧地址的跳转页。
   去掉每页内容外壳的 0.3 秒淡入上滑。
2. **页面之间的切换**：`@view-transition { navigation: auto; }` —— 新页面画好之前一直显示旧页面，再用 0.12 秒交叉淡化换过去；侧栏单独成组、不动。不认这条的浏览器照常整页切换。
3. **左下角的名字、头像**：上一页画过的先画上（按令牌认，换账号不认），不再每页先空一下再冒出来。画法收成 `zhiqu-ui.js` 的 `paintUser` 一处。
4. **AI 助手**：聊天记录到了才画「可以这样开始」（原来模型列表先回来时会先闪一下空状态）；跟着底部时，公式排完、图片到了也留在底部（原来排完公式往上跳一截）。
5. **互不依赖的请求一起发**：看板的总览与番茄钟两块、专注统计的总数与趋势、AI 助手的聊天记录与执行轨迹。
6. **文字一律系统无衬线字体**（用户定的）：去掉 Google Fonts；正文、标题、Wiki 正文、数字都用系统字体（苹方 / 微软雅黑 / 系统 UI 字体）；
   数字用等宽数位（`font-variant-numeric: tabular-nums`）对齐，不再用等宽字体。等宽只留给代码：代码块、diff、文件路径、命令、工具输出、Wiki 源码编辑器。
7. **判据**：骨架不遮（在 node 里跑发布的 `zhiqu-ui.js`：后台页遮、普通页不遮 —— 第一版把判断放在 `NAV` 定义之前，`NAV` 还是 undefined，抛了被 try 吞掉，后台页就不遮了，
   源码判据看不出这种错）；没有页面再引外网字体；字体令牌里没有衬线；页面外壳不带淡入；切换的那几行 CSS；三处请求并行；空状态等记录；跟着底部；左下角的缓存按令牌认、名字转义。各自扰动见红。
8. **暴力测试**：内置浏览器里连续快速切页面（含 AI 助手、Wiki、看板），量「点下去 → 骨架」「点下去 → 数据画完」；AI 助手往上翻历史、加载更早的消息不跳。

### 怎么验
内置浏览器实测（前后对比同一账号、同一顺序）；全量通过、扰动见红；桌面应用重新打包。

## 结果（2026-10-05 ～ 10-06）

照计划做完。

**前后对比**（内置浏览器、同一个灌了量的账号、同一个切换顺序，「数据画完」= 页面启动收尾时打的 `zq-boot-done` 标记；原来的代码从 JAR 里解出来、加上同一个标记，跑在 18081）：

| 页面 | 原来：点下去到看得到内容 | 现在：骨架 | 现在：数据画完 |
|---|---|---|---|
| AI 助手 | 0.82 / 1.32 秒（之前全空白） | 约 0.08 秒 | 0.40 / 0.67 秒 |
| 看板 | 0.30 秒 | 约 0.09 秒 | 0.19 秒 |
| 任务 | 0.12 秒 | 约 0.08 秒 | 0.11 秒 |

- **骨架先露**：`zhiqu-ui.js` 的 `holdsUntilBoot` 只给后台页和 `profile.html` / `achievement.html` 加遮罩；去掉了 11 个页面内容外壳上的 `zqFadeIn`。非管理员直达后台页照旧劝返、不闪后台的骨架（实测）。
- **切换**：`@view-transition`、侧栏单独成组不动、0.12 秒、系统设了「减少动态效果」时关掉。
- **左下角**：`paintUser` 一处画（壳的 `updateSidebarUser` 交给它），记在 sessionStorage、按令牌末尾认；令牌本身不进记录。
- **AI 助手**：`historyLoaded()` —— 这个 notebook 的记录到了才画空状态（切 notebook 时同理）；`keepPinned` 用 `ResizeObserver` 盯每条消息的高度，只在跟着底部时拉回底部。
  用真滚轮往上翻：每次 10 格稳稳往上 1000 像素，不被拽回底部。
- **并行**：看板（总览 ∥ 番茄钟任务下拉 ∥ 今日计数）、专注统计（总数 ∥ 趋势，趋势的失败另接住，免得总数先失败时多弹一句）、AI 助手（记录 ∥ 执行轨迹）。
- **字体**：14 个页面去掉 Google Fonts 的三行 `<link>`（共 32 行）；`--zq-fontBody` 换成系统无衬线（-apple-system / 苹方 / 冬青黑 / 微软雅黑 / Segoe UI / 思源黑体 …）；
  `--zq-fontM` 的中文回落也换成无衬线；新加 `.zq-num`（正文字体 + 等宽数位），34 处数字、日期、时间从 `.zq-mono` 换过来（看板大数字、番茄钟、统计、后台指标、各处日期）；
  等宽字体留给代码：代码块、diff、文件路径、命令、令牌前缀、工具输出、工作区搜索结果、Wiki 源码编辑器、执行轨迹里的 agent 类型、管理员发的临时密码（区分 1/l、0/O）。
- 另外留了一个量时间用的标记：`route()` 收尾时 `performance.mark('zq-boot-done')`。

**试过又撤掉的**：AI 助手的消息加 `content-visibility: auto`（看不见的不排版）—— 50 条长消息时数据画完从 0.40～0.67 秒降到 0.18～0.20 秒，
但「↑ 加载更早的消息」之后正在看的那条被推下去 3000 像素（原来的代码照样停在原位，同样的步骤对比过）。撤了；长历史的排版开销留作以后。

**没做完、说清楚的**：
- 用真 WKWebView 量的时候，「新开的数据区第一次跳转」偶尔整整等 1 秒才开始建新页面（原来的代码也有，像是 Service Worker 第一次安装）；用户已经装着的应用里不会每次碰到，没再追（用户要求不弹窗口，WebKit 专有的问题没法在内置浏览器里量）。
- Google Fonts 是「有时候卡一两秒」的主要嫌疑（这台机器的网络上没缓存时一次 1.3～2.7 秒、挡渲染挡脚本）；去掉之后这条路不在了，但用户那一侧的卡顿没法直接复现确认。

**判据**：`PageSwitchSmoothnessTest` 七条（其中「骨架不遮」在 node 里真跑发布的 `zhiqu-ui.js`：`ui-shell-check.js`，16 条）；`MainFlowWalkthroughTest.AI助手的空状态` 加两条；
`AiReadTasksWiringTest` 的锚点换成并行那一行。跟着改的：`PositioningCopyTest`（「成就不在导航里」只看 `NAV` 那一段 —— 原来扫整个文件，新代码里认旧地址跳转页的 `'achievement.html'` 让它红了）、
`SettingsDialogTest`（名字从 `paintUser` 记到按钮上），两处改写都扰动见过红。
扰动 15 个全红：遮罩判断放回 `NAV` 之前（正是第一版的错，红在「后台页没遮」）、每页都遮、不认令牌、名字不转义、又引 Google Fonts、正文换回衬线、看板大数字用回等宽、外壳又淡入、
去掉页面过渡、看板 / AI 又串行、趋势的失败没人接、往上翻也拽回底部、记录没到就画空状态、不记「记录到了」。

**暴力测试**：内置浏览器里不等加载完连续切 10 个页面（看板、AI、任务、Wiki、AI、例行、参考计划、统计、AI）→ 停在 AI 助手、50 条消息、在底部、没有空状态、左下角名字在、控制台没有页面脚本的报错、没有外网字体请求。

**验**：全量 972 / 0 / 0 / 0（开着 Docker）；桌面应用重新打包。验证用的账号 `nav39_*`（300 条任务、200 页 Wiki、120 条消息）留在 `zhiqu_verify` 里由用户删。
