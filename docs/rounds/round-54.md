# 第五十四轮（2026-10-09）：AI 助手 —— 桌面应用里一问要等几分钟（命令行很快）、「输出额度全用在了思考上」

## 由来
用户 2026-10-09「继续」+ 截图 + 命令行记录：③ AI 助手报「⚠ 模型把这次的输出额度全用在了思考上，没来得及写回答」（DeepSeek、深度思考、代码模式）；
④「每次在desktop app里面都要等待好几分钟，在cli里面就很快」。同一个模型（deepseek-v4-pro）。

## 先量（假模型记下每一次调用：时刻、带没带思考、max_tokens、是哪个 agent；每次 3 秒，模拟一个慢模型）
- 一句普通的话：**三次模型调用排成一串** —— 检索改写（资料里没命中就换个说法再搜）→ 写回答 → 对话摘要（每十条一次）。第一个字要等两次、done 要等三次。
- 深度思考：只有写回答那一次带 `thinking: enabled`；**`max_tokens` 写死 4096** —— 思考也算在里面，DeepSeek 想完 4096 就没地方写回答（③ 就是这个）。命令行是 16384。
- 代码模式：同样先改写一次检索（「帮我写个动画」并不是在资料里找东西），code agent 的工具轮之后再单独写一次回答。
- 翻代码时看出来的：**网页 / 桌面应用里有三处请求不说「思考不思考」** —— code agent 的工具轮（`ModelProviderClient.callOpenAiToolTurn`）、拆计划（`callStudyPlanToolCall`）、看图（`callAiApiWithVision`）。
  DeepSeek 不说就默认想；**命令行一直明说不要思考**（`HarnessModelGateway`：`thinking: disabled`）—— 第十二轮用户就说过 v4-pro 在命令行里「一直在思考循环」，那次在命令行这边关掉了，网页这边的工具轮没跟上。
  用户的「代码」开关是记住的，于是桌面应用里每问一句，code agent 的每一轮工具调用都要想上一阵 —— ④ 的主因。

## 做了什么
1. 那三处明说不要思考（和命令行一样；用户按的「深度思考」管的是写回答那一次）。`AiServiceImpl` 里私有的那份 `applyOpenAiReasoningOptions` 和 `AiStreamAdapterSupport` 的公有那份做的是同一件事，删掉私有的、都用公有的。
2. 写回答那一次的输出上限和命令行同一档：`OutputLimits.ANSWER_MAX_TOKENS = 16384`，供应商不收（说的是上限太大）就降 8192、4096 —— 这套回退原来只在命令行的网关里，挪到 `OutputLimits` 两边共用。OpenAI 兼容和 Anthropic 两个回答流都用它。
3. 按下「代码」时不做检索改写（少一整次模型往返）。

## 判据
- `ModelProviderToolTurnTest` 加一条：DeepSeek 的工具轮发出去的请求体里 `thinking.type == disabled`（真的 HTTP）；不是 DeepSeek 不带 `thinking`。
- `AnswerOutputLimitTest`（新，真的 HTTP）：深度思考一次给 16384、明说要思考；不收就降一档拿到回答；不是在说上限的 400 不重来；Anthropic 同一套。
- `ModelRequestThinkingTest`（新）：把发给模型的每一处（13 处）全数出来、归类，OpenAI 兼容的每一处都要说思考不思考 —— 新加一处没归类就红，逼着人决定；代码模式不改写检索。
- 扰动 9 个全红：工具轮不说、拆计划不说、看图不说、多一处发请求没归类、代码模式照样改写、回答又是 4096、不收也不降、什么 400 都降、Anthropic 不降。

## 复测（同一个假模型）
- 普通的话：写回答那一次 `max_tokens` 16384（原来 4096）；改写照旧在前面（资料里没命中时，这一趟还在 —— 见下面「没做的」）。
- 代码模式 + 深度思考：不再改写，**第一个字从两次调用之后提前到一次之后**（3 秒假模型：6.1s → 3.1s）。
- 工具轮不思考：内置的验证服务没开代码工作区，跑不到工具轮 —— 由上面那条真 HTTP 的判据管。

## 没做的（记下来）
- 普通聊天里资料没命中时的那次改写还在（资料库里本来就什么都没有时它白跑一趟）—— 要判断「这个人有没有能搜的东西」，另一件事。
- 每十条一次的对话摘要排在 done 前面（多等一次调用）—— 它要和这一条消息一起落库，挪到 done 之后要动收尾的事务，另一件事。

**验**：全量 1029 / 0 / 0 / 0（开着 Docker）；桌面应用重新打包（后端改了，跟着 jar 走）。用户那台 Mac 要换成这次的包才看得到。
