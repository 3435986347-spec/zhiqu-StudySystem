# 第六十八轮（2026-10-15）：恢复点击编辑、只读开关与页面流畅度

## 用户问题与计划

- 用户纠正只读模式的交互：沿用原先点击正文即可编辑，只增加默认关闭的只读开关；打开开关后才禁止编辑，保留原保存/取消。
- 长标题导致编辑工具栏换到下一行后靠左；工具栏无论是否换行仍靠右。
- Wiki 与其他页面存在明显卡顿，排查共享输入事件、页面加载、渲染及桌面 WebKit 路径，以合成数据对照实际开销，按证据修复。
- 保留草稿、乐观锁、异步回执与链接/附件交互，不访问用户真实 Wiki、数据库、内网资料或模型；不下载、安装 Docker。
- 必要行为判据先红后绿；真实浏览器快速操作与 WebKit 验证；同步缓存、截图和 round，review 后提交推送。

## 实现与验证

### 只读是可选开关，保留原来的编辑方式

- 只读开关默认关闭。点击正文继续直接编辑，标题可直接改名，格式工具、任务勾选沿用原入口，原有保存与取消保留；不再要求先点「编辑」按钮。
- 打开只读后禁止正文、标题、任务、格式、源码和图片粘贴 / 拖入等修改入口。已有未保存内容保留在原 DOM 中并存本地草稿，不自动提交；关闭只读后可继续编辑。源码锁定沿用同一个 textarea，保留文字和选区。
- 保存与只读开关相互独立：用户仍可明确保存锁定中的草稿，保存不会替用户关闭只读；失败保留草稿。保存期间开关只读、又继续输入等回执竞态分别处理，未再修改的已保存草稿能正常清理，较新的输入会保留并更新版本基线。
- 开关切换使旧编辑上下文失效，迟到的插入链接 / 改名弹窗、冲突确认不能修改新会话；切页加载时仍阻止把旧正文编辑进新页面。引用笔记中的任务控件保持禁用。
- 只读锁定未保存内容时，内部 Wiki 链接仍支持单击、Enter、中键和修饰键跳转；编辑未锁定时继续保留编辑链接文字的原行为。
- `wiki-readonly-check.js` 的 21 组行为判据全绿；旧实现先出现真实断言失败，新增草稿、源码、会话失效等边界用独立扰动副本逐一见红。保存与开关竞态另有红绿对照。`wiki-link-routing-check.js` 的 10 组包含锁定草稿的三种链接入口，也有先红后绿记录。

### 长标题换行后的工具栏位置

- `.zq-wiki-tools` 增加 `margin-left:auto` 和右对齐，约束可用宽度；标题占满上一行后，工具栏仍靠右，窄容器中可自行换行。
- 隐藏的真实 WKWebView 使用发布页面的标题 / 工具栏片段，仅替换合成标题。旧 CSS 在 1120px 容器、长标题换行后留下 **550px** 右侧空隙，断言确实失败；修改后空隙为 **0px**。短标题 1120px、长标题 320px 两组也均为 0px，三组横向溢出均为 0px。判据接入 `DesktopWebKitLayoutTest`。

### 公共滚动监听与页面加载

- 全站 tooltip 的 `wheel` 回调只关闭提示，不调用 `preventDefault`，却注册为没有 `passive` 的捕获监听。本轮显式使用 `{capture:true, passive:true}`，让 WebKit 无须为了这段回调等待主线程后再开始滚动。`ui-shell-check.js` 真实运行发布脚本，旧版 `passive=undefined` 产生 AssertionError，修后 Wiki、AI 助手、任务页三组注册与提示关闭行为全绿；原面板动画的 10 组行为也通过。
- 普通业务页的模块代码加载与登录校验并行，业务启动仍等待登录成功；后台模块继续等服务端确认管理员身份后才加载。模块加载拒绝会被及时接住，不产生未处理的 Promise 拒绝，不重复加载或重复报错；首页、旧跳转页及缺少 UI 帮助器的保守路径保留。
- `PageStartupTest` 调用的 8 组行为判据，旧版 2 组真实断言失败，修改后 8 组全绿。鉴权后启动、后台不预载、提前失败有处理、复用预载、鉴权失败不启动、旧地址先跳转、缺少 UI 的保守路径再分别做 7 份独立副本扰动，均为对应 AssertionError 红。独立复核另加登录与模块同时失败、模块在登录完成后失败、后台登录失败三种边界，均通过。
- 真实内置浏览器用合成服务固定登录响应 **300ms**、页面模块 **350ms**，统计页三次到业务启动：修改前 **699 / 731 / 718ms**，修改后 **386 / 428 / 431ms**；中位数由 **718ms** 降到 **428ms**。这只说明此受控慢加载场景减少了串行等待，不能据此推断所有设备或所有页面都快约 40%，也不代表所有卡顿已解决。
- 公共 UI 未发现持续 DOM 扫描或 MutationObserver；未根据猜测修改 blur 或侧栏动画。

### Wiki 附件完成后不再反复扫描全文

- 每个引用预览就绪事件原先都扫描整篇正文、重绑全部双链并重设任务状态。现在只初始化该预览子树，正文的外部链接委托仍只绑定一次；只读开关的全文状态同步保留在切页和切换开关等实际需要的位置。
- 多个预览同批就绪时，只安排一次下一帧的视口恢复；执行时重新读取当前恢复请求，校验页面、登录身份和有效期。用户滚轮、点击、触摸和键盘输入仍立即撤销待恢复位置，避免迟到预览把用户拉回旧位置。
- `wiki-embed-ready-check.js` 10 组，旧版 9 组真实断言失败、新版全绿，页面/登录/过期/脱离根等守卫逐个扰动见红。独立复核只读 21、嵌入 10、内链 10、外链 9、编辑稳定 10 组通过；另验证事件目标本身是链接或任务框、锁定草稿中的新预览、各种用户输入中断恢复等 4 组边界。
- 隐藏真实 WKWebView：1000 条父页双链、32 个媒体各触发 3 次完成事件（共 96 次），旧版处理耗时中位 **44ms** / 最大 46ms，产生 **192 次**全文扫描；新版中位 **<1ms** / 最大 1ms，全文扫描 **0 次**。这是该批事件处理开销，不是整个知识页加载时间。
- 未改目录渲染和所有 Markdown 解析器；合成量测中 100 页目录约 1ms，普通约 96k 正文解析约 5.7ms，尚无依据为了这次卡顿替换它们。超大库/超长页仍可能有额外布局开销。
