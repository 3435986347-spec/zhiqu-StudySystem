# 第五十六轮（2026-10-10）：界面打磨第 8 步（一）—— 例行计划页

## 由来
用户 2026-10-09「继续ui」：第 7 步（第五十五轮）之后接着第 8、9 步。第 8 步「其余页面」一共六处（例行计划、参考计划、专注统计、设置 / 成就弹窗、后台四页、落地页），一轮做不细，
分三轮：这一轮例行计划；第五十七轮参考计划和专注统计；第五十八轮设置 / 成就弹窗、后台四页、落地页。

## 现在是什么样（验证账号：31 个例行计划、300 个任务；今天 2026-10-10 周六）
- **天天要看的东西在最底下**：页面从上到下是「从任务生成」（一大块：任务列表 + 灰底的设置）→「新建例行计划」表单 →（右下半边）「我的例行计划」。31 个计划的列表在 1440 宽时第一屏只露出四条。
- **两张表单各问各的**：「从任务生成」能选星期、偏好时间、早间提醒；「新建」没有这三样 —— 选「每周」也选不了哪几天（服务端悄悄按今天是星期几定），时间一律 08:00。
  星期按钮不管选的是「每天」还是「每周」都在那儿。
- **「标记完成」给了不该给的**：每个在日期范围内的计划都给「标记完成」，不管今天轮不轮到它。今天周六，「每周一、三、五」的点下去服务端回「该日期不在例行计划范围内」，
  右上角报错（没包 `safe`，靠壳的 `unhandledrejection` 兜底说出来 —— 我起初以为只进了控制台，是我查提示框的选择器没对上；更正在这里）。按钮本来就不该在那一行上。
- **今天做没做看不出来**：列表不读打卡记录，点过「标记完成」之后那一行还是原样；要去看板才看得到。
- 三张卡标题上面都压着一行小字（「从任务生成」「新建」「进行中」）；每一行都摆着「标记完成」「删除」两个字按钮（31 行 62 个）；星期按钮、任务行、计划行的样子都是 JS 里拼的内联样式（这一页 62 处）。

## 计划
1. 页头：右边两个按钮 ——「从任务生成」（次）、「新建例行计划」（主），各开一个弹窗；页面本身只放两块：
   - **今天**：今天轮到的（`/routine/instances` 今天一天），和看板「今天」一个画法（时间、名字、频率 · 时长、「完成 / 已完成」），按服务端给的打卡状态画；没有轮到的就说「今天没有要做的例行计划」。
   - **全部例行计划**：一条一行（时间、名字、频率 · 时长 · 没开始 / 已结束），进行中的在前、没开始的、已结束的（变淡）在后；删除是悬停才出现的图标按钮（和任务页一样）。
2. 新建和从任务生成用同一套设置：频率（每天 / 每周 分段）、星期（只在「每周」时出现，默认勾上今天是星期几 —— 和服务端不填时一样，只是说出来）、时长、偏好时间、提醒、开始 / 结束日期（新建才有；结束不填按 30 天，写在框里）。
   标题、说明的草稿照旧留着（刷新不丢），建好清空、弹窗关上；从任务生成一次生成好几个，按钮在提交时变「生成中」不让连点。
3. 「完成」「删除」都走 `safe`（不靠兜底），「完成」提交着时按钮不让再点。
4. 内联样式挪进样式表（`.zq-rt-*`、星期按钮用 `.zq-chip[aria-pressed]`、分段用 `.zq-seg`）；JS 只管类和 `aria-*`。
5. 判据：例行计划页的画法在 node 里真跑（今天的列表按打卡状态画、全部的排序和阶段、两种设置读出来的提交内容、每周不选星期不让交、失败走 `safe`）；页面结构（页头两个按钮、没有小字眉标、没有内联样式）；跟着改那几条钉住旧写法的判据（`InitErrorReplacesDemoContentTest` 的星期按钮、`InlineFormResetTest` 的清空）。扰动见红。
6. 真浏览器：1440 / 960 / 手机、浅 / 深截图；暴力：连点「完成」、弹窗里连点「创建」、一次勾 20 个任务生成、跨零点（dayReload）。全量；桌面应用重新打包。

## 结果

**做了的**
1. 页面只放两块：**今天**（`/routine/instances` 今天一天，和看板「今天」同一套 `.zq-agenda-row`：打过卡的变淡、按钮写「已完成」，打卡记到那一行的日期；头上「1 / 18 完成」）和**全部例行计划**（进行中的按时间在前、没开始的写「10/12 开始」、已结束的变淡写哪天结束；删除是悬停才出现的图标按钮，手机上一直在）。
   两块用 `auto-fit` 并排，各不到 300px 就一上一下（最窄的桌面窗口 960 里各 333px，还是并排；手机上一上一下）。名字最多两行，再长的悬停看全。
2. 页头右边「从任务生成」「新建例行计划」两个弹窗，同一套设置（`settingsHtml`）：多久一次（每天 / 每周分段）、每周哪几天（只在「每周」时出现，默认按下今天是星期几，选上的是实心的）、几点做、每次多久、早上提醒；新建另有名字、说明、开始 / 结束（结束不填按 30 天，写在框上）。
   读表单（`readRoutineForm`）不对就说：没名字、每周一天都没选（原来服务端悄悄按今天定）、时长不是 1–1440 的整数、时间没填、结束在开始之前。
3. 新建：提交着不让再点，建好才删草稿、关弹窗；没建上弹窗不关、草稿留着。从任务生成：按钮写「生成 N 个」、提交着写「生成中…」，生成一个去一个勾；中途失败说「生成了 k 个，后面的没成」，已经生成的那几个不会再来一遍。
4. 「完成」「删除」都包在 `safe` 里；「完成」提交着不重发。（原来没包：失败靠壳的 `unhandledrejection` 兜底说出来 —— 起初我以为只进了控制台，更正见上面。）
5. 页面和模块里没有内联样式了（这一页 62 处）；样子在 `.zq-rt-*` / `.zq-page-stack`（以后几页也用）/ `.zq-chip[aria-pressed]` / `.zq-seg`。全站内联 `style=` 664 → 602。页头说明换成办公的说法（「每天写日报、每周复盘……」，原来是「背单词」）。缓存令牌 `20261010-routines`。

**判据**
- `routines-check.js`（由新的 `RoutinesLookTest` 调用，import 发布的模块、壳用替身）：六段 —— 今天按打卡状态画 / 记到那一行的日期；全部的排序、阶段、没有打卡按钮、删除是带名字的图标按钮；两种设置读出来的提交内容和各种不让交；默认按下的星期在 UTC+14 和 UTC−10 都对；
  两个弹窗真点（连点三下只发一次、建好才清草稿、失败不关；生成中途失败说出几个、去掉已生成的勾）；「完成」「删除」走 `safe`、「完成」不重发；零点只重新取「全部」和「今天」。
- `RoutinesLookTest` 另外两条：页面（页头两个按钮、两块、没有小字眉标、没有常驻表单、没有内联样式）；模块不写样子（不拼 `style=`、不改 `.style.`；选上的星期、悬停出现删除、手机上一直在，三条样式在）。
- 跟着改的：`InlineFormResetTest` 删了（表单不常驻了，「建好清空 / 生成完去勾」换成 routines-check.js 里真点）；`RoutinePhaseTest` 里钉旧源码的「只给进行中的标记完成」挪进 routines-check.js；`routine-phase-check.js` 零点那段挪过去；
  `InitErrorReplacesDemoContentTest` 的「星期按钮 7 个」挪过去（现在在弹窗里真点）；`FrontendTokenAndDateTest` 的「日期输入框不写死日期」连脚本一起扫（例行计划的日期框在弹窗里了）；`DesignTokensTest`（70 → 60）、`MobileLayoutTest`（18 / 11 → 12 / 8）两个「没扫空」的下限跟着内联样式往下走，理由写在旁边。
- 第一次全量红了一条我该先查到的：`LatestResponseTest` 按名字钉着 `loadRoutineSources`（判据纪律第 7 条 —— 搬代码之前拿字面量对一遍 `src/test`，这次没对）。
  弹窗里取任务的 `loadSources` 改回那个形状（先领 `latestOnly`、`await api.get`、`if (!current()) return;`，外面包 `safe`），判据的名单换成 `loadSources` 并加上 `loadRoutines`（打卡后、零点时都会再取；它用 `Promise.all` 取两样，判据认这种写法）；两处去掉 `if (!current()) return;` 各自见红。
  真浏览器里「待办 → 进行中 → 待办」连点，留下的是最后点的「待办」。
- 扰动 18 个全红，模块里的 15 个逐个看过是红在该红的那一条上（比如「星期几按浏览器时区算」只有 UTC−10 那条红 —— 两个时区都要有）。
