# 第一百零五轮（2026-11-05）：工作区左侧那块去掉、选文件夹弹系统框、档位放到输入框下面

## 由来
用户 2026-11-05：「1.ai助手左侧下面的工作区去掉，不要显示。2.点击选择文件夹应该直接打开系统的文件夹和文件页面。3.点击档位切换的时候会有明显卡顿，同时三个档位应该放在输入框下方，点击向上拉起切换档位的面板。」
- 卡顿量过：切一次档位连发 3 个请求（切换 → 再读设置 → 再读文件树），本地一共约 60 毫秒，但用户的库在远程，每个都要多走一趟；回来以后左侧文件树整块重画。切换接口本身就回新状态，后两个都用不着。

## 计划
1. **左侧「代码工作区」整块去掉**：HTML、文件树 / 搜索 / 看文件的代码、样式一起删（后端接口留着，确认草稿时还要读文件）。`#zq-code` 的显隐搬到那一条上。
2. **选文件夹弹系统框**：后端和用户在同一台电脑（工作区只在回环地址生效），`POST /api/workspace/pick-folder`（管理员 + 回环）起系统自带的小程序弹框：macOS `osascript choose folder`、Windows PowerShell `FolderBrowserDialog`、Linux `zenity`。
   网页版和桌面应用同一条路，外壳不用改、不用重打包。路径不拼进脚本（走参数 / 环境变量）；一次只开一个；10 分钟没选就关；选完校验是存在的目录。弹不了（Linux 没装 zenity）就说清楚，退回页面里的选择器。
3. **档位放到输入框下面**：工具条上一个按钮显示当前档位，点开向上拉起面板（四档，每档一句说明），选了面板马上收、名字马上变，只发一个请求，后端回的状态直接画。在途时最后点的生效、失败退回后端说的（第一百零三轮那两条留着）。
   用户这次说「三个档位」，之前定的是四个（close / plan / manual / auto），没说去掉 close，先留着、告诉用户。
4. 判据先红；真浏览器里点、量请求数、手机宽度。系统框是真弹窗（`no-popup-windows`：不擅自弹），假脚本验流程和各种结果，`osacompile` 验脚本能编译，真弹让用户点一次。换缓存令牌。

## 做到一半用户又说
- 「就是点击上传文件的时候会弹出来的那种」：选文件夹就是要系统的选择框，不是页面里的。
- 「同时代码按钮删掉，感觉多余了」：计划第 1 条「`#zq-code` 的显隐搬到那一条上」作废，按钮连同它记在 `zq.codeMode` 里的按下状态一起删。

## 结果
- **左侧「代码工作区」整块没了**（HTML、文件树 / 搜索 / 看文件的代码、样式）。`/workspace/files`、`/search`、`/status` 页面不再用，接口留着。
- **档位放到输入框下面**：工具条上「附件」旁边一个按钮写当前档位（close / plan / manual / auto），点开向上拉起面板，每档一句说明；项目按钮留在输入框上方。用户说「三个档位」，之前定的是四个，没说去掉 close（去掉就没有关的办法了），留着。
- **卡顿**：改之前切一次连发 3 个请求（PUT 20–48ms、再读设置 6–8ms、再读文件树 6–8ms），回来以后左侧文件树整块重画；用户的库在远程，每个请求都多走一趟。
  改之后点下去 2–4 毫秒面板收起、名字变好，只发 1 个 PUT（31–48ms），回的状态直接画；在途时最后点的生效；失败重新读一遍。
- **选文件夹弹系统框**：`POST /api/workspace/pick-folder`（管理员 + 回环），`WorkspaceFolderDialog` 起 macOS `osascript choose folder` / Windows `FolderBrowserDialog` / Linux `zenity`。起始路径走环境变量、不拼进脚本；一次只开一个；10 分钟没选杀掉；选完校验是存在的目录；取消什么都不改；弹不了（比如 Linux 没装 zenity）退回原来页面里的选择器。前端这一个请求单独等 11 分钟（`request()` 加 `timeoutMs`，默认 30 秒等不到用户选）。网页版和桌面应用同一条路，外壳不用改。
- **「代码」按钮删了**：`codeModeOn()` 改成看 `wsStatus.enabled` —— 档位开着（生效了）每句都带 `codeMode: true`，close、没生效、不是管理员都不带；切到 close 不等回包马上算关。**这是个取舍**：原来开着工作区也可以普通聊天（不按按钮），现在档位开着每句都走代码模式，想普通聊天切到 close。写工具照旧由档位卡在后端、改动照旧先成草稿。工具条省出 32px，手机上模型下拉从 33px 宽到 69px。
- 真浏览器（验证库，`http://localhost:18082`，发送在发出之前拦下、不花模型的钱）：auto 发的一句 `codeMode: true`；切到 close 紧接着发的一句 `false`；切回 plan 等回包后发的一句 `true`；没有 `#zq-code`、左侧没有 `#zq-ws`；面板 `[415,541]–[775,767]` 贴在输入框上方、4 项、当前项 `aria-checked`；点别处收起；手机 375 宽不横着滚、面板 `[69,362]` 不出界。系统框换成假回包走过：取消什么都不改、选了发 PUT、没有页面里的选择器。测完工作区恢复成测试前的 ws-web + auto。
- **没验的**：真的系统框没有弹过（`no-popup-windows`：不擅自开窗口），macOS 的脚本用 `osacompile` 编译过、流程用假脚本走过（选了 / 取消 / 没装 / 报错 / 超时 / 同时两次）；Windows、Linux 的命令只钉了长相，没有真跑。要用户点一次。桌面应用要重打包才用得上：后端的新接口跟着 JAR 走（外壳不用改）。
- 判据：`ws-bar-check.js`（抠发布的那一段真跑，17 条）、`WorkspaceFolderDialogTest` 9 条、`AiComposerTest`（项目在上档位在下、面板向上拉起）、`CodeModeToggleWiringTest`（请求体带 `codeModeOn()`、按钮和记的状态都没了）、`request-check.js`（`timeoutMs`）、`WorkspaceControllerGuardTest`（弹框要回环）。
  扰动 51 处全红（档位条 28、`codeModeOn` 2、系统框 17、`timeoutMs` 1、样式 2、按钮放回 1）。头一遍有 3 处不算数：点当前项目那处没红（补了样本）；到时间不杀那处没红（原来只看返回值，补了「进程真的没了」）；`timeoutMs` 那处的「红」是判据脚本自己炸了（替身写错，修了再扰动，这回红在那一条上）。
- 真浏览器里还发现：全站 `button{white-space:nowrap}` 让面板里长的那句说明伸出面板，改 `white-space:normal`（`AiComposerTest` 钉着）；面板不能以 `.zq-tier-pick` 为定位容器（窄屏出界），改以输入框为准。
