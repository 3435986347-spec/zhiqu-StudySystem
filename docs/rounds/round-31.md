# 第三十一轮（2026-10-04）：后台四页拆成模块（方案第 4 步的第二块）

## 由来
方案第 4 步：`zhiqu-api.js` 按页面拆成原生 ES 模块（不引入构建步骤），公共层 + 每页一个模块，每页只加载自己的模块。
第三十轮做了第一块（设置 / 成就弹窗 → `assets/settings.js`，共用层 `zqShared`）。这一轮做第二块：**后台四页**（监管后台、账号管理、
反馈管理、共享计划审核）。挑它的理由：自成一块（只有管理员用）、普通用户从此不下载这段代码、而且它要立起「页面模块」这个形状 ——
之后的统计、例行计划、任务、看板、参考计划、Wiki、AI 助手都照这个形状一页一页搬。

## 计划（开工时）

1. **页面模块的形状**：`assets/pages/<名字>.js`，导出 `boot(sh)`；壳的 `route()` 里，搬走的页面不再在 `boots` 表里，而在一张
   「页面 → 模块」表里，`import()` 之后调 `boot(zqShared)`。地址带壳自己的 `?v=`（和 settings.js 同一个取法，收成一个函数）。
   后台页的门（`ZQUI.isAdminPage` + 服务端角色）照旧在加载模块**之前** —— 普通用户直达后台页时连模块都不下载。
2. **挪**：`bootAdmin`、`bootAdminIssues`、`bootAdminRag`、`bootFeedbackAdmin`、`bootAccountAdmin`、`bootSharedPlanAdmin` 和只有它们用的
   助手函数进 `assets/pages/admin.js`。和参考计划页共用的东西（分类表、频率说法……）留在壳里经 `zqShared` 给。挪，不重写。
3. **模块加载失败要说出来**：断网 / 服务器正在重启时 `import()` 会失败 —— 页面换成和「加载失败」一样的错误卡片（`renderInitError`），
   不是一片空白。
4. **判据**：钉在这几个函数上的旧判据跟着搬（读模块）；页面模块表里的每个文件都存在、都导出 `boot`；模块只用 `zqShared` 给了的东西
   （和 settings.js 同一条判据，改成扫 `assets/` 下全部模块）；后台页的门在加载模块之前；离线缓存里有它。
5. **暴力测试**：普通用户直达四个后台页（不下载模块、劝返）；管理员逐页打开、真点（禁用 / 启用一个测试账号、处理一条反馈、审一个参考计划）；
   模块加载失败（把模块地址弄坏）时的样子；刷新、来回切。

### 怎么验
真浏览器：管理员四页逐个走一遍、普通用户直达四页；网络面板里普通用户没有请求 `pages/admin.js`。全量通过、扰动见红；桌面应用重新打包。

## 结果（2026-10-04）

照计划做完。

- **页面模块的形状**：`assets/pages/<名字>.js` 导出 `boots`（页面文件名 → 启动函数，参数是 `zqShared`）；壳里一张 `PAGE_MODULES`（页面 → 模块），
  `route()` 在 `boots` 表里找不到这一页时 `import()` 对应的模块再启动它。加载收成一个 `loadModule`（第三十轮的设置弹窗也改走它）：地址带壳自己的 `?v=`、
  同一个只加载一次、加载不上时抛一句写给用户看的话（会出现在「加载失败」卡片上 —— 浏览器的原话是 `Failed to fetch dynamically imported module: http://…`）、
  失败的不缓存（网恢复了下一次能加载上）。
- **后台四页**（监管后台、账号管理、反馈管理、共享计划审核）挪进 `assets/pages/admin.js`（壳 5686 → 5434 行，模块 290 行）。
  挪过来的代码一个字没改：模块顶上 `bind(sh)` 把要用的壳里的东西解构成同名局部变量（`api`、`esc`、`$`……），`api.get`、`esc(...)` 照旧。
  反馈列表原来挂在壳的 `state.feedback` 上，只有这两个函数用 → 模块里的局部变量；反馈页上一个早就没人调的 `window.setF = function () {}` 删了。
  `zqShared` 多给了 `$` / `$all`、`askText`、`showInfo`、参考计划分类的两个函数、`freqLabel`（参考计划页还在壳里，分类表仍只有一份）。
- **普通用户不下载后台的代码**：后台页的门（`ZQUI.isAdminPage` + 服务端角色）在加载模块之前；离线缓存不预先下载页面模块（打开过的照样会被运行时缓存）。
  **和开工时的计划不一样的一处**：计划第 4 条写的是「离线缓存里有它」—— 做的时候发现预先下载就等于每个装了这个应用的人都下载后台的代码，和这一轮的目的相反；
  后台页离线也没有用（数据全在接口上），所以改成不预先下载，判据钉的也是「不预先下载」。

**判据**：`PageModulesTest`（新，5 条）—— `PAGE_MODULES` 每一项 node 真的 import、核对导出了这一页的 `boots`；每个应用页面要么在 `boots` 表里、要么在
`PAGE_MODULES` 里（两边都没有 = 打开一片空白，两边都有 = 挪完忘了删）；模块只用 `zqShared` 给了的东西，**并且壳的助手被直接调用时模块要么解构了它、要么自己定义了它**
（少解构一个就是打开那一页时的 ReferenceError —— 第三十轮那条只看 `sh.xxx`，覆盖不到「解构成局部变量」这种写法）；后台页的门在第一处 `loadModule` 之前
（不管有没有 await —— 第一版只认 `await loadModule(...)`，扰动「门之前顺手预取」时它看不见，改了）、离线缓存和页面都不直接加载页面模块；
`module-load-check.js` 用真的 `import()` 跑发布的 `loadModule`（真模块加载得上、同一个只加载一次、换令牌是另一份模块、加载不上说人话、失败不缓存、之后能加载上）——
这条替掉了原来钉 `throw requestError('…')` 原文的写法（方案第 4 步：钉原文的换成行为判据）。`MobileLayoutTest` 的页面网格扫描加上 `assets/pages/`（页面模块画在 `.zq-main` 里）。
扰动 14 个全红。

**第一遍全量红了 1 条**，又是「搬家之后判据扫错文件」：`RoutinePhaseTest` 只在壳里数 `freqLabel(…frequency, …daysOfWeek)` 的调用，而共享计划审核的详情弹窗
（三处之一）挪进了模块 —— 数少了所以红；更要紧的是它那条「不许原样显示 DAILY / WEEKLY」也只扫壳，模块里原样显示它看不见。改成扫 `assets/` 下全部脚本，
扰动（在模块里原样显示周期）见红。

**真浏览器**（`zhiqu_verify`）：普通用户直达四个后台页 → 都劝返到 AI 助手，网络记录里没有 `pages/` 的请求（同一份记录里看得到这几页的壳和 `?v=20261004-admin`，所以不是没记）；
把测试账号临时提成管理员 → 监管后台（六个数、流量、运行状态、RAG 状态，「刷新数据」「刷新状态」）、账号管理（14 个、搜索回车、禁用 → 启用一个旧测试账号、重置它的密码 → 弹出「密码已重置」，
没有读那串临时密码）、反馈管理（自己提一条测试反馈 → 筛选 → 关闭）、共享计划审核（详情弹窗、修改弹窗的分类下拉、取消）—— 加载的是 `pages/admin.js?v=20261004-admin`，
控制台没有 ReferenceError / TypeError。**模块加载失败没在真浏览器里演**：要「接口照常、只有模块加载不上」，浏览器里摆不出来（断网时接口先失败，
走的是另一张错误卡片）—— 由 `module-load-check.js` 用真的 `import()` 跑。账号改回普通用户；测试反馈、被重置密码的旧测试账号留在 `zhiqu_verify` 里由用户删。

**验**：全量 958 / 0 / 0 / 0（开着 Docker；含命令行那一侧的 node 测试）；桌面应用重新打包（包里的 JAR 带着 `pages/admin.js`）。
