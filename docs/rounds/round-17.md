# 第十七轮（2026-09-28）：暴力测试 —— 数据量的极端（用了很久的账号）

## 由来
用户 2026-09-28 要的暴力测试里「不同输入…极端情况」，前几轮都是「一次操作」的极端（坏输入、连点、刷新、Ctrl+C、坏文件）。
还没测的是**时间的极端**：一个用了两年的账号 —— 几千条任务、几百个例行计划、上千页 Wiki、几万条聊天消息、几百个 Notebook、
几千条学习记录。开发时的账号都是空的，所以慢的地方从来没人见过。第三、四轮修过几处「整表取回来在内存里筛」，但那是读代码读出来的，没实测过。

## 计划（开工时）
在 `zhiqu_verify` 里造一个这样的账号（直接往库里灌，不走接口 —— 否则限流先挡住），然后：

### 1 每一页打开要多久
- 真浏览器里逐页打开（看板、任务、例行计划、参考计划、Wiki、AI 助手、统计、成就、个人中心），记下接口时间和页面画完的时间。
- 慢的逐个查：N+1 查询、整表取回、没用上索引、前端一次画几千个节点。

### 2 会随着数据变慢的操作
- 建一个任务、打一次卡、存一页 Wiki、发一条消息：数据多了之后要多久（成就检查、索引重建、链接重算这类「每次都全量」的）。

### 3 修
- 有上限的地方加上限并说出来（分页、「只显示最近 N 条」），不静默截断。

### 暴力测试（每轮都做）
- 就是这一轮本身。另加：数据多的账号上连点 / 狂刷新，接口不超时、不出现运行问题。

## 结果

造的账号：3000 条任务、823 页 Wiki、300 个 Notebook、25980 条消息、200 个例行计划、12000 次打卡、3000 条学习记录。
（造数据的时候先吃了一次亏：接口造任务 3000 条 4 秒，Wiki 800 页 35 秒 —— 查下来是 12 个并发写同一个人的 Wiki 在排队（每人一把锁），不是慢。）

### 逐页量（真浏览器，本机）
| 页面 | 改之前 | 改之后 |
|---|---|---|
| 任务 | 取回全部 1.6MB、42128 个节点 | 一页 100 条 55KB、1530 个节点；「加载更多」、页脚「共 3000 条（显示了 100 条）」 |
| 例行计划 | 为了显示 20 条取回全部 1.6MB | 11KB |
| 统计 | 为了数四象限取回全部 1.6MB；「已完成 / 总任务」一直是 0 | 不取任务；2581 / 3000 |
| 看板 | 一周 1155KB + 全部学习记录 398KB | 274KB + 1KB |
| 知识 Wiki | 目录树 1.2MB、220ms；加一页后第一次打开 4150ms | 460KB、60ms；加一页后 0.3 秒 |
| AI 助手 | 消息本来就分页（50 条）、300 个 Notebook 45KB | 没动 |

### 查出来的
- **统计页两格永远是 0**：字段名对不上（`completedTasks` vs `completedTaskCount`）。
- **Wiki 每打开一次把全部加密正文从库里搬五遍**：`findPageByTitle` 为了比标题 SELECT 全部列，ensureSystemPages 调三次；建 index、建目录树各一次。
  第二轮只去掉了「解密」，没去掉「搬」。
- **Wiki 越大、加一页之后第一次打开越慢**：重建 index 的链接时每个 [[链接]] 查一遍全表 —— 823 页就是 823 次；旧链接逐条删。
- **翻页会重复**：只按 updatedAt 排序时，并列的几条在两页之间先后不定 —— 扰动（去掉 id 兜底）实测第二页出现了第一页的一条。

### 扰动
14 + 2（Wiki 链接）+ 1（首页条目）处，全红。一处一开始是弱判据：「逐条删旧链接」—— 假的链接表里本来就没有链接，逐条删也删不到东西；
给它两条旧链接之后红。
