# 第一百二十一轮（2026-11-08）：网页代码模式说「已写入文件」，其实一个都没写

## 由来
用户在 zhiqustudy.com（auto 档、没选文件夹 = 生成到产物）里说「写一个文件」，回答是「## 已写入文件 文件路径：`./四象限周计划.md` …」，连文件内容都贴了，产物里什么都没有：「我叫他写一个文件，怎么这样，但是没有在artifact里面生成」「档位是auto」。

线上查到的（执行 6 的每一步、日志）：

- **代码 agent 是对的**：跑了 1 轮（看了工作区），一个文件都没写，结论是「工作区现在是空的，还没有建立任何文件。你想写哪个文件，我还缺少关键信息：文件名、格式，以及内容主题。」
- **最终回答把它改写了**：网页的代码模式在代码 agent 之后还有一步「最终回答」—— 另调一次模型，拿历史对话、用户这句话、代码 agent 交上来的东西重写一遍回答。它照上一轮列过的选项替用户选了一个，说「已写入文件」，还把文件内容编了出来（953 字）。
- 对这一步的约束（`CodeContextPrompt` 的「能写、没调写工具」那一支）只说了「如实回答看了什么、跑了什么」「不要说没写成」，没说「不许说写了文件」，也没叫它把代码 agent 的问题转告。后面两道核对只查引用。
- 宿主那道「说的和做的」（第九十五轮）只认「……草稿」的说法；产物模式说的是「已写入文件」「已新建 xx.md」，对不上。

命令行没有这个问题：命令行把 agent 自己的结论给用户。网页多了一次改写，说的和做的就可能分家。

## 计划
1. **代码模式的回答就是代码 agent 自己的结论**（和命令行一样），不再另调一次模型重写；`/review` 的结论也一样原样给。代码 agent 什么都没交出来（出错、被打断）时才退回最终回答那一步。省一次模型调用。
2. 退回的那一步（`CodeContextPrompt`「能写、没调写工具」）：明说这一轮一个文件都没写，不许说写了、生成了、保存了；代码 agent 在问问题就照原样转告。
3. 宿主的核对加上「已写入 / 新建 / 创建 / 生成 / 保存了某个文件」：一个文件都没写却这么说，推一次（和「草稿」那条一样）。
4. 判据：端到端（`CodeAgentLoopIntegrationTest`，真起 node 的循环、假模型照这次的样子：代码 agent 反问、最终回答那一步编「已写入」）—— 回答必须是代码 agent 的反问、没有「已写入」、最终回答那一步根本没被调用；原来那条「生成到产物」的也改成看存下来的回答是不是代码 agent 的结论。宿主的核对用 node 测（说写了文件、其实没写 → 推回去）。
5. 部署到服务器，在网页上用同一句话再试一遍。

## 结果

- **代码模式的回答就是代码 agent 自己的结论**：宿主交回一个单独的 `conclusion`（`code-host.js`），后端 `CodeWorkspaceAgent.Result` 多一项 `conclusion`，`FinalWriter` 有它就原样当回答、不再调模型。`conclusion` 只认这一次新说的、没出错没被打断的：历史那段后面跟着一句固定的「好的，前面的对话我当参考」，半路断了时原来的 `last` 会是它或者上一轮的旧回答；被推回去（清单没做完）之后出错 / 到点 / 跑命令时被打断（exec 回「已中断」、不抛错，`error` 是空的），被推回去的那句也不算。
- **两种情况照旧由最终回答那一步说**：代码 agent 没交出结论（用完轮数、出错、被打断）；同一轮 Wiki 工具循环也跑了（它的回执要拼进去）。这两种情况下的提示（`CodeContextPrompt`「能写、没调写工具」那一支）加了两句：一个文件都没写，不许说写入了 / 新建了 / 生成了 / 保存了、不许编内容；代码 agent 在问就照原样转告，不替他选。
- **宿主的核对认「写了文件」的说法**（`CLAIMS_FILE`）：「已写入文件」「新建了 `./x.md`」「文件已保存」…… 一个文件都没写却这么说，推一次。跑过命令的不判（auto 档的 shell 可能真写了，看不出来就不推）。判断写没写过只看 `drafts`（选了文件夹）和 `wrote`（生成到产物）：起初还加了 `ctx.changedFiles`，扰动照出它多余，删了。
- 判据：
  - 端到端（`CodeAgentLoopIntegrationTest`，真起 node 的循环）：「写一个文件」—— 代码 agent 看一眼空的工作区、反问；写最终回答的那一步要是被调用，假模型照线上那一次编「## 已写入文件」。回答必须是那句反问、写最终回答的那一步 0 次、产物 0 个。同一轮也查了知识库：由最终回答那一步合并（1 次），它拿到的有代码 agent 的反问和「一个文件都没写」。原来「生成到产物」那条：代码 agent 用完了轮数、没有结论 —— 由兜底那一步说，它要知道生成了什么（第一次改判据时误以为这里也该用结论，跑出来才看清是兜底）。
  - 宿主（`code-host.test.js`）：线上那句话推回去、推回去之后照实问就是结论；说法表 7 个算、8 个不算；跑过命令不推；真写了再说「已写入 a.md」不推；结论的六种情况（正常、出错、用完轮数、推回去后出错、推回去后到点、跑命令时被打断）。
  - `CodeContextPromptTest`：兜底那一支的两句话。
- 扰动 19 个全红（第一批 14 个里 2 个绿：「被打断也交结论」—— 原来的样本里打断总会抛错，`error` 替它挡了，补了跑命令时被打断的样本；「判断写没写过不看 changedFiles」—— 它多余，删了，再补了「真写了再说已写入」的样本让 `wrote` 那一半见红）。
