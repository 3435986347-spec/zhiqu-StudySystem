# 第一百一十一轮（2026-11-07）：Codex 同级第 4 步 —— apply_patch

## 由来
方案第 4 步（[`docs/codex-parity-plan.md`](../codex-parity-plan.md)）。`edit_file` 一次只能改一处，改好几个文件要一个一个调：中间失败就是半截改动，一轮一轮也费 token。Codex 用 `apply_patch` 一次改多个文件。

## 计划
1. `apply_patch`：格式和 Codex 一样（`*** Begin Patch`、`Add / Update / Delete File`、`Move to`、`@@`），模型见得多。
2. **要么全成要么全不成**：先把所有文件的结果算好、检查完才动磁盘；写到一半出错全部退回。
3. 规矩和 `edit_file` 同一套：读过才能改、没被别人改过、`.git` / `.zhiqu` 不能碰、UTF-8、大小上限。原文要能唯一定位，出现几处就拒绝，不猜（Codex 取第一处，错了是一声不响地改错地方）。
4. ask 档改之前把所有 diff 摆出来，问一次；auto 不问；plan 不给。删除和 `delete_file` 一样挪进回收站。
5. 网页：改动进草稿，和 `edit_file` 一样确认才落盘；网页从来不给删，所以带 Delete / Move 的补丁整个拒绝。
6. 判据：真 `git diff` 的输出转成补丁，打上去要和目标文件一字不差；写到一半注入故障，看是不是全退回。

## 结果
**真跑过的**（真浏览器，网页 auto 档，真后端，假模型先 `read_file` 再打补丁）
- 多文件补丁（改两个、新建一个）：确认框里三份 diff，磁盘一个字没动；**用真鼠标点「确认写入」**，三个文件全部落盘，页面说「已写入 3 个文件」。
- 第二个文件对不上的补丁：第一个也没进草稿。带 Delete 的补丁：整个拒绝，说清网页不能删。
- 一致性：真 `git diff` 转成补丁，100 轮随机改动（多文件、新建、删除，文件里有大量重复的空行和 `}`）打上去一字不差。
- 故障注入：写到第 1–5 步分别让改名失败，原文、新文件、新目录、回收站、临时文件全部退回；退回之后还能接着改。

**查出来的**
- 对不上时的线索是个对象，我直接拼进字符串，模型只会看到 `[object Object]`（判据抓到的）。
- 改名的文件数算了两次（写一个、删一个）。
- 扰动第一批 50 处红 43。绿的 7 处都是判据没照到，**有两处是危险场景**：缺 `*** Begin Patch` 时第一个操作被当开头吃掉、缺 `*** End Patch` 时打半截。代码是对的，但没有样本照得到它，下次改代码就可能悄悄坏掉。补了样本，复验 7 处全红。

判据：后端全量 1339（1 跳过写明原因）、命令行 361/361、评测工具 102 过 1 跳。

**还没做的**

- 文件 > `maxFileBytes`、不是 UTF-8 的改不了，和 `edit_file` 一样。
