# 第一百一十二轮（2026-11-07）：Codex 同级第 5 步 —— 长命令与后台进程

## 由来
方案第 5 步（[`docs/codex-parity-plan.md`](../codex-parity-plan.md)）。`shell` 一条命令最多跑 120 秒，到点就杀，起一个 dev server、再测它，或者盯一个十分钟的构建，都做不了。Codex 有 exec 会话和 `/ps`、`/stop`。

## 计划
1. `shell` 加 `timeout_seconds`（默认 120，最多 600）。加 `background: true`：起完就回，等一小会儿把开头的输出带回来（立刻失败的当场看到）。
2. `shell_output`：看后台命令的新输出，可以 `wait_seconds` 等一会儿（结束了立刻回）。`shell_stop`：连进程组一起停。
3. 后台命令和前台一样关在系统沙箱里，档位按起的时候算。
4. 输出只留最后 1 MB，一次最多给 64 KB，丢了多少、后面还有多少都照实说。
5. 命令行：`/ps`、`/stop [id|all]`；退出时全部收掉；同时最多 8 个。
6. 网页同一套工具（用户：两者要一致），进程还是后端起、门还在后端；一轮结束全部收掉，同时最多 4 个。
7. 判据用真进程：真的后台跑、真的看输出、真的杀干净（连子进程）。

## 结果
**真跑过的**（真浏览器，网页 auto 档，真后端，假模型按脚本走）
- 起一个 8 秒的后台命令，`shell_output` 等 3 秒看到前几行，再等 30 秒在第 8 秒结束时立刻回（不等满），退出码 0。
- 另起一个 `sleep 200`，`shell_stop` 之后进程真的没了（退出码 137）；又起一个不管它，这一轮结束后后端收掉，也真的没了。
- `sleep 30` 给 `timeout_seconds: 1`，1.0 秒结束。
- 模型拿到的工具：`shell`、`shell_output`、`shell_stop`。

**查出来的**
- 扰动 56 处红 53。绿的 3 处都是判据没照到（被挡的提示、停掉的不占名额、起过后台命令也算跑过），补了，复验全红。
- 真浏览器日志里 `第$i行` 打出来是乱码：**不是沙箱的事**，macOS 自带的 bash 3.2 把中文的第一个字节算进了变量名，沙箱外一样，写 `${i}` 就对。留意模型写的中文命令可能碰到。

判据：后端全量 1345（1 跳过写明原因）、命令行 375/375、评测工具 102 过 1 跳。

**还没做的**
- 不能往进程里写 stdin（Codex 能）。要交互的程序还是跑不了。
- 网页没有 `/ps` 这样的界面，只有模型能看后台命令，一轮结束全部收掉。
