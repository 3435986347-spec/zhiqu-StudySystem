# 第二十四轮（2026-10-04）：删 —— 旧前端、页面里的设计稿示例数据、Java 版命令行

## 由来
`docs/product-plan.md` 第 2 步。用户 2026-10-03 看过清单后选「全部删」。

锐评里说的是「死代码和假数据靠测试站岗，而不是删掉」：
- 旧 `static/js/` `static/css/`：33 个文件、22,346 行，**零个页面加载**，但打进 JAR、对外可访问。CLAUDE.md 里记着它坑过一次
  （早八提醒的渠道凭据界面只在旧 js 里，于是对谁都不工作）；第二十三轮又是一次（Wiki 待合入变更的审阅界面只在旧 js 里）。
- 14 个页面里 12 个还带设计稿的示例数据：内联脚本在 `zhiqu-api.js` 加载之前把一份编造的学习计划写进 DOM。用户看不到它，
  全靠「启动失败时 `renderInitError` 换掉整个 `.zq-main`」这一道；`InitErrorReplacesDemoContentTest` 给它站岗。
  而启动**成功**时没被覆盖的那部分示例照样露出来 —— 「已审核模板 · 4 个」「第 3 轮」「例行完成 60%」都是这么来的。
- Java 版命令行（`com.zhiqu.cli.*` 7 个文件 1,471 行、`deploy/desktop/bin/zhiqu`）：已由 npm 版接替，桌面包里还带着。

## 计划（开工时）

1. **旧 js/css**：整目录删掉；`SecurityConfig` 放行名单里的 `/css/**` `/js/**` 一起去掉（指向不存在的东西的放行规则只会让人以为它们还在用）。
   `static/vendor/` **不删** —— KaTeX、DOMPurify、Vditor 是 `zhiqu-api.js` 在用的（README 里说它也是旧的，那句改掉）。
2. **示例数据**：逐页看内联脚本，示例数据删掉，真接线（内联 `onclick` 引用的函数、番茄钟、弹窗）留下；页面的初始 HTML 里放中性的空状态，
   不放编造的数字和条目。`InitErrorReplacesDemoContentTest` 那条站岗改成「页面里没有示例数据」。
3. **Java 版命令行**：源码、测试、`bin/zhiqu`、打包脚本里拷它的几行、桌面打包判据里钉它的几条一起删；
   `LoginDeviceLabelTest` 不再从 Java 代码里取 UA（生产者没了），历史登录记录里的「命令行」标签照旧认。
4. 文档：CLAUDE.md、AGENTS.md、README、`deploy/desktop/README.md` 里讲它们的段落跟着改。

### 怎么验
真浏览器把 14 个页面都打开一遍（空账号 + 有数据的账号），启动成功时页面上不许出现示例数据（第二十三轮那个「和静态 HTML 一字不差的带数字文字」扫描再跑一遍，
这次连 style 里写死的宽度也看）；全量测试通过；桌面应用重新打包确认不带 Java 版命令行。
