# 第十五轮（2026-09-28）：不丢字 —— 刷新、关页、登录过期、断网时，用户打的字还在

## 由来
用户 2026-09-28 要的暴力测试里有「不停刷新」。第十三轮测了刷新时 AI 回答不丢，第十四轮测了连点；还没测的是**用户自己打的字**：
没耐心的人会在打到一半时刷新、误关标签页、放着页面去吃饭回来登录已经过期。收口第十四轮时扫了一眼 `zhiqu-api.js`：
全文件没有一处 `beforeunload`，聊天输入框的草稿不存，登录过期一律跳到 `index.html?login=1`、登录之后回看板 —— 原来在哪一页、打了什么都没了。

## 计划（开工时）
先在真浏览器里把每种「丢字」实测出来，再修；判据先红、扰动见红。

### 1 聊天输入框的草稿
- 打了一半刷新 / 关页 / 切 Notebook：回来时草稿还在（按 Notebook 分开存，发出去就清掉）。

### 2 知识 Wiki 的编辑
- 正在编辑（正文 / 源码模式）时刷新或关页：浏览器先问一句；万一还是走了，回来时提示「有没保存的内容，恢复吗」。
- 两个标签页改同一页：后保存的那个被乐观锁挡住时，打的字不能跟着报错一起没了。

### 3 登录过期
- 任何一页上登录过期被带去登录：登录之后回到原来那一页（只认站内的相对地址，不做开放跳转）；那一页上打的字按上面两条还在。

### 4 其它会打字的地方
- 逐个过一遍（新建例行计划的说明、提交参考计划、反馈、Raw Source 粘贴……），能用同一个机制的就用同一个机制，不各写一份。

### 暴力测试（每轮都做）
- 打字时狂刷新（每 200ms 一次、刷 20 次）：草稿每次都在、不串到别的 Notebook / 别的页。
- 本地存储满了、被禁用（隐私模式）：功能照常，只是不保草稿，不报错。
- 超长草稿（几十万字粘贴）：存不下就不存，不卡页面。

## 结果

### 先实测（真浏览器）
- 聊天框打一句、刷新：没了。Wiki 源码模式改了几行、刷新：没了；改着改着点了目录里的别的页：没了，一声不吭。
- 登录过期：跳到登录页，登录之后回看板 —— 原来在哪一页、打了什么都没了。

### 修（一套机制，`drafts` / `keepDraft`）
- **聊天框**：刷新后还在（按 Notebook 分开）；发送后**服务器确认收到才删**（事件里的 `userMessageId`）；没收到就把字放回输入框。
  实测：没配模型时发送 → 「请先配置模型」，那句话回到输入框、草稿还在；配上假模型后发送 → 回答出来、草稿删掉。
  每打一个字就立刻刷新（在 400ms 的保存间隔之内）×3：「一二三」一个不少 —— 离开页面时当场存。
- **Wiki**：改了没保存就刷新 → 回来顶上「这一页有没保存的修改（9/28 10:22）[恢复] [丢弃]」→ 恢复 → 保存，草稿删掉。
  **旧版本上的草稿**：另一个标签页先改了这一页 → 恢复后保存被乐观锁挡住，字和草稿都还在 —— 但每次都挡，刷新重试也一样，
  草稿永远存不进去。改成保存前先问「这一页在你离开之后被改过…用我的这一版替换」，点了才存；别人加的那行不会被悄悄盖掉。
- **登录过期**：`index.html?login=1&next=routines.html` → 登录 → 回到例行计划页，表单里打了一半的标题还在。
  `safeNext` 只认本站的 `xxx.html`：`//别处`、`https:`、`javascript:`、`../`、带 `//` 的查询串一律回看板。
- 例行计划的标题 / 说明、导入来源的粘贴框也接上了。其余的输入框（提交参考计划的简介、驳回原因）都是一两句，没接。

### 暴力测试
- 刷新暴力测试（9 次、间隔 0.2 秒）**撞出限流**：页面整个换成「加载失败 · 请求过于频繁」。数了一下：AI 助手打开一次 8 个请求，
  其中 6 个在 `/api/ai/` 下，而那一桶是 40 次 / 分钟（给发消息调模型用的）—— 刷新六七次就锁一分钟；回答到一半刷新后
  每 2 秒轮询一次，长回答一分多钟也会把它用完。改成 AI 桶只算写操作。改完 10 次快速刷新：页面正常、草稿还在。
- 存储满了 / 被禁用、坏数据、过期、超长：node 判据逐条喂（不报错、功能照常、只是不存）。

### 扰动
草稿机制与接线 21 + 旧版本草稿先问 2 + 限流桶 3 处，全红。判据自己也红过两次（扫描窗口截在了 `});` 上 ——
登录和退出那两行里本身就有 `});`），改窗口之后才看的是对的东西。
第一次全量红了一条既有判据（`WikiTabsTest.重绘不得压历史栈`）：取消编辑那次重绘被我改写成 `paintWikiDoc(cur, …)`，
它钉的是 `paintWikiDoc(state.wikiCur, { history: true })` 这个写法。行为没变，但判据没有放宽 —— 把调用改回它钉的写法。
