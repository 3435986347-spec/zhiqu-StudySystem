# 第一百三十轮（2026-11-11）：边做边说 —— 每步前一句判断

## 由来
用户 2026-11-11（第一百二十九轮做到一半）：「而且现在都没有反馈，zhiqu每次都是做完了才说，我想要他能够一边做一边有反馈，能够显示一些判断之类的」。
问过两件（用户定的）：① 做完第一百二十九轮接着做；② **每步前一句判断** —— 像 Codex：调工具之前模型写一句「先看 core.js 的结构」「测试挂在边界上，改 clamp」，
马上显示（终端一行灰字，网页 / 桌面在回答的步骤里一条）；思考原文照旧收着（网页上点开「思考」能看）。另一个选项「连思考原文也实时滚出来」没选。

## 查明
- 第十二轮（用户 2026-09-28 要的「思考不要展示出来……只告诉用户结论和更改了什么」）起命令行默认是**安静模式**（`agent.js` 的 `quiet`）：
  模型的字收完才打，**不调工具的那一条才是结论、才打出来；调工具的那一条（「接下来做什么」）一个字都不显示**。所以从头到尾只看得到动画和最后的结论。
- 系统提示（`prompt.js`）也是这么写的：「少说、多做（用户看不到你调工具前写的字，只看得到结论和改动）」「调工具之前最多写一句话」—— 模型多半一句都不写。
- 网页 / 桌面的代码模式跑的是同一份循环：步骤（第一百二十七轮）按 `trace` 实时合进回答，但模型那一句同样没进步骤。命令行存到网站的会话也一样。

## 怎么做
1. 系统提示：「用户看不到」改成「用户在看着」—— 每次调工具之前先用一句话说判断（看到了什么、接下来做什么、为什么，不超过 40 字），不写推测过程和自言自语，连着几次每次一句、不重复。
2. 命令行（安静模式）：带工具调用的那一条，有字就马上打一行灰字（`· 判断`），在工具的那几行前面；思考的动画照旧。`--verbose` 本来就边收边打，不重复打。
3. 步骤：新的一种 `note`（判断）—— 命令行的 `StepLog`、后端的 `TraceSteps`、网页三处同一份；网页上是一行字（不是一个动作），点不开，原样转义。
   网页 / 桌面的代码模式经宿主的 `trace` 实时到页面；命令行存档也带上。
4. 不变的：结论还是只认最后那一句（第一百二十八轮）；判断不进「结论」、不进核对（`claimCheck` 只看最后的回答）。

## 怎么验
- 命令行判据：安静模式下带调用的那一条马上打一行（在工具那几行前面）、没有字的不打空行、结论照旧只打一遍；`StepLog` 出 `note`、太长的截断；系统提示里是新的说法。
- 后端：`TraceSteps` 认 `note`（原来会被收成 `other`）。网页：`note` 画成一行字、点不开、HTML 转义。
- 真浏览器：本机后端 + 假模型，代码模式问一句，看判断一条条出现在步骤里。
- 扰动见红、三组全量，然后和第一百二十九轮一起推送、部署（用户：「做完后接着做一百三十轮，并且推送、部署」）。

## 结果
- 系统提示改成「用户在看着」：每次调工具之前先用一句话说判断，不超过 40 字。安静模式有字就马上打一行灰字（`· …`），排在工具那几行前面；没有字不打空行；`--verbose` 边收边打过了，不重复打。`/resume` 回放同一条规矩。
- 步骤加一种 `note`：命令行 `StepLog`、后端 `TraceSteps`（原来不认的种类收成 `other`）、网页三处同一份。网页上是一行字，点不开，标题原样转义；带了细节也不画。结论仍只认最后那句，核对（`claimCheck`）不看调工具前的那一句。
- 判据：`quiet-thinking.test.js`、`steps.test.js`、`desktop-host.test.js`（宿主把 note 排在读取前面，结论不拿它）、`TraceStepsTest`、`TraceStepsRenderingTest`（node 跑发布的那份 `ai-assistant.js`）。命令行全量 550（531 过、19 跳）。缓存令牌 `20261112-r130`。
- 扰动见红后恢复：`judgmentText` 改成返回空串，步骤判据红（第一条变成 `read` 而不是 `note`）；去掉页面上 note 的专门画法，渲染判据红（判断被收成 `other`、点得开、细节里的字画出来）。
- 没在浏览器里用假模型走一整轮代码模式：页面接本机代码是方案第 3 步，这一轮的网页变化是步骤列表里多一种点不开的字，由上面的渲染判据钉着。
