# 第一百零三轮（2026-11-02）：AI 助手输入框上方选项目、点按钮切档位；输入框里的内框去掉

## 由来
用户 2026-11-02：「把代码工作区优化到在输入框上方选择项目里面选择目录，参考其他的 coding agent 产品，几个模式档位也用按钮点击切换」「里面的矩形框也去掉」（附截图：输入框里一圈灰色的内框）。
- 现在选工作区要点左侧面板「代码工作区」那一块的齿轮，弹窗里浏览文件夹、点档位、再点「保存并生效」—— 和对话隔着整个页面，Claude Code / Codex 那类产品是在输入框边上选项目。
- 内框：全站的 `textarea:focus` 给所有输入框加了 3px 的聚焦光圈；输入区外面那层大圆角框本来就会在聚焦时变色，里面的输入框又画了一圈。

## 计划
1. 输入框正上方一条（只有管理员、拿得到 `/workspace/settings` 时出现，和左侧那一块同一个条件）：
   - 左边「项目」按钮：文件夹图标 + 项目名（文件夹名，完整路径在悬停说明里）+ 下拉箭头。点开一个往上弹的小菜单：最近用过的项目（当前的标出来，路径小字）+「选择文件夹…」（就是原来那个一层层点进去的选择器）。
     选了就生效；档位还是「关闭」时开成「只读」（最小的那一档），不然选了像没选。最近的项目只记在这台浏览器里（`zq.ws.recent`，最多 6 个）。
   - 右边一排档位按钮：关闭 / 只读 / 读+写 / 读+写+运行，按下的看 `aria-pressed`，点了就生效（`PUT /workspace/settings`）；没选项目就点开某一档，先弹选文件夹。悬停说明照原来弹窗里的那四句。
   - 前提由后端裁决（回环 / 目录在不在 / 管理员），前端不复述：选了的档位没生效时，把后端说的原因写在这一条下面，不偷偷改按钮。
   - 左侧面板的齿轮和「工作区设置」弹窗去掉（两个地方改同一件事），那一块只留文件树，没开时的提示改成「在输入框上方选择项目、点档位开启」。
2. 输入框聚焦时里面不再画光圈（外框变色就是聚焦的样子）。
3. 判据先红；真浏览器（验证库、工作区在临时目录）里选项目、切四档、选文件夹、没生效时的原因、手机宽度各走一遍，截图给用户；连点档位的暴力测试。换缓存令牌。

## 结果
- **输入框正上方一条**（`#zq-ws-bar`，管理员、拿得到 `/workspace/settings` 才出现）：左边项目按钮（文件夹名 + 下拉箭头，完整路径在悬停说明里），
  点开往上弹一个菜单 ——「最近的项目」（当前的标底色、下面一行小字是路径）+「选择文件夹…」（原来那个一层层点进去的选择器）；右边一排档位按钮，点了就生效。
  左侧面板的齿轮和「工作区设置」弹窗去掉了，那一块只留文件树；没开时提示「在输入框上方选择项目、点档位开启」。
- **档位的名字**：做到一半用户说「模式的名字改成plan，auto，manual，close」—— 按能力从小到大：close = OFF、plan = READ（只读）、manual = WRITE（改动要在草稿里确认）、
  auto = EXEC（还能跑白名单命令，改动照样要确认）。按钮上只写名字，每一档能做什么在悬停说明里；左侧「代码工作区」那一行也用同一套名字。后端的 OFF / READ / WRITE / EXEC 不变。
- 选项目时档位还是 close：开成 plan（不然选了像没选）；还没选项目就点开某一档：先弹选文件夹。最近的项目只记在这台浏览器（`zq.ws.recent`，最多 6 个，存不了不炸）。
  选了的档位没生效（文件夹不在了、不是本机回环）：按钮照旧是选的那一档，下面一行写后端给的原因（「没有生效：…」），「代码」按钮收起来。
- **最后点的那一下生效**：真浏览器里用真鼠标快点 plan → manual，第一版停在 plan（在途时的点击直接丢了）。改成在途时记下最后点的、回来再补发；按下的样子点的时候先画上，
  都回来（或失败）以后照后端重画。再测：真鼠标连点 auto → manual → close → plan → manual，页面、后端、左侧面板都是 manual；`ws-bar-check.js` 里在途时连点三下只补发最后那一下（一共两个请求）。
- **内框**：`.zq-composer textarea:focus{box-shadow:none;}`（压过全站的 `textarea:focus` 光圈）；聚焦时外框变色，量过 `box-shadow: none`。
- 真浏览器（验证库、工作区在临时目录）里走过：四档来回切（后端状态、左侧面板、「代码」按钮跟着变）、「选择文件夹…」换到另一个文件夹、从「最近的项目」换回来、
  删掉的文件夹（没生效的原因）、手机宽度（分成两行、不横着滚）；Esc 关菜单只在 `ws-bar-check.js` 里验过。测完把工作区恢复成测试前的 ws-web + auto。
- 判据：`ws-bar-check.js`（抠出发布的那一段真跑，8 条）+ `AiComposerTest` 一条（位置、四个名字和顺序、去掉齿轮和弹窗、内框、按下的样子）；`AiLookTest` 那条跟着改到新写法。
  扰动 18 处全红（不补发最后那下、失败不重画、不先画按下、close 选项目不开 plan、没项目不弹选文件夹、close 时也说原因、不去重、存的超过 6 个、读的不截 6 个 / 不滤坏数据、
  存不了就炸、关菜单不拿掉监听、名字对错、不是管理员还露着；HTML 名字、内框规则、那一条的位置）。头一遍「最多 6 个」那处没红（读的时候本来就只取 6 个），给存和读各补了只有它照得出来的样本。
