# 第十二轮（2026-09-28）：命令行 —— 只说结论、不空转、用满模型的窗口

## 用户的要求（原话）
> 又发现一个问题，现在明明是一个很小的问题却一直在思考循环，然后也很容易达到上下文上限。我的这个 deepseekv4pro
> （自己配置的模型是有 1m 上下文的）然后能不能思考内容不要展示出来，用一个动态的小的像素图案来表示在思考，
> 并且说明在思考中，然后只告诉用户结论和更改了什么，不要展现废话
>
> 把上面那个也加入升级中

用户贴的真实记录（马里奥游戏，「人物卡在最上面不能下来」）里能看到：模型在工具调用之间写了上万字的推测（「我陷入困境…让我重新想…」），
反复读同一个文件；窗口按 64000 算、压缩两次、服务器又裁掉 22 条；真正的 bug（`ctx.translate(x, 0)` 漏了 y）最后是靠写脚本做实验找到的。

## 计划（开工时）

### 1 思考过程不展示（用户点名要的）
- 模型在调工具的那几条回复里写的文字 = 思考过程：**不打印**。这段时间状态行是一个**动态的像素图案 + 「思考中 Ns」**，
  顺带一行小字说正在做什么（读哪个文件、搜什么）。
- 只打印：**最后的结论**（不再调工具的那条回复）和**改了什么**（写文件 / 删文件 / 跑命令的那几步，写文件带 diff）。
  读文件、搜索、列目录这类只在状态行里一闪，不留成永久的行；一轮结束说一句「读了几个文件、搜了几次」。
- `/verbose` 切回原来的全显示（给想看过程的时候）；记进配置，下次还是这样。
- `/resume` 回放按同一个规矩。

### 2 用满模型的窗口
- 查清楚为什么 1M 的模型按 64000 算（没填窗口 → 按默认；网页里能填，但命令行里没人告诉用户）。
- 启动横幅写明「上下文 64000（这个模型没填窗口，按默认算）」；新命令 `/window <token 数>` 直接给自己的模型设窗口
  （服务器新接口，只能改自己的模型配置，范围 8000–1000000，和网页那一处同一个校验）。

### 3 不空转
- 模型在调工具的回复里写了很长一段（> 3000 字）推测：在工具结果后面附一句「别长篇推测，拿不准就写最小复现跑一下」。
- 连续 8 次只看不动（读 / 搜 / 列，一次写或跑都没有）：同样附一句。
- 系统提示：工具调用之间最多一句话；拿不准就做实验。
- 省上下文：较早几轮里模型写的长篇思考（调工具的那几条回复里的文字）只留开头一小段 —— 结论另有最后那条回复。

### 4 记录里顺带查出的
- `search` 的 path 给了一个文件 → 原来报「不是一个普通文件」，模型以为搜索坏了、改成一段段读。现在 path 可以是文件。
- 写完 .html 也查内联 `<script>` 的语法（这类单文件小游戏最常见；模型自己写 check.js 用 new Function 查）。
- 桌面应用没开时 `zhiqu` 直接报连不上（还报了两遍）→ 默认连本机桌面应用时，macOS 上自动把应用打开、等它起来。

### 暴力测试（每轮都做，用户 2026-09-28 的要求）
- 状态行动画在各种终端宽度（20 / 40 / 80 列）、中文窄屏、Ctrl+C 打断时不留残影、不闪（沿用第九轮「按每次 write 回放」的判据）。
- 模型输出几万字思考、几百个工具调用时，不卡、屏幕不刷屏。

## 结果
- **思考过程不展示**：默认只打印结论和改动；读 / 搜 / 列目录只在状态行一闪；`/verbose` 切回全显示并记住。
  真 pty 实录（假模型先写 1000 多字推测、读文件、再改文件）：屏幕上只有「⏺ 修改 a.js + diff」「改好了：…」和一句「这一轮读了 1 次文件」；
  状态行依次是 `⣀⣤⣶⣿ 思考中 Ns`、`⣤⣶⣿⣶ …`、`⣶⣿⣶⣤ …` —— 像素图案在动。
- **不空转**：长篇推测（> 3000 字）、连续 8 次只看不动都附提醒；较早几轮的长篇思考发给模型时只留开头；系统提示新增「少说、多做」。
- **窗口**：查清 1M 被按 64000 算的原因 —— 模型配置没填窗口，没填就是 `HarnessContext.DEFAULT_WINDOW`。启动和压缩时说出来；
  `/window 1m` 调新接口 `POST /api/harness/models/{id}/context-window`（只改这一列、只能改自己的 USER 模型）。
- **顺带**：search 可以给文件；写 .html 查内联 `<script>`；本机桌面应用没开时 macOS 上自动打开并等它起来。
- **暴力测试**：20 / 40 / 80 列窄终端 + 超长中文活动说明不折行、停下不留残影；思考中 Ctrl+C 动画和定时器都收干净；
  模型连着调 200 次读文件，屏幕上不到 10 行。
- 扰动：命令行 28 处、服务器 /window 4 处，全红（其中 3 处一开始是弱判据 —— 窄终端判据读到折行的后半截、`<script src>` 没带内容、
  「起来之后报别的错」没有用例 —— 补强后红）。

### 第十二轮（2026-09-28）：命令行 —— 只说结论、不空转、用满模型的窗口

用户贴的真实记录（DeepSeek V4 Pro 在工具调用之间写了上万字推测、反复读同一文件；1M 的模型被按 64000 算、压缩两次）加一句：
「思考内容不要展示出来，用一个动态的小的像素图案来表示在思考，并且说明在思考中，然后只告诉用户结论和更改了什么」。计划在 `docs/rounds/round-12.md`。

- **思考过程不展示**（默认；`/verbose` 或 `--verbose` 切回全显示，记进 `~/.zhiqu/config.json` 的 `showThinking`）：
  模型的回复**收完才打**—— 不调工具的那条是结论，按 Markdown 整段打；调工具的那条里的字是过程，不打。
  读 / 搜 / 列目录 / 没下发的名字 / 参数坏了，只在状态行里一闪（`hushedUi` 把 step 换成 `setActivity`）；写 / 删 / 跑命令照常打印（写带 diff）。
  一轮结束说一句「读了几次文件、搜了几次」。`/resume` 回放同一个规矩。被输出上限截断又接着说的结论，两段都打。
- **像素图案**：`ui.startThinking()`，4 个点阵字符像均衡器起伏（`pixelFrame`，120ms 一帧）+「思考中 Ns · 在做什么」，
  按终端宽度截短（折行的话擦的时候行数对不上）；一轮的 finally 里 `stopThinking`（Ctrl+C 也走这里，定时器不留）。
- **不空转**：调工具的回复里写了 > 3000 字、连续 8 次只看不动 → 工具结果后面附一句（拿不准就写最小复现）；
  发给模型之前，较早几轮调工具那几条回复里的长篇思考只留开头 200 字（`slimThinking`，最近 2 条原样；会话记录里是原话）；
  系统提示新增「少说、多做」。
- **窗口**：模型配置没填窗口就按 `HarnessContext.DEFAULT_WINDOW`（64000）算 —— 启动横幅和压缩时现在都说出来；
  `/window 1m`（也收 `128k`、纯数字）调 `POST /api/harness/models/{id}/context-window` 设自己的模型（范围 8000–1000000，
  与网页同一个 `ContextBudget.validate`）。
- 记录里顺带查出的：`search` 的 path 可以是文件（原来报「不是一个普通文件」，模型以为搜索坏了）；写 .html 也查内联 `<script>`
  （src 外链、非 JS 的 type 不查；module 按 ES 模块；行号对到 HTML）；默认连本机桌面应用而它没开时，macOS 上 `open -g -b com.zhiqu.quadrant`
  打开它、最多等 40 秒（`src/desktop.js`；探测不带重试，否则光探测就 1.3 秒），没装就说清楚、不再报两遍「连不上」。
