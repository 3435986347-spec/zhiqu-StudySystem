# 读陌生代码库

目标不是「读完所有文件」，是能回答三个问题：**怎么跑起来、一条请求怎么走、要改的地方在哪。**

## 1. 先看骨架（不要一上来读源码）

按顺序读，每一步停下来记一句结论：

1. `README.md` 和 `docs/` 里的上手文档 —— 项目自己怎么介绍自己。
2. 构建与依赖清单：`package.json`、`pom.xml`、`build.gradle`、`pyproject.toml`、`go.mod`、`Cargo.toml`。看**依赖**就能猜出技术栈和它解决的问题。
3. `list_files` 看两层目录，认出哪些是源码、哪些是生成物（`target/`、`dist/`、`node_modules/` 不用看）。
4. 配置文件：`application.yml`、`.env.example`、`docker-compose.yml`、CI 配置 —— 知道它连什么、怎么启动、怎么测。

## 2. 找到入口

- 服务端：`main` 函数、`@SpringBootApplication`、`app.listen`、`func main`。
- 前端：`index.html` 引的第一个脚本、路由表。
- 命令行：`bin` 字段、`console_scripts`、`main` 包。
- 定时任务和消息消费者：`@Scheduled`、`cron`、`consumer`、`subscribe` —— 这些是没有 HTTP 入口的隐形入口，最容易漏。

## 3. 顺一条真实路径走到底

挑一条**用户最常用的**操作（登录、下单、列表页），从入口一路跟到数据库再回来，每层记一句：

```
HTTP POST /api/order  →  OrderController.create
  → OrderService.create（事务边界在这）
    → 校验 + 扣库存（InventoryClient，远程调用，会失败）
    → OrderMapper.insert → MySQL
  → 返回 { id }
```

这一条走完，比读二十个文件有用：分层方式、错误处理、事务、日志、鉴权在哪一层，全都露出来了。

## 4. 代码库大时分头看

超过几百个文件时，用 `spawn_agent` 派只读探索的子 agent（`role: "explorer"`），一人一块，最后 `wait_agent` 收结论：

- 一个看**构建与运行**：怎么编译、怎么跑测试、有哪些脚本。
- 一个看**数据层**：表结构、迁移、ORM 映射、缓存。
- 一个看**接口层**：路由清单、鉴权中间件、错误码约定。
- 一个看**前端**（如果有）：页面怎么组织、状态管理、接口调用封装。

派的时候把「看哪一块、回答什么问题」写清楚，不要只说「看看这个项目」。子 agent 之间不要改同一个文件（explorer 本来也改不了）。

没有 `spawn_agent`（用户把子 agent 关了）就自己按上面的顺序一块一块看，不要假装派了。

## 5. 产出

用户没要文件就只在回答里给，不要自己建文档。**用户要的是项目说明文件**（写进 `ZHIQU.md` 给以后的会话看）的话，那是 `/init` 的活 —— 告诉他跑 `/init`，不要在这里另写一份。

结构：

1. **一句话**：这是什么、用什么写的、跑起来要什么。
2. **目录地图**：`src/` 下每个目录一行，说职责，不说文件名。
3. **一条路径**：上面那条调用链。
4. **约定与坑**：命名、错误处理、事务、测试怎么写、哪些地方看起来能改其实不能（生成代码、迁移文件、第三方 vendored 代码）。
5. **要改 X 应该动哪里**：如果用户是为了某个任务才让你读的，直接给落点。

不确定的地方标出来（「这块没跟到底」），不要编。
